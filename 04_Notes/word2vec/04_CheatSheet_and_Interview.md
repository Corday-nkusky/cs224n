## 1. 一句话核心贡献（必背）

> **Word2Vec 用"负采样"把词向量训练的代价从"每个样本算遍整个词表 O(V)"降到"只算 K+1 个二分类 O(K)"，
> 让词向量第一次能在十亿词级语料上廉价训练——它是一场效率革命，顺带证明了"极简代理任务也能学出好表示"。**

配套必须记住的**三个数字**（全是【官方源码】/【论文原文】）：

| 数字 | 值 | 出处 |
|---|---|---|
| 负样本数 K | 5（小语料 5~20，大语料 2~5） | 源码 `negative = 5`；论文 §2.2 |
| 噪声分布指数 | **3/4** | 论文 §2.2 `U(w)^{3/4}/Z` |
| 学习率 α | **Skip-gram 0.025 / CBOW 0.05** | 源码：默认 0.025，`if (cbow) alpha = 0.05` |

## 2. 30 秒速查卡

### 2.1 公式卡

```
目标（Skip-gram + NEG）:  L = -log σ(u_o·v_c) - Σ_k log σ(-u_nk·v_c)

梯度（全部）:             ∇ = (σ(s) - y) · 对面的向量,   y ∈ {1 正, 0 否}
                          ∇_{v_c} = (σ(s_pos)-1)·u_o + Σ_k σ(s_k)·u_nk
                          ∇_{u_o} = (σ(s_pos)-1)·v_c
                          ∇_{u_nk} = σ(s_k)·v_c

稳定写法:                 log σ(x) = -logaddexp(0, -x)     ← 必须这么写
负采样分布:               P_n(w) ∝ f(w)^0.75
每步代价:                 (1+K)·D      （完整 softmax 是 V·D）
初始 loss 参考值:         (1+K)·ln 2 = 4.159   ← 训练不动时先对照这个数
```

### 2.2 参数卡（【官方源码】默认值）

| 参数 | 默认 | 说明 |
|---|---|---|
| `-size` (D) | 100 | 词向量维度 |
| `-window` (C) | 5 | 窗口半长，源码里还会 `rand % window` 动态缩减 |
| `-negative` (K) | 5 | 0 = 不用负采样 |
| `-min-count` | 5 | 出现次数低于此值的词直接扔掉 |
| `-sample` | 1e-3 | 高频词子采样阈值（论文说 1e-5，见 `03 §5.1` 的冲突说明） |
| `-alpha` | 0.025 / 0.05 | SG / CBOW |
| `-cbow` | 1 | 默认 CBOW，Skip-gram 要 `-cbow 0` |
| `-hs` | 0 | 默认关层次 softmax |
| 负采样表 | 1e8 | `const int table_size = 1e8;` |
| 学习率衰减 | 降到 `α₀ × 1e-4` | **相对值**，不是绝对 1e-4 |

### 2.3 坑位速查（详见 §3）

```
loss 一动不动 ≈ 4.159        → 学习率被 batch 平均除没了 / 梯度没回传
loss 越训越大                → lr 太大 或 epoch 太多（NEG 无正则，范数会失控）
loss 变 nan                  → log-sigmoid 用了 naive 写法，exp 溢出成 -inf
similarity 全是 0.99         → 语料太小/太规整，或忘了归一化排查
most_similar 返回自己        → 没把查询词自己 mask 掉
用了 W_out 当词向量          → 标准是 W_in
```

## 3. 高频踩坑点（Troubleshooting）

### 坑 1 · batch 版直接照抄在线版的学习率 → loss 完全不动

**症状**：loss 从头到尾是 `4.1589`（正好 $(1+K)\ln 2$），一步没降。
**原因**：loss 对 batch 取了 `.mean()`，梯度被除以 B=512，等效步长只剩 `0.025/512 ≈ 4.9e-5`。
**实测**：lr=0.025 卡死 / 3.0 收敛不足 / **6.0 正常（2.87→1.57）** / 25.0 nan 发散。
**解法**：batch 化的同时把 lr 放大（量级上 ×√(B) ~ ×B 之间，实测 B=512 时 ×240 附近可行）。

### 坑 2 · 学习率太大 → 不是收敛慢，是**指数发散**

**实测**（同一语料，3 epoch）：

| lr | ‖W‖ 变化 | loss |
|---|---|---|
| 0.01 | 8.9 → 12.2 | 正常下降 |
| **0.025**（原版默认） | 13.1 → 20.1 | 正常下降 |
| 0.1 | 4.7e6 → 1.5e10 | **1e47**，发散 |
| 0.5 | nan | nan |

**判断方法**：训练中打印 `‖W‖`。正常是缓慢增长（几十量级）；发散是指数增长（1e6、1e10…）。

### 坑 3 · epoch 不是越多越好 → loss 不降反升

**实测**：同语料 lr=0.025，
- 5 epoch → loss 3.27→**1.65** ✅
- 20 epoch → loss 2.76→**8.0e5**，‖W_in‖ 涨到 **425** ❌

**原因**：NEG 无正则项，理论最优要求正样本 $s\to+\infty$，范数会一直涨；
小语料上正负样本梯度"拉锯"（一个词既是 A 的正样本又是 B 的负样本），放大了这个效应。
**解法**：监控 loss，**不降了就停**；大语料上原版也只跑 1~5 epoch。

### 坑 4 · naive `log(sigmoid(x))` → nan

**实测**：`np.log(1/(1+np.exp(-x)))` 在 x=−1000 时给 **−inf**；
`-np.logaddexp(0, -x)` 给 **−1000.0**。
**解法**：永远用 `logaddexp`；sigmoid 自己写就分段（见 `03 §4.2`）。

### 坑 5 · `sparse=True` 配 Adam → 直接报错

**实测**（torch 2.6.0）：
```
RuntimeError: Adam does not support sparse gradients, please consider SparseAdam instead
```
**解法**：稀疏梯度只用 `SGD` 或 `SparseAdam`；或者关掉 `sparse=True`（代价：每步更新整个矩阵，慢）。

### 坑 6 · 花式索引的重复下标：`a[idx] -= x` 只生效一次

**实测**：

| 写法 | idx=[1,1,1], x=1 的结果 |
|---|---|
| numpy `a[idx] -= x` | `[0, -1, 0, 0, 0]` ❌（应为 −3） |
| torch `t[idx] -= x` | `[0, -1, 0, 0, 0]` ❌ |
| torch `index_add_` | `[0, -3, 0, 0, 0]` ✅ |
| numpy `np.add.at` | 正确累加 ✅ |

**影响**：一次抽 K 个负样本可能抽到同一个词两次，此时该词的更新被少算一次。
正确做法是 `np.add.at(W_out, neg, -lr*outer(...))`。实际影响很小，但**面试问到"你的实现有什么缺陷"时这是个好答案**。

### 坑 7 · 用错了矩阵：训练完要用 `W_in`

标准做法是取 `W_in`（syn0）。有人用 `W_out`，也有人用 `W_in + W_out`。
**别混着用**：`W_in[i]` 和 `W_out[j]` 不在同一个坐标系里，把两者混在一个相似度计算里是错的。

### 坑 8 · `most_similar` 返回查询词自己

忘了把查询词自己的相似度设成 −inf。同理做类比 `a - b + c` 时要排除 a、b、c 三个词，
否则你永远会得到"答案就是 b"。

### 坑 9 · 用点积当相似度 → 被范数主导

NEG 下各词向量范数差异可以很大（**实测**：初始 ≈0.42，训练后整体 ‖W_in‖=25.3，平均行范数 2.97）。
直接用点积会让"高频词 / 范数大的词"永远排第一。**必须用 cosine（归一化后点积）**。

### 坑 10 · 中文语料直接按空格切

中文没有空格，必须先分词（jieba / pkuseg / LTP），否则得到的是"字向量"或者整句当一个 token。
这一条不在本文代码范围内（本文是英文合成语料），但**中文项目第一步就会踩**。【常识，未实测】

## 4. 高频面试题（6 道 + 白话标准答案）

### Q1. CBOW 和 Skip-gram 有什么区别？什么时候用哪个？

**答**：方向相反。CBOW 用**上下文预测中心词**（多射一），Skip-gram 用**中心词预测上下文**（一射多）。

- **速度**：CBOW 快数倍。Skip-gram 每个上下文词都要单独更新一次，代价约是 CBOW 的 (1+K) 倍量级。
- **罕见词**：Skip-gram 更好——每个罕见词都独立当过中心词；CBOW 把上下文**取平均**，罕见词的信号被稀释了。
- **小语料**：用 Skip-gram；**大语料 / 追求速度**：CBOW。
- 【官方源码】默认 `cbow=1`；默认 α 也不同（CBOW 0.05 / SG 0.025）。

> **追问**：CBOW 的"取平均"失去了什么？→ 丢掉了词序和每个上下文词的独立信息（这也是它快的原因）。

### Q2. 为什么需要负采样？不用会怎样？

**答**：完整 softmax 的条件概率分母是 $\sum_{w=1}^{V}\exp(u_w^\top v_c)$，
**每个训练样本都要算 V 个内积**。V=1e5、D=300 时一个样本就是 3e7 次乘加，根本训不动。

负采样把它改成：1 个真邻居 + K 个随机噪声词，做 **K+1 个二分类**（判断题而非 V 选题），
代价从 $O(V\cdot D)$ 降到 $O((1+K)\cdot D)$，**与词表大小无关**（V=1e5 时约 1e5 倍加速）。

> **追问**：代价是什么？→ 打分不再归一化，**不是概率**，所以 word2vec 不能算句子概率、不能生成文本。
> 另一条路是 Hierarchical Softmax（Huffman 树，$O(\log_2 V \cdot D)$），原版默认用负采样。

### Q3. 负采样的噪声分布为什么是 $U(w)^{3/4}$？

**答**：【论文原文】试过 unigram、均匀分布、3/4 次方，**3/4 次方在所有任务上都显著更好**。
直觉：幂=1（纯词频）会让 "the/a/in" 被采太多，但它们太容易判"否"，梯度信息量小；
幂=0（均匀）又让高频词出现太少，模型学不会区分"常见但不相干"的词。
**0.75 是实验调出来的经验值，没有理论推导**。

### Q4. 为什么有两套向量（`W_in` / `W_out`）？最后用哪个？

**答**：因为打分 $s = u_o^\top v_c$ 是**双线性**的，同一个词当"中心词"和当"上下文词"时角色不对称——
共用一套会强制打分矩阵对称，损失一半表达力，还会让"自己和自己"的打分行为异常。

训练完**取 `W_in`**（原版输出 syn0）。也有人用 `W_in + W_out`，但**不能把两者混在不同的相似度计算里**（坐标系不同）。

### Q5. `king - man + woman ≈ queen` 为什么成立？它有哪些局限？

**答（分两层，这是加分点）**：

- **表层**：训练后空间里出现近似线性的"语义方向"，`king - man` 得到"变成王室"这个方向向量，
  加到 `woman` 上就平移到 `queen`。几何上就是**平行四边形的第四个点**。
- **深层**：【第三方，GloVe 论文的论证】真正编码语义的不是共现概率，而是**共现概率的比值**。
  要让向量支持线性类比，就必须让"内积 = 共现概率的对数"，而线性结构正是 $\log$ 的必然后果。
  对 word2vec 而言，SG+NS 被证明**隐式地在分解 shifted PMI 矩阵**（$PMI - \log k$）
  【第三方，Levy & Goldberg 2014】，所以同样成立。

**局限**（必须主动说出，否则显得只会背书）：
1. **静态向量**：一个词只有一个向量，一词多义无解（"bank" 银行 or 河岸）→ BERT 类的上下文相关表示解决这个问题。
2. **依赖共现统计**：低频词、跨领域词效果差；没有足够共现就没有方向。
3. **成功率被高估**：博客只给你看成功的例子；整体准确率远低于 100%。
4. **我的实测反例**：`paris - france + japan` 在我的合成语料上 top1 是 **beijing** 不是 tokyo——
   因为三个首都词共享完全相同的上下文，模型**没有任何信号区分它们**。类比不是魔法，是统计。

### Q6. Word2Vec 是语言模型吗？能算 perplexity 吗？

**答：不能。** 这是**严格定义 vs 工程实际**的典型题：

| | 真正的语言模型 | Skip-gram |
|---|---|---|
| 建模 | $P(w_{1:T})$ 的链式分解 $\prod_t P(w_t\mid w_{<t})$ | 一堆**独立**的 $P(\text{context}\mid \text{center})$ 相乘 |
| 归一化 | 严格归一化，是真概率 | NEG 下**不归一化**，只是打分 |
| 算句子概率 | ✅ | ❌ |
| 生成文本 | ❌（没有"下一个词"的概念） |

它只是**借**了一个"类语言模型"的代理任务来学表示。
所以别指望用 word2vec 算困惑度或做生成——它的唯一输出是一张查表用的向量表。

## 5. 概念辨析（面试官最爱埋雷的地方）

| 概念对 | 严格区分 |
|---|---|
| **词向量 vs 句向量** | word2vec 是**词级**；RAG 里用的 BGE/E5 是**句子级**，完全不同的东西 |
| **静态 vs 上下文相关** | word2vec/GloVe/fastText 静态（一词一向量）；ELMo/BERT 动态（随句子变） |
| **NEG vs NCE** | NEG 只用**样本**；NCE 还要噪声分布的**数值概率**，理论上更接近真 softmax |
| **NEG vs Hierarchical Softmax** | 前者采样，代价 O(K·D)；后者建 Huffman 树，代价 O(logV·D)，无需采样 |
| **OOV（未登录词）** | word2vec/GloVe ❌ 无解；fastText（字符 n-gram）✅；BPE/subword ✅ |
| **one-hot vs embedding** | 前者是"座位号"（两两正交，不能比远近）；后者是"坐标"（可算距离） |
| **余弦相似度 vs 点积** | NEG 下范数差异大，**必须用余弦**；点积会被高范数词主导 |
