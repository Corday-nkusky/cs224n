# 02 · 直觉模型与演进脉络：为什么需要它，它解决了什么痛点

> 这份回答两件事：**它到底在干什么**（直觉），**它是从哪来的、后来被什么取代了**（演进）。
> 公式一律不写，推导在 `03`。

---

## 0. 一句话定位

> **Word2Vec 是一场「效率革命」，不是「效果革命」。**
> 它用"把多选题改成 K+1 道判断题"这一招，把训练词向量的代价从"算遍整个词表"降到"只算 6 个数"，
> 于是词向量第一次能在**十亿词级**语料上几小时训完——这是它能横扫 2013~2018 的真正原因。

配套的第二个贡献是**工程性的**：它证明了"用一个极简的代理任务（proxy task）学出来的表示"，
效果能打败"精心设计的语言模型"。这个思想后来统治了整个表征学习领域（对比学习、BERT 的 MLM 都是它的后代）。

## 1. 三个直觉：把"词向量"这件事想明白

### 直觉 1 · 观其友，知其人

> **分布式语义假说**（distributional hypothesis，Firth 1957 原话：
> *"You shall know a word by the company it keeps"*）——
> 一个词的意思，就是它**经常和谁一起出现**。

"king" 和 "queen" 你没背过定义，但你知道它们很像——因为你见过的句子里，它们周围都是
crown / palace / throne / rule。**两个词的上下文越像，它们的意思就越像。**

Word2Vec 做的全部事情，就是把这句话变成一个可以优化的数学目标：
> 让"能互相预测"的词，在向量空间里靠近。

### 直觉 2 · 从「座位号」到「坐标」

这是整个 embedding（嵌入）思想的核心对比，值得记牢：

```
   one-hot（独热编码，词 = 座位号）          embedding（嵌入，词 = 坐标）
   ─────────────────────────────────       ─────────────────────────────────
   king   = [0,0,1,0,...,0]  ← V=100000    king   = [ 0.21, -0.83, 0.44, ...]  ← D=100~300
   queen  = [0,1,0,0,...,0]                 queen  = [ 0.19, -0.79, 0.51, ...]
   apple  = [1,0,0,0,...,0]                 apple  = [-0.62,  0.11, 0.03, ...]

   • 任意两个词内积 = 0（正交）              • 内积 = 相似度（cosine）
   • king 和 queen 的距离 = king 和 apple    • king·queen = 0.93  ← 真相似
     的距离，都是 √2 —— 毫无区别              king·apple = 0.05  ← 真不相似
   • 维度 = V（10 万维，且 99.999% 是 0）    • 维度 = D（几百维，稠密，每个分量都有意义）
```

> **白话**：one-hot 给每个词发一个**互不相干的座位号**，座位号之间不能比远近；
> embedding 给每个词发一组**坐标**，能算距离、能加减、能画在图上。
> "嵌入"这个名字的意思就是：把离散的、稀疏的编号，**嵌进**一个连续的稠密空间里。

### 直觉 3 · 空间里的「方向」= 一种语义关系

这是最漂亮的部分。训练完后，向量空间里会出现**有方向性的结构**：

```
                          king
                           ●
                          ╱ ╲          向量减法:  king - man
              (royalty)  ╱   ╲                    ≈ "成为王室" 这个方向
                        ╱     ╲
                       ●───────●         那么:  woman + (king - man)
                     man       queen             = woman 往"王室"方向平移
                                                 ≈ queen  ✓

   同理:  paris - france  ≈  "成为首都" 这个方向
          tokyo  - japan  ≈  同一个方向
   所以:  japan + (paris - france) ≈ tokyo
```

换成几何语言：**词向量空间里存在一个近似线性的"语义坐标系"**，
性别、时态、首都、比较级……各自对应一个方向。类比运算 `a - b + c` 就是在做**平行四边形的第四个点**。

> ⚠️ **这个"线性结构"不是设计出来的，是统计规律浮现出来的。** 03 §8 会讲它和共现概率比值的关系。
> 也别把它神化：它只在大规模真实语料上稳定成立，而且**类比的成功率远低于博客给你的印象**
> （Google analogy 数据集上，原版 skip-gram 的 overall accuracy 大约 70% 量级，不是 100%）。【第三方，凭印象，未复核】

## 2. 数据流：两个结构图

### 2.1 Skip-gram：用中心词猜上下文（本文 MVP 用的就是这个）

```
 语料:  "the king wears a golden crown"
                  │
                  │ 以 king 为中心, C=2 (左右各看 2 个词)
                  ▼
        ┌─────────────────────────────────────┐
        │  the     king     wears    a        │   ← 窗口
        │   ↑       ●        ↑      ↑         │
        │   └───────┼────────┴──────┘         │
        │        上下文词(context)             │
        └─────────────────────────────────────┘
                  │
                  ▼  拆成训练对 (center → context)
        (king, the) (king, wears) (king, a)   ... 每个位置拆 ~2C 对

 每个训练对走一遍:
        center index ──► W_in 查表 ──► v_c  (D,)
                                         │
        context index ─► W_out 查表 ─► u_o (D,) ──► s = v_c · u_o ──► σ(s) ──► 想接近 1
                                         │
        K 个负样本 ────► W_out 查表 ─► U_n (K,D) ─► s = v_c · u_n ──► σ(s) ──► 想接近 0
```

### 2.2 CBOW：用上下文猜中心词（方向反过来）

```
        the  ┐
        wears├─► 向量取平均 ──► h (D,) ──► 与 W_out 打分 ──► 预测 king
        a    ┘
```

**一句话区别**：Skip-gram 是"一词射多词"，CBOW 是"多词射一词"。

### 2.3 两套矩阵的全貌

```
                     W_in  (V, D)              W_out (V, D)
                   ┌──────────────┐          ┌──────────────┐
   中心词下标 c ──► │ 第 c 行 v_c  │          │              │
                   └──────┬───────┘          │  第 o 行 u_o │ ◄── 上下文下标 o
                          │                  │              │
                          └──────── s = v_c · u_o ──────────┘
                                          │
                                       σ(s) → loss

   训练完只留 W_in 当词向量（也可以用 W_in + W_out，gensim 默认只留一份）
```

## 3. 技术演进链条（每一代解决的痛点）

| 年代 | 代表 | 词怎么表示 | 解决了什么 | **还痛在哪**（→ 催生下一代） |
|---|---|---|---|---|
| 1950s~ | **one-hot / 词袋 BoW** | V 维 0/1 向量 | 让计算机能"存"词 | 词之间**无法算相似度**（两两正交）；维度灾难 |
| 1990s | **共现矩阵 + SVD**（LSA / HAL / COALS） | 统计词-词共现，SVD 降维 | 第一次有了"稠密向量"，能算相似度 | 矩阵巨大且稀疏；SVD 重算代价高；**高频词（the/a）主导**整个矩阵；新词来了要重跑 |
| 2003 | **NNLM**（Bengio et al.） | 神经网络的 embedding 层，作为语言模型的**副产品** | 端到端学习，向量质量好 | **最后一层 softmax 要对 V 个词归一化**，隐藏层还有稠密矩阵乘法 → 太慢，只能跑小语料 |
| **2013** | **Word2Vec**（Mikolov, Google） | CBOW / Skip-gram + **负采样** | **把 O(V) 降到 O(K)**；去掉隐藏层稠密计算；单机一天能训千亿词 | **静态向量**：一个词只有一个向量，**一词多义无解**；**OOV 未登录词无解** |
| 2014 | **GloVe**（Pennington, Stanford） | 直接对**共现矩阵的对数**做加权回归 | 把"统计派"（SVD）和"预测派"（NN）统一起来，理论更干净；利用了全局统计 | 依然是静态向量，依然 OOV |
| 2016 | **fastText**（Bojanowski, Facebook） | 词 = **字符 n-gram 子词**向量之和 | **解决 OOV**：没见过的词能用子词拼出来；对形态丰富的语言（德/芬/土耳其语）提升明显 | 依然是静态向量 |
| 2018 | **ELMo** | 双向 LSTM 的**层加权**表示 | **上下文相关**：同一个词在不同句子里向量不同 → 一词多义开始有解 | LSTM 慢、并行差 |
| 2018~ | **BERT / Transformer** | 自注意力 + MLM 预训练 | 上下文相关 + 可并行 + 迁移到下游任务 | 大模型时代：embedding 层变成 LLM 的一部分 |
| 2020s | **专用句向量模型**（BGE / m3e / E5 / Conan-embedding） | 对比学习训练的**句子级**向量 | 直接对标"检索/RAG"场景，词级类比反而不重要 | — |

> **注意这条线的分岔**：2018 之后，"词向量"这个词的含义变了。
> 现在说 embedding，通常指**句子/文档级**、**上下文相关**的向量（RAG 里用的那种）。
> Word2Vec 是**词级、静态**的。两者不是替代关系——LLM 的 embedding 层在数学上和 word2vec 的查表**完全同构**，
> 只是它随整个模型一起被训练、且表示的是 subword（BPE）token 而不是整词。

## 4. 方案对比（选型时直接看这张表）

### 4.1 CBOW vs Skip-gram

| | **CBOW** | **Skip-gram** |
|---|---|---|
| 任务方向 | 上下文 → 中心词（多射一） | 中心词 → 上下文（一射多） |
| 一次更新的代价 | `O((C + K)·D)` | `O(2C·(1+K)·D)`（每个上下文词一次更新，**更贵**） |
| 速度 | **快数倍** | 慢 |
| 罕见词 | 表现差（被上下文平均"稀释"了） | **表现好**（每个罕见词都单独当过中心词） |
| 小语料 | 一般 | **更好** |
| 原版默认 | ✅ 默认 `cbow=1` | 需要 `-cbow 0` |
| 默认学习率 | **0.05** | **0.025** |

> 【官方源码】`word2vec.c`：`real alpha = 0.025` 全局默认，但 `main()` 里有 `if (cbow) alpha = 0.05;`。
> 帮助文本原文：`"default is 0.025 for skip-gram and 0.05 for CBOW"`。
> 【实测】本文两个脚本都用 skip-gram，所以都用 0.025 这一档。
>
> 关于"Skip-gram 小语料更好、CBOW 更快"：这是原版 README 里被广泛引用的经验结论，**我没有逐字复核 README 原文**，标【第三方】。

### 4.2 绕开 softmax 的两条路

| | **Negative Sampling（负采样）** | **Hierarchical Softmax（层次 softmax）** |
|---|---|---|
| 做法 | 抓 K 个噪声词，做 K+1 个二分类 | 建一棵 Huffman 树（按词频），把多分类拆成 `log₂V` 次二分类 |
| 每步代价 | `O((1+K)·D)`，与 V 无关 | `O(log₂V · D)` |
| 谁受益 | 原论文说**对高频词**效果更好 | 原论文说**对低频词**更友好 |
| 实现难度 | 简单（本文 MVP 就是它） | 麻烦（要建树、要算路径） |
| 实际使用 | **默认选择**（原版 `negative=5`，gensim 也默认它） | 罕见词场景；`hs=1` 开启 |

> 【官方源码】`int hs = 0, negative = 5;` —— 默认关掉 HS、开负采样。

### 4.3 Word2Vec vs GloVe vs fastText vs BERT

| | **Word2Vec** | **GloVe** | **fastText** | **BERT 类** |
|---|---|---|---|---|
| 信息来源 | 局部上下文窗口 | **全局共现矩阵** | 局部窗口 + **字符 n-gram** | 全句双向上下文 |
| 向量粒度 | 词 | 词 | 子词 → 词 | subword token → 上下文相关 |
| 静态/动态 | **静态** | **静态** | **静态** | **动态（上下文相关）** |
| 一词多义 | ❌ | ❌ | ❌ | ✅ |
| OOV 未登录词 | ❌ | ❌ | ✅ | ✅（BPE 拼） |
| 训练成本 | 极低（CPU 分钟~小时） | 低 | 低 | 高（GPU） |
| 今天还用吗 | 教学/基线/极低成本场景 | 少 | 形态丰富语言、小语种 | **主流** |

## 5. 一个必须纠正的常见误解

> **❌ 错：「Word2Vec 是一个语言模型。」**
> **✅ 对：它借了一个"类语言模型"的代理任务来学词向量，但它本身不是语言模型。**

严格地说（这是**严格定义 vs 工程实际**的典型例子）：

| | 真正的语言模型 | Word2Vec 的 Skip-gram |
|---|---|---|
| 建模对象 | `P(w₁...wₜₙ)` 的链式分解 `Π P(wₜ｜w<ₜ)` | 一堆 `P(context｜center)` 的**乘积** |
| 归一化 | 分母严格归一化，是真的概率 | **NEG 下不归一化**——`σ(s)` 只是个打分，不是概率 |
| 能算句子概率吗 | ✅ | ❌ 算不了 |
| 能生成文本吗 | ✅ | ❌ 生成不了（没有"下一个词"的概念） |

Skip-gram 的目标函数里，每个上下文词是**独立**预测的，互相之间没有条件依赖——
所以它不是在建模"序列"，只是借"预测邻居"这个任务逼着向量去编码共现信息。

**这个区分的实际意义**：别指望用 word2vec 做语言建模、算困惑度（perplexity）、或者生成句子。
它只有一个输出：一张词表查表用的向量表。

## 6. 什么情况下「不该」用 Word2Vec（边界）

- ❌ 需要**一词多义**（"bank" 是银行还是河岸）→ 用 BERT 类上下文相关表示
- ❌ 需要**句子/文档级**向量做检索、RAG → 用专门的句向量模型（BGE / E5 / Conan）
- ❌ 词表里有大量**未登录词/拼写变体**（用户query、医疗术语）→ fastText 或 BPE 方案
- ❌ 数据极少（几百条样本）→ 直接下载预训练词向量微调，别自己从头训
- ✅ 适合：教学、可解释性要求高（能画出来）、CPU-only 低成本服务、作为 baseline 对照组、
  以及**任何你想亲手搞懂 embedding 是什么**的时候
