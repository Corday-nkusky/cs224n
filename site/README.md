# CS224N 交互复习站

一个入口、按**两条轨道**组织的**离线交互复习站**：12 个知识点（K01–K12，已开工 1 门）+ 4 份动手作业（A1–A4，已开工 1 份），其余在首页显示为灰卡。

- 双击 `index.html` 就能开（`file://` 协议，无服务器、无后端、无数据库）
- 断网可用（KaTeX 与 markdown-it 都是本地拷贝）
- 纯 HTML / CSS / 原生 JS，没有构建步骤
- 首页是**课程列表**，不是 K01 的正文 —— 见下面「多课程地基」
- 首页分「知识点」与「动手作业」两区，两条轨道互通 —— 见下面「两条轨道」

## 一眼看懂的分工

| 谁 | 管什么 |
|---|---|
| `site/data/kNN.js` | **内容的唯一载体**：10 段式正文、公式、交互编排、Quiz、术语表、诚实清单全在这里 |
| `../code/*.py` + `../logs/*.txt` | 数字的实测来源（每个数字都要能复现） |
| `site/data/courses.js` | **课程注册表**：有哪几门课、编号与标题 |
| `site/js/core/` | 纯算法层，浏览器与 Node 共用同一份 |

**交互页就是唯一要读的东西 —— 这是硬要求，不是偏好。**

- 页面里**不许出现「去别处读原文」的指针**。`site.check.js` 的 §2b 用正则扫全文钉住它
  （`arXiv:1310.4546 §2.1` 这类**论文**章节号例外，那是合法出处，不是 md 指针）。
- `../06_讲义精讲/K01_*/**.md` 是**历史讲义的留档**：站点不引用它、也不从它派生任何东西。
  旧的 `tools/build_lectures.py` + `data/lectures.js` 那条派生链已于 2026-10 拆除。
- **改内容 = 改 `site/data/kNN.js`。没有第二处。**

> 2026-10 的方向调整（两波）：
>
> **第一波 · 拆轨** —— 之前是「md 正本 → 站点派生」双轨，读者得自己判断该看哪边，
> 而两条轨体量相当（`k01.js` 102 KB / `lectures.js` 101 KB），谁也不是答案。

>
> **第二波 · 加深** —— 拆完轨之后用户指出：「**你现在的十段式网页最多只能用来复习，里面缺少大量的内容**」。

> 这 5 个主题**完全没写**。
>
> | | 加深前 | 加深后 |
> |---|---|---|
> | 10 段正文 | 10,570 字 | **35,193 字** |
> | 最薄的一段 | 154 字（第 10 段 Quiz） | 2,479 字（第 9 段误区） |

## 多课程地基

一个入口要装多门课时，会碰到四种耦合，性质完全不同：

| 层次 | 不这样做会出什么问题 | 正确的做法 |
|---|---|---|
| **容器层** | 没问题 —— `KB.chapters` / `KB.viz` / `KB.core` 都是 map 挂载式，课 id 只是其中一个 key | 保持，不用管 |
| **命名层** | 算法层若往 `window` 上抛全局单例（`K01CORE` 这种），第二门课一加载就**静默覆盖**它：第一门课的算法全错、**且不报错**，现有断言一条都不会红 | 各挂各的：`KB.core.<课id>` —— 见「硬约束 10」 |
| **心智层**（最容易漏） | `var CHAPTER = KB.chapters.k01`、`'#/k01/' + s.id`、UI 代码里写死的课程清单、写死的课程名标题 —— 换课就全是错的，而且错得很隐蔽 | 全部改成从**注册表 / 当前课程**现取 |
| **轨道层**（2026-10 新增） | 把作业当「第 13 门课」平铺：地址前缀、首页分区、侧栏分组、段骨架假设全都要跟着写死一遍，加一份作业就要改 5 处 UI 代码 | 注册表里一个 `kind: 'task'` + 一个 `parent`，其余全部派生 —— 见「两条轨道」 |

课程清单若硬编码在 UI 渲染代码里，「做完了 K02」就变成要去改 UI 的 `false` → `true`。
`ready` 应该由运行时派生：

```js
KB.courseReady = function (id) { return !!(KB.chapters && KB.chapters[id]); };
```

**做完一门课 = 新增一个 `data/kNN.js` 并挂到 `KB.chapters`**，首页那张卡自动点亮，别的都不用改。
**做完一份作业 = 新增一个 `data/aN.js` + 注册表里一条 `kind:'task'`（带 `parent`）**，
首页分区、侧栏分组、地址前缀、双向链接一起生效。

### 地址约定

```
#/                                首页（课程列表，分「知识点」「动手作业」两区）
#/c/<课id>/<段id>                 某个知识点的一段
#/c/<课id>/ref/glossary[/<i>]     术语表（可定位到第 i 条）
#/c/<课id>/ref/formulas           公式速查
#/c/<课id>/ref/params             参数与形状
#/c/<课id>/ref/honesty            诚实清单
#/a/<课id>/<段id>                 某份动手作业的一段
#/a/<课id>/ref/…                  作业的术语表 / 公式 / 诚实清单（同一套 ref 页）
#/about                           全站关于页
```

**两条轨道在地址栏里就分家**：`c/` 是知识点，`a/` 是动手作业。前缀由
`rootOf(课id)` 从注册表的 `kind` 现取（`kind: 'task'` → `a`），
所以新增一份作业只要在注册表里写 `kind: 'task'`，地址、首页分区、侧栏分组一起生效。

**专业页为什么一定要挂 `ref/`，而不是 `#/c/k01/glossary`：**
段 id 由各门课自己起，和专业页名字放同一个命名空间迟早撞车 —— K01 第 10 段就叫 `quiz`、
第 5 段叫 `formula`，而专业页叫 `formulas`，**只差一个字母**。
加一层 `ref/` 让两个命名空间彻底不相交，将来任何一门课起名叫 `glossary` 也不会出事。

**地址只由两个函数产生**（`app.js` 里的 `courseSec` / `courseRef`；段地址 `courseSec`，
专业页 `courseRef`）。以前 `'#/k01/'` 这种前缀是直接写在 5 处渲染代码里的，
改地址格式要逐个找出来 —— 现在只动这一段。

**自测页地址不能写死**：`quizSecId()` 去找**哪一段挂了 `quizset` 块**。
K01 把它单独放在第 10 段（段 id 就叫 `quiz`），A1 挂在最后一段（`checklist`）——
两处的段骨架本来就不同，写死 `'quiz'` 的话 A1 的自测入口会 404。

**首页与课程内是两种页面形态**：`body` 上挂 `route-home` 类，首页收起「属于某门课」的东西
（左栏段落列表、该课的工具条、进度条），只留课程清单 + 站点级的关于页。
顶栏标题、`<title>`、侧栏分组标题都跟着当前课程现取。

### 两条轨道：知识点与动手作业

作业不是「第 13 门课」。混在一起读起来的后果是把作业当成「又一个知识点」，
而它回答的是完全不同的问题：

| | 知识点（`#/c/…`） | 动手作业（`#/a/…`） |
|---|---|---|
| 回答 | 这是什么 | 现在做什么 |
| 骨架 | 固定十段：是什么 → 为什么 → 直觉 → 数学 → 公式 → 数字 → 动手 → 更大的图景 → 误区 → 自测 | **自己那套**（A1 是：要你交什么 → 开工前的两关 → 四级台阶 → 四个函数 → 三个最易犯的错 → 真语料出图 → Part 2 与书面题 → 交付与验收 → 常见坑 → 自检与自测） |
| 注册表 | 不写 `kind`（默认 `topic`） | `kind: 'task'` + `parent: '<知识点id>'` |
| 交互 | 讲清概念的实验 | **预演**：不装环境就能把要算的东西先算一遍 |

**双向链接全由一个字段推导**（注册表里的 `parent`）：

- `parentOf(作业id)` → 作业页工具条第一条「对应知识点：K01 词向量与分布语义」
- `tasksOf(知识点id)` → 知识点页工具条里「配套动手作业：A1 …」
- 最后一段末尾还有一条**跨轨道出口**（`.xband`）：作业页读完 → 回知识点复习；知识点页读完 → 去做作业。
  只挂在最后一段 —— 挂在每段就成了每页重复的横幅，读到第 3 段的人还不该被催着去写作业。
- 没有对应关系的课（K05 这类还没配作业的）什么都不渲染，不是渲染一个空壳。

**A1 是这条轨道的标杆**（`data/a1.js` + `js/core/a1_core.js` + `js/viz/a1_viz.js`），A2–A4 照抄它的结构即可。

### 交互的公共骨架（`js/ui/viz-kit.js`）

注册表（`KB.vizReg` / `KB.viz.register` / `KB.viz.mount`）与六个公共小件
（`panel` / `ctl` / `slider` / `kvs` / `bars` / `matrix`）原本锁在 `js/viz/k01_viz.js` 的闭包里 ——
于是**只有 K01 能用**，A1 要加交互就只能在第二个文件里把 `panel` / `slider` 再抄一遍，
两份迟早长歪。现在抽出来共用，`k01_viz.js` 的 11 个交互调用点一字未改。

**加载顺序是硬约束**：`viz-kit.js` 必须在任何 `js/viz/*.js` 之前
（那些文件一加载就调 `KB.viz.register` / `KB.vizKit.panel`，kit 没到就直接 TypeError，
而且只在浏览器里炸）。`build_single.py` 里有一条专门判定这件事的硬检查。

`matrix()` 比原来多三个能力：`opts.bads`（把「你的实现和正确答案差在这里」的格子标红）、
`opts.rows`（行表头另给名字，用来展示「词表没排序时每行对到哪个错词」）、`opts.compact`。

## 单文件手机版（`dist/CS224N-mobile.html`）

```bash
python site/tools/build_single.py      # 源码零改动，只产出一个文件
node   site/tests/smoke-mobile.mjs     # 36 条断言，退出码即判定
```

**一个 1.13 MB 的 `.html`，拷到手机上（微信/QQ/AirDrop）用浏览器打开就能用**，
不需要 `css/`、`js/`、`vendor/` 任何一个兄弟文件，也不需要联网。

> ⚠️ 仓库里现有的 `dist/CS224N-mobile.html` 是**2026-10 重构前的快照**，
> 里面还带着「讲义正本」那条轨、也**没有 A1**。用户明确要求**不主动重建**它（费时间），
> 所以它和新站点的内容会不一致。要重新同步就手动跑一次 `build_single.py`。
>
> `smoke-mobile.mjs` 的逐路由扫描因此是**自适应**的：它先看产物里有没有 `KB.chapters.a1`，
> 有才把 `#/a/a1/…` 这些路由加进列表。写死要扫 A1 的话，产物没重建的这段时间里
> 这条会一直是红的 —— 那不是真的坏，是版本不同步。

内联了什么：5 个 CSS 段 + KaTeX CSS + 15 个 JS + **20 条 `@font-face` 的 woff2 字体**
（base64 data URI，占 338 KB）。字体只保留 woff2、丢掉 woff/ttf 两档回落 ——
iOS 10+ / Android 5+ 全支持，覆盖率够；真遇到不支持的机器 KaTeX 会退回系统衬线字体，
公式仍可读，只是没那么"教科书"。

`build_single.py` 里三条**硬判定**（加/删脚本后必须同步，否则中止）：

```python
if len(srcs) != 15:                     raise SystemExit(...)   # 脚本数对不上
if i_courses > i_k01:                   raise SystemExit(...)   # courses.js 排到了 k01.js 之后
if min(i_viz) < i_kit:                  raise SystemExit(...)   # viz/*.js 排到了 viz-kit.js 之前
```


**手机专属补丁只注入到产物里，不写回 `css/`。** 桌面站点的外观一个字都没变
（主站三套校验仍然全绿，条数见「五套校验」）。补丁做的事：

- 关掉 iOS 横屏的自动放大；`viewport-fit=cover` + `env(safe-area-inset-*)` 避开刘海与底部手势条
- 顶栏在手机上**隐藏 `.sub` 说明与进度条图形** —— 那句"断网双击 index.html 即可"是桌面场景的话，
  手机上留着只会把标题挤到换行；省下的宽度让给标题（`E-5` 用 `scrollWidth > clientWidth` 实测它没被截断）
- 触摸目标抬到 ≥ 44px（Apple HIG 下限），`-webkit-backdrop-filter` 补齐 iOS 前缀
- 矩阵 / SVG / 代码块 / 柱状图各自 `overflow-x:auto`，横滑时不许带着整页一起滚

### 两处容易踩的坑（写死在 `build_single.py` 里了）

1. **内联 `<script>` 时的两个字符串**：HTML 读脚本内容时遇到 `<!--` 会转入 escaped 状态，
   之后再出现 `<script` 就进 double-escaped —— 那时 `</script>` **不再闭合脚本**，整个页面会被一个字符串吃掉。
   脚本统一把 `</script` → `<\/script`、`<!--` → `<\!--`（JS 里都是 identity escape，语义不变）。
   `markdown-it.min.js` 里确实有 3 处 `<!--`（它要解析 HTML 注释），目前因为**全文没有 `<script` 字样**才没出事。
2. **只改 token 与布局、不动类名**：和主站同一条纪律，见下面「几条硬约束」。

五套的差别很重要：`site.check.js` 是**静态**的，它在 Node 里读数据，从来不执行 `app.js`。
所以 `app.js` 里一个多余的括号它能全绿通过，而页面其实白屏 —— 这正是 `smoke.mjs` 存在的理由
（第一版就是这么被抓出来的：`KB.app` 根本不存在）。

### `smoke.mjs` 的几条设计约定

- **零依赖**：只要 Node ≥ 20 的全局 `WebSocket`/`fetch` + 本机 Chrome，不下载 Chromium、不起本地服务器。
- **退出码即判定**，并在末尾打印失败清单，可直接提交进仓库当验收脚本。
- **预期断言数硬判定**（217）：断言数对不上直接判失败，防止有人删了断言还显示"全绿"。
  增删断言时要同步改 `EXPECT_TOTAL`；临时本地实验可 `K01_SMOKE_EXPECT=0` 关掉。
- **正向对照**：末尾会**主动抛一个异常**，确认错误收集器真的收得到 —— 否则前面所有
  "无 JS 异常"都是空转。
- **反向对照**：多条"期望为空"的断言都配了对照项。例如验"整式回退"时，
  不只看 `data-lit="all"` 这个属性，还实测整式底色**真的出现了**。
- **`waitFor` 超时要把页面内容一起抛出来** —— 失败信息只有"等待超时：路由 #/about 生效"时，
  真正的原因（`KB.firstReadyCourse is not a function`）根本看不见。现在超时会附上
  `#content` 的前 900 字，一眼就能看出是"页面空白"还是"渲染了别的东西"。
- **异步的东西轮询到落定，别用固定 sleep** —— `T-9`（后退 + 滚动位置恢复）原来固定
  `sleep(800)`，偶尔会抓到 `y=0` 而报红：那是**慢**，不是**坏**。假红一条的代价是

  「目标段已重新渲染进 DOM」+「滚动位置已恢复」。给断言加固定等待前先问一句
  「它是在等一个异步落定，还是在赌一个时长」。

## 几条硬约束（踩过的坑，别改回去）

1. **不用 `fetch`、不用 ES module** —— `file://` 打开会被浏览器拦掉。内容全部走 `data/*.js`。
2. **LaTeX 一律写在 `String.raw` 里** —— 普通 JS 字符串会把 `\f` 之类当转义吃掉。
   `String.raw` 模板字符串**必须以反引号收尾**，用单引号收尾是语法错误。
3. **长公式不撑破布局** —— grid / flex 的子元素默认不会缩到内容以下，
   所有可能装长内容的容器都加了 `min-width: 0`，超宽只在自己的框里横向滚动
   （`.tbl-wrap` / `.mx-wrap` / `.vec` / `.math-block` / `pre` / `.hl-stage`）。
4. **公式逐项高亮** 靠 KaTeX 的 `\htmlClass{hl-pN}{...}` + `trust: true`，
   CSS 只有 `.hl[data-step="N"] .hl-pN` 三条规则（N = 1..3）。
   - 标记**不许跳号**（有 p1 和 p3 却没有 p2 → 中间那步点了没反应）；`site.check.js` 会拦。
   - 分项若讲的是**整体**结论（公式里确实没有对应片段），渲染器会退化成整式高亮，
     不会留一个"点了没反应"的步骤。哪几个分项走了回退，`site.check.js` 会逐个点名。
5. **过渡动画会骗过 `getComputedStyle`** —— 高亮带 0.18s 的 `background-color` 过渡，
   点击后**同步**读样式只能拿到过渡起点（透明）。测样式要么等一会儿再读，要么先关掉过渡。
6. **选择题的选项一律纯文本** —— 不写 `**粗体**` / `__下划线__`，也不放 HTML 标签。
   出过一次真实事故：9 道选择题的正确项全写了 markdown 粗体，18 个干扰项一个都没有，
   于是「哪个选项是粗体」就等于「哪个是答案」。这类泄露**渲染层是对的**（`quiz.js` 忠实渲染数据），
   所以两层断言都配了：`site.check.js` 盯数据（选项不许带强调标记），`smoke.mjs` 盯渲染结果
   （作答前 DOM 里不许有 `<b>`、不许提前打对错记号、同题 4 个选项结构必须一致）。改回去任一层都会红。
7. **术语表每条是「多段讲解」而不是一句话** —— 每条写成 `[r\`名称\`, r\`多段正文\`, '出处']`，
   正文用空行分段、可放 `<div class="eg">例子</div>` / `<ul>` / `$公式$`（`data/k01.js` 顶部有
   `var r = String.raw`，反斜杠不用双写）。渲染走 `KB.md.block`（块级，能出 `<p>`），
   **不是** `KB.md.inline` —— 改回 inline 会让所有段落挤成一坨。
   - `.glos-item` 数量被 `smoke.mjs` 硬判定为 42，改内容可以、增删条目要先同步断言。
   - 释义会被 `site.check.js` 的**模糊词检查**扫到：不许出现「大约 / 大概 / 差不多 / 一般来说 / 通常情况下」。
8. **术语链接只能在 DOM 层插，不能在 HTML 字符串上跑正则** ——
   `app.js` 的 `linkTerms()` 在渲染完成后遍历文本节点，靠 `termSkip()` 避开
   `<code>` / `<a>` / KaTeX / `[data-viz]` 交互区 / **Quiz**。为什么不能在字符串层做：
   HTML 字符串里没法区分「这是正文」还是「这是属性值」，一跑正则就会连 `<a href>` 一起改坏。
   - **Quiz 区绝对不能插链接**：选项里多一个 `<a>`，点击就变成跳转（作答失灵），
     还会打破 `smoke.mjs` F-11「同题 4 个选项 DOM 结构一致」。`T-3` 专门盯这条。
   - 别名从术语名自动推导（括号 / 斜杠 / 去尾部 ` m`、` σ` 这类符号），**长度 < 2 一律丢弃** ——
     `unigram 分布 U(w)` 会推出别名 `w`，放着不管会误匹配 26 处；纯英文别名额外加 `\b` 词边界。
   - 去重：正文整页同一术语只链第一次；术语表内**每条独立去重**（共用一个 used 的话第 10 条之后就没链接了），
     且不链自己（`T-8` 盯这条）。
   - 落点路由是 `#/c/<课id>/ref/glossary/<下标>`，下标是 **glossary 数组序号（0 起）**，不是页面上的条目号（1 起）。
   - 链接样式试过 `color: inherit` 只留虚线 —— 实机截图里几乎看不见，等于没做；现用主色 + 虚线。
9. **不要给术语链接额外做「回到原文」按钮** —— 浏览器自带后退就够了，而且比自定义按钮更好：
   hash 路由下后退会把**滚动位置一并精确恢复**（实测离开前 `y=1200` → 后退后 `y=1200`，
   连被点的那个链接都停在视口同一个位置）。原理是浏览器的 scroll restoration 在
   `route()` 里那句 `window.scrollTo(0, 0)` **之后**执行，正好覆盖掉它。
   - 但这依赖 `history.scrollRestoration` 保持默认 `'auto'`。**谁在 `route()` 里改成 `'manual'`
     （想"自己管滚动"），这个能力会静默失效** —— `smoke.mjs` 的 `T-9` 就是锁这条的，会立刻变红。
   - 如果哪天真要加自定义回退 UI，记得连同 `T-9` 一起改，别让它变成一条过时断言。
10. **各课的算法层必须挂 `KB.core.<课id>`，不许往 `window` 上抛全局单例** ——
    全局单例是两门课共用一个名字，**后加载的那门会静默覆盖它**，于是先加载的课程
    11 个交互数字全错**且不报错**。挂载式（`KB.core.k01` / `KB.core.k02`）各挂各的才不会互相踩。
    `core.test.js` 走 `require()` 取的是 `module.exports`，所以浏览器侧的命名变化不影响 Node 侧 151 条断言。
11. **不许给路由写「悄悄回落第一段」的兜底** —— 地址打错时页面看起来完全正常，
    这种错能一直藏到有人发现内容不对。`renderUnknown()` 显式报「没有这个地址」，
    并且 `route()` 用 try/catch 把渲染异常打在页面上（防白屏）。
12. **侧栏是两级目录，段落必须嵌在自己那门课下面** —— 一级是课程，二级是**当前那门课**的段落
    （缩进 + 左侧竖线 + `▾` 标记）。把段落平铺在整个课程清单**之后**会被读成「第 13 门课」，
    看不出这些段落属于谁。实现上就是：渲染课程时，若这门课是当前课程，
    紧接着 append 它的 `<ul class="sec-nav">`（`app.js` 的 `renderCourseTree` / `secNavFor`）。
    - 首页没有任何「打开的课程」，所以二级目录**根本不渲染**（不是用 CSS 藏起来 ——
      藏起来的话 DOM 里仍有一个语义上属于某门课的列表）。
    - 工具条（术语表 / 公式速查 / Quiz…）全是「某门课的」，所以带一个动态分组标题
      「K01 · 工具」；首页没有课程，标题一并去掉，只留站点级的关于页。
13a. **每段开头的导读卡（`goal`）和第 1 段的本课地图（`roadmap`）不许删** ——
    用户原话是「学习时不知道看哪个，效率很低」，这两样就是针对那句话做的导航层。
    `site.check.js` §2b2 钉住「10 段每段开头都有导读卡」「地图覆盖 10 段且顺序一致」，
    `smoke.mjs` 的 `G-nav-1..4` 钉住渲染与点击跳转。
13b. **每段正文有体量下限，别把某段"顺手精简"回要点列表** ——
    2026-10 用户提醒：「**你现在的十段式网页最多只能用来复习，里面缺少大量的内容**」。
    量化诊断证实如此：加深前 10 段正文只有 10,570 字（第 7 段的 11 个交互只有 437 字、
    第 10 段只有 154 字）。现在的下限写死在 `site.check.js` §2b3：
    **每段 ≥ 2,000 字 / 10 段合计 ≥ 32,000 字 / 每段 ≥ 8 块**。
    这条断言防的正是「改薄」—— 那种改法**不会让任何旧断言变红**，却正好把用户抱怨的问题
    原样搬回来。要加内容随便加；要删，就得连着这条下限一起论证，别让它悄悄退化。
    - `goal` 卡的列数是**自适应**的（`.goal` 用 `grid-auto-flow: column`，不写死 3 列）：
      第 1 段没有「前置」这一栏，写死 `repeat(3, 1fr)` 会让空出的第 3 格露出容器底色。
      所以 `smoke.mjs` 的 `G-nav-1` 断言第 1 段是 **2 栏**、`G-nav-4` 断言其余段是 **3 栏**，
      `G-nav-5` 再量一遍列宽确认是均分（没有 leftover 空格）。
13c. **LaTeX 的反斜杠：两种字符串写法，规则正好相反** ——
    `data/k01.js` 里两种字符串都在用，反斜杠要写几个**不同**，写错都不让 KaTeX 报错：
    - **`String.raw` 模板**（`` r`...` ``）→ 写 **1 个**。
      写成 `\\mid` 会被 LaTeX 读成**换行**：`` r`$P(\\text{ice}\\mid\\text{solid})$` ``
      渲染成「P(」换行「textice」换行「mid」……公式被拆成好几行。
    - **普通单引号串**（`'...'`）→ 写 **2 个**。
      写成 `'$V\cdot D$'` 会把 `\c` 吃成 `c`（表格里印出 `VcdotD`）；
      `'$V\times d$'` 更狠 —— `\t` 是**真转义**，直接变成制表符。
    - 两种产物都**不报错**（剩下的还是"合法数学"），所以 §4 的 `throwOnError` 完全拦不住。
      2026-10 一次性抓到 **16 处 raw 模板 + 18 处单引号串**，全靠**看截图**才发现
      （第 8 段的公式被拆成三行、第 10 段的表格印着 `VcdotD` 和 `alpha = 0.75`）。
    - 现在两条断言钉住：**§4b** 扫求值后的数据（raw 模板留下的双反斜杠一眼可辨，
      只放过矩阵换行 `\\` 后面跟数字的情况）；**§4c** 扫**源码文本** ——
      单引号串的损坏发生在求值那一刻，数据里反推不出来，只能读源码。
      两条都做过反向对照（注入错误 → 变红 → 还原），确认不是空转。
14. **「关于」这类全站页不许挂任何课程编号** —— 眉标写 `'CS224N · ' + courseNo()` 的话，
    进过一次 K01 就永远是 K01；正文里的数字、路径、进度也不能取当前课程，
    否则「关于」会跟着你最后看的那门课变形。`smoke.mjs` 的 `G2-8` 直接断言
    眉标与正文里都不出现任何课程编号。
15. **交互面板故意比正文宽（`--viz-bleed`）** ——
    用户原话：「**可交互可视化那一节的交互界面太小了，应该和上面的文字同宽导致**」。
    正文那 780px 是为「读」定的（一行四十来个字最省眼），但矩阵/条形/哈夫曼树是拿来
    「看」的，被同一条行宽卡着只能缩在左上角。做法是让 `.viz` 向两侧出血，
    **出血量 = 中间栏还剩多少空位**（`css/viz.css` 的 `--viz-bleed`，上限 400px），于是：
    宽屏铺开到一千多像素；中等屏（1280 那种主流笔记本）至少吃回正文的左右 padding，
    也宽出 68px；≤860px 归零，**绝不会压到左右两栏**。
    `smoke.mjs` 的 `I2-1` 量「1600px 下面板比正文宽 ≥150px」、`I2-2` 量「左右不越界」、
    `I2-4` 单独量 1280 这一档（下限改成 0 的话它会红）。
16. **条形填充条必须 `display: block`** —— 它是 `<i>`，**行内元素的 `width`/`height` 一律无效**。
    少了这一行，52 条填充条全部渲染成 0×0 的空盒子：页面上只剩左标签和右数字、中间一片空白，
    而**元素在、class 对、`style="width:100%"` 也写着**，四套校验没有一条会红。
    修之前整整一版都是这样（2026-10 用户报「表里全是无色的，没有按长度渲染颜色」）。
    现在 `site.check.js` §2b4 对着源码钉 `display:block`，`smoke.mjs` 的 `I2-3` 量真实盒子
    （display 必须是 `block` 且宽高 > 0），两条都做过反向对照。
17. **左上角品牌区是 `<a href="#/">`，倒三角是独立按钮** ——
    - 品牌区（NLP 方块 + 文字）整块回首页，**用 `<a>` 而不是绑 click**：
      只有真链接才自带中键、右键「新标签打开」和键盘 Tab + Enter。
      `site.check.js` §2b4 与 `smoke.mjs` 的 `G4-1/G4-2` 钉这条。
    - 倒三角只管「展开 / 收起」，**不跳转**，所以它的 handler 里必须有
      `e.stopPropagation()` —— 不停的话这次点击会冒泡到行上（行上的行为是「进入这门课」），
      于是「收起」和「跳转」同时发生，看起来就像根本收不起来。
      `smoke.mjs` 的 `G3-1` 断言「目录 10 → 0 条、箭头 ▾ → ▸、**hash 一动不动**」。
    - 收起状态只跟**当前这门课**绑定：`app.js` 的 `navCollapsed` 在 `routeInner` 里
      跟着路由清理。不清理的话，首页和关于页的侧栏会挂着一门课的段落目录
      （`G2-6` / `G2-8` 立刻红 —— 这个回归真的发生过一次）。
18. **`String.raw` 模板里一个字都不许出现反引号** ——
    `String.raw` **不处理 `\`` 转义**：写 `` r`A \`\`\` B` `` 求值出来是 `"A \`\`\` B"`（留下反斜杠），
    而写裸反引号（想表达 Markdown 的行内代码）**直接是语法错误**。
    这不是理论风险：写 A1 内容时踩了三次（`data/a1.js` 的 `intro`、一段从 notebook 复制的
    docstring、以及 `honesty` 里的一处），三次都是 `node --check` 报
    `SyntaxError: Unexpected identifier 'xxx'`，而报错行号指着**下一个**标识符，很难定位。
    规矩：
    - **行内代码一律用 `<code>` 标签**（`data/k01.js` 从头到尾都这么写，所以从来没踩到）；
    - **多行代码用 `{ t: 'code', text: … }` 块**，别在模板里手拼三反引号围栏；
    - 实在要在正文里印出反引号字符，就用 HTML 实体 `&#96;`。
19. **作业页的自测地址不能写死 `'quiz'`** ——
    K01 把 `quizset` 块单独放在第 10 段（段 id 就叫 `quiz`），
    A1 挂在最后一段（`checklist`）。写死 `'quiz'` 的话，A1 的「去 Quiz 自测」
    会跳到 `#/a/a1/quiz` —— 那一格不存在，页面显示「没有这个地址」。
    现在统一走 `quizSecId()`：**去找哪一段挂了 `quizset` 块**。
    连带一个小处理：如果自测块**就在当前这一段里**（作业的骨架就是这样），
    页尾那张卡的文案换成「回术语表速查」—— 否则它是一张点了没反应的卡。
