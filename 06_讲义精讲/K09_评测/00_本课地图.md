## §1 这一课要回答的问题

**主问题**：K08 之后，你手里有了一个能检索、能生成的系统。**但你怎么说它"好"？** 评测给出的那个数字，凭什么信它？这一课回答的就是"**说不清模型到底好不好**"这个痛点——它不教新模型，教的是**判断模型好坏的整套方法，以及这些方法各自的破绽**。

**拆成十个必须回答的子问题**：

| # | 子问题 | 在哪答的 |
|---|-------|---------|
| 1 | 为什么"模型好不好"说不清？评测到底要回答什么？ | `01` §1 |
| 2 | 为什么必须用 **held-out 测试集**，而不是看训练集或挑几个例子？ | `01` §2 |
| 3 | **benchmark** 是什么？它和测试集什么关系？怎么从 GLUE 走到 MMLU/HLE？ | `02` §1 |
| 4 | 常见指标（accuracy / EM / token-F1 / BLEU / ROUGE / pass@k / win-rate）各在量什么、何时用哪个？ | `02` §2 |
| 5 | 好的 benchmark 要满足什么？为什么会有"蒙对"？ | `02` §3 |
| 6 | 上面这些说法是真的吗？跑一遍看对不对 | `03` 全篇 |
| 7 | **LLM-as-judge** 为什么流行？它的偏置从哪来、有哪些？ | `02` §4、`04` §4 |
| 8 | EM/F1 的公式长什么样？**pass@k 的无偏估计**从哪来？ | `04` §2–§3 |

## §3 知识清单

每条一句话结论 + 出处。**扫一遍，看有没有哪条你讲不出来。**

### A. 为什么评测难（3 条）

1. 【slides】p4：**benchmark 与 leaderboard 在驱动进展**——但 p5 同时承认"最常见 benchmark 太多了、还在不断变、且前沿大模型和小开源模型的榜单不一样"。
2. 【slides】p15：好 benchmark 的四个 desiderata——**scale/diversity、difficulty（人类够得着、SOTA 够不着）、quality（答案明确正确）、no spurious bias**；否则"**AI 能以错误理由把题做对**（right for the wrong reasons）"。
3. 【slides】p66–68：**Goodhart 定律**——"当一个度量变成目标，它就不再是好度量"。这是整课的元命题。

### B. benchmark 家族（5 条）

4. 【slides】p7–8：**GLUE / SuperGLUE** 是"把已有 benchmark 标准化/重排后的集合"，覆盖广谱"直觉级 NLU 能力"（BoolQ、MultiRC、CB、RTE、COPA、ReCoRD、WiC、WSC），榜单吸引大量参与。
5. 【slides】p9–11：**MMLU** 57 个任务，**知识密集**（高中到大学），是训练/后训练期最常用的跟踪基准；**MMLU-Pro 更难**。
6. 【slides】p12：**GPQA** 研究生级"Google-proof"问答，发布时（2023-11）看着太难，到 COLM 2024 时 **O1 已达 78.3%**——**benchmark 会饱和**的活证据。
7. 【slides】p13：**HLE（Humanity's Last Exam）**——为对抗饱和而生的更难题集。
8. 【slides】p28：**行为类 benchmark**——迎合（sycophancy）、诚实、讨好、观点。p31–33 按"答案类型 → 判分复杂度"分类：选择题→accuracy 最简单；短答案→**span 匹配 / 精确数值匹配**（SQuAD、AIME、FrontierMath）；句子答案→**判分是 `???`**；长答案→IFEval、LongGenBench、WriteBench。

### C. 指标（6 条）

9. 【slides】p35–36：**model-free 经典指标**——BLEU（MT，**precision 导向**，n-gram 重叠）、ROUGE（摘要，recall 导向）、METEOR（含词干/同义）、CIDEr（用 TF-IDF 奖励"共识"）、TER（编辑距离）、WER（ASR 标准）。**p36 的判词：太拘泥表面模式，语义不够**。
10. 【slides】p37：**n-gram 重叠没有语义概念**的实例——"Are you enjoying the CS224N lectures?" 的几种回答里，"Yes!" 得 0（false negative）、错的回答反而得高分（false positive）。
11. 【slides】p38–40：**model-based 指标**——BERTScore（BLEU/ROUGE 的"软嵌入版"，Zhang 2020）、Word Mover's Distance（嵌入版 EMD，Kusner 2015）、BLEURT（训来模仿人类评测，Sellam 2020）。
12. 【slides】p41：model-based 指标的六个隐忧——**受模型自身偏置限制、对事实错误/幻觉不敏感**（BERTScore 会给 "born in 1942" vs "1924" 高分）、跨域无校准、算力与可复现性、**长度偏置**、与人判断不一致的实证。
13. 【slides】p43–49：**信息论指标**——Shannon 熵 / Von Neumann 熵度量**多样性**（p44），Vendi score（p45，G-Vendi 在梯度上算，能预测 OOD 表现）；KL 散度度量**分布距离**，但高维连续分布不可积、支撑不交时除法除零（p47），**MAUVE 用"量化 + K-means + 求 KL"绕过**（p48–49）。
14. 【slides】p51–52：**reference-based vs reference-free**——前者有金标准答案、是长期标准，但金标准质量差/覆盖不足就会失效，模型会**过拟合参考的怪癖**；后者没有金答案，从"不可想象"变成新常态（G-Eval、FActScore、SelfCheckGPT、CLIPScore、COMETKiwi）。

### D. judge 与人类（4 条）

15. 【slides】p54–55：**人类评测是"终极理想"但有硬伤**——贵、不可扩展、主观、评分者间一致性、不可复现、以及**可信度陷阱 / 流畅陷阱 / 长度陷阱**；且**不同方式做的研究之间分数不可比**。做法对的关键：**明确 rubric、多人标注再校准、算 inter-rater agreement**。
16. 【slides】p56–61：**Chatbot Arena** 用真人偏好对战。优点：**比别的评测更"in the wild"**；缺点：会混入大量怪异/越狱查询、成本高、只测有名模型、外部效度存疑。
17. 【slides】p63：**LLM-as-a-judge**——比人评便宜、更听指令，但偏置明确：**自我偏好 / 裙带偏置（偏爱自己或同门的输出）、verbosity（啰嗦）偏置、擅长"氛围检查"但**弱于细逻辑、强模型当 judge 也贵。
18. 【slides】p64：做对 judge 的办法——**清晰指令/示例/rubric、让多个 judge 讨论**（ChatEval 2023、CollabEval 2025）、**"LLM 陪审团"用多样化评委面板**兼顾抗偏置与成本。

### E. 污染、饱和与可复现（4 条）

19. 【slides】p71–73：**数据污染**——训练语料里可能就有测试集（互联网数据、合成数据都会污染）；检测手段是 **n-gram 重叠（常用 8–13 gram）**，辅以嵌入/改写式近重复检测。
20. 【slides】p75：**生成器-校验器间隙（GV gap）**——"7+8"答 15，"7+8=15, True or False" 却答 False；GPT-4 也只有 **76%** 自洽。说明"答对"不一定等于"真懂"。
21. 【slides】p76：**prompt 格式影响巨大**——zero-shot vs few-shot、几个 shot、是否 CoT、甚至**少了一个空格**、以及**答案抽取脚本本身**，都改变分数 → **可复现性受挑战**。
22. 【slides】p77：开放问题——**评测的科学落后于工程的进展**：真正的理解 vs 模式匹配、防污染与 gaming、校准/认识论不确定性/诚实、**能力与诱发（elicitation）分离**、整体评测，以及**元评测（评测的评测）**。

## §5 术语索引

按首次出现的篇排。`01` 篇零前置，`02` 篇是本知识点核心概念，`04` 篇才需要推导背景。

| 术语 | 一句话解释 | 出处 |
|------|-----------|------|
| **held-out 测试集** | 训练时绝不接触、只在最后评一次的数据 | `01` §2 |
| **train/dev/test 三分** | 调参用 dev、最终只测一次 test，防止"偷看" | `01` §2 |
| **benchmark** | 标准化的问题集 + 评分方式 +（通常）榜单 | `02` §1 |
| **leaderboard** | 把多个模型在同一 benchmark 上的分数公开排名 | `02` §1 |
| **accuracy** | 判对的比例，选择题最直接 | `02` §2 |
| **EM（exact match）** | 归一化后整串相等才算 1 | `02` §2、`04` §2 |
| **token-F1** | token 级 precision/recall 的调和平均 | `02` §2、`04` §2 |
| **BLEU / ROUGE** | n-gram 重叠；前者 precision 向（MT）、后者 recall 向（摘要） | `02` §2 |
| **pass@k** | 生成 n 个样本、抽 k 个，至少一个正确的概率 | `02` §2、`04` §3 |
| **win-rate** | 成对比较里某模型的胜出比例（judge/人评用） | `02` §2 |
| **reference-based / free** | 有无金标准答案作参照 | `02` §3 |
| **spurious bias** | 数据里的"假捷径"（标注 artifact），让模型以错误理由做对 | `02` §3 |
| **对抗 / 动态 benchmark** | 用模型参与构造、持续更新的评测，抗饱和 | `02` §3 |
| **LLM-as-judge** | 用另一个 LLM 当裁判打分/选优 | `02` §4 |
| **位置偏置 / 长度偏置 / 自我偏好** | judge 受槽位、长度、是否自己产出影响 | `02` §4、`04` §4 |
| **人类评测 / rubric** | 真人打分；rubric = 明文评分标准 | `02` §5 |
| **inter-rater agreement** | 不同评分者一致程度（人评的可靠性指标） | `02` §5 |
| **数据污染（contamination）** | 测试样本进了训练语料，分数虚高 | `02` §6、`04` §5 |
| **de-contamination** | 用 n-gram/嵌入近重复检测剔除污染样本 | `02` §6 |
| **benchmark 饱和** | 所有模型都接近满分，失去区分度 | `02` §6 |
| **Goodhart 定律** | 度量一旦成为目标就失效 | `02` §6 |
| **red teaming** | 主动攻击模型以找漏洞/越狱，算安全评测 | `02` §6 |
| **统计显著性 / 置信区间** | 分数差是否超出抽样噪声 | `04` §6 |
| **元评测** | 对 benchmark 和指标本身再做评测 | `02` §6 |

## §7 下一课预告：K10 推理模型（CoT / test-time compute）

会复用本课的东西：**"跑分→判断"这套动作不变**，K10 的新模型同样要靠本课这套评测才能说清"推理到底有没有变强"。

会变的两样：

1. **评测对象从"答案"变成"过程"** —— 长链推理的分数好看，可能是真推理，也可能是本课 p75 说的"**假装推理/自洽间隙**"；评测要能区分。
2. **饱和的出路会具体化** —— 本课 p12/p13 讲的"更难 benchmark（GPQA→HLE）"正是推理模型的主战场。

**本课的收益在 A4 立刻兑现**：A4 B 部分就是本课 `04` §2（EM 的变体——GSM8K 数值精确匹配）与 `02` §2（指标选择）；C/D 部分就是 `02` §4（judge + 长度偏置直方图）；E 部分就是 `02` §6（红队）。
