# K09 · 02 它到底是什么

> **进这一篇之前你能说出什么**：① 好评测必须建在模型没见过的数据上；② 一个数字离开"怎么算的、有没有捷径"就没有意义；③ 度量一旦被当目标就会失效。
> **这一篇回答什么**：benchmark 到底是什么？指标家族怎么分、各自量什么？judge 怎么当裁判？污染、饱和、红队各是什么？
> **读完你应该能说出什么**：
> 1. **benchmark = 标准化问题集 + 评分方式 +（通常）榜单**；它和 held-out 测试集的关系
> 2. 指标分清四组：**model-free / model-based**、**reference-based / free**、**信息论**、**成对偏好（win-rate）**——以及 accuracy/EM/F1/pass@k 何时用
> 3. **spurious bias**（假捷径）如何让模型"以错误理由做对"；对抗/动态 benchmark 怎么反制
> 4. **LLM-as-judge** 的四类偏置；**数据污染**的机制与检测；**饱和 / 红队 / 可复现性**

**这一篇不推公式、不跑代码。** 会给几个定义式的**口头版**和手算级的小例子（3 句话、5 个词），真正需要推导的都在 `04`。
**这一篇的目的是让你在 `03` 里看见那些数字时，知道每个数字是什么、该不该长那样。**

## §1 benchmark 是什么

### 1.1 三个东西别混

| 概念 | 是什么 | 关系 |
|------|--------|------|
| **测试集（held-out）** | 一批模型没见过的问题 + 正确答案 | benchmark 的**原料** |
| **benchmark** | **标准化的**问题集 + **固定的评分方式**（+ 通常有榜单） | 对测试集"做了规格化"的成品 |
| **leaderboard** | 把很多模型在同一 benchmark 上的分数**公开排名** | benchmark 的展示面 |

【slides】p7 一句话点破 SuperGLUE 的性质：它是"**一堆已有 benchmark 被标准化/重排后的集合**"。也就是说，benchmark 的价值不只在题目，更在于**大家用同一套题、同一套评分**——否则分数不可比（这正是 `01` §3 的后果）。

> **【直觉】用你 408 里的东西打比方——SPEC / Dhrystone**：同一条跑分程序、同一套编译参数，不同机器的分数才能比较。**benchmark 就是机器学习界的"跑分标准"**。

### 1.2 benchmark 的几代（【slides】p7–13）

| 代 | 例子 | 特征 |
|----|------|------|
| **直觉级 NLU 集合** | **GLUE → SuperGLUE** | 把已有任务标准化拼起来，覆盖广谱"语言理解"（BoolQ、MultiRC、CB、RTE、COPA、ReCoRD、WiC、WSC） |
| **知识密集多任务** | **MMLU**（57 任务） | 不再只是"语言理解"，而是**高中到大学各科知识**；训练/后训练期最常用；**MMLU-Pro 更难** |
| **研究生级难题** | **GPQA → HLE** | 为对抗饱和而生；GPQA 发布时"太难"，一年后 O1 到 **78.3%**（p12），于是有了 **HLE**（p13） |
| **行为/安全** | 迎合、诚实、观点（p28） | 不测知识，测**行为倾向** |

这里有一张图（p6 "Trend: Multi-Task Benchmarks"），讲的是"多任务 benchmark 成为趋势"；p10 是 MMLU 的题目截图，p13 是 HLE 的封面——**都不含可提取文字，故不转写**。

### 1.3 按"答案类型"看判分难度（【slides】p31–33）

这张表是本课最实用的一张，**判分难度从上到下递增**：

| 答案类型 | 判分方式 | 代表 benchmark |
|---------|---------|---------------|
| **选择题** | straightforward **accuracy**（最简单） | GLUE、MMLU、TruthfulQA、SimpleQA、GPQA Diamond、HLE 选择题部分 |
| **短答案** | **span 匹配 或 精确数值/表达式匹配** | SQuAD、AIME 2025、FrontierMath、HLE 短答案部分 |
| **句子答案** | **`???`**（slides 自己打了三个问号！） | 句子级翻译、摘要、复述、图像描述 |
| **长答案** | 专门 benchmark（判分难） | IFEval、LongGenBench、WriteBench |

**"句子答案"那格写着 `???` 是这张表最重要的一格**：它说明**翻译/摘要/复述这类任务的判分，官方都没给公认答案**——这正是下文 BLEU/ROUGE/judge 存在的理由。

## §2 指标家族：每个指标在量什么

指标可以按两条轴分，清楚了就不容易选错。

### 2.1 轴一：model-free 还是 model-based（【slides】p35–41）

| 类 | 是否用模型 | 代表 | 在量什么 |
|----|-----------|------|---------|
| **model-free（经典）** | 不用，纯统计 | **BLEU**（MT，**precision 向**，n-gram 重叠）、**ROUGE**（摘要，**recall 向**）、METEOR（含词干/同义）、CIDEr（图片描述，TF-IDF 奖励共识）、TER（编辑距离）、WER（ASR） | **字面/重叠** |
| **model-based** | 用嵌入或训练好的模型 | **BERTScore**（BLEU/ROUGE 的"软嵌入版"）、**Word Mover's Distance**（嵌入版 EMD）、**BLEURT**（训来模仿人类评分） | **语义相似** |

**BLEU/ROUGE 的死穴**（【slides】p36–37）：它们**没有语义概念**。slides 给了个扎心的例子——问 "Are you enjoying the CS224N lectures?"：

```
回答          打分
"Yes!"        0        ← false negative（人觉得对，机器判 0）
"Yup."        0.67     ← 字面重叠高
（某个否定的回答）     高分   ← false positive
```

> **手算级例子**：ref = "the cat sat"，gen = "the cat sat down"。
> 逐词看，3 个词都命中、多了一个词。**precision（对上的/生成的）≈ 3/4，recall（对上的/参考的）= 3/3** → BLEU 偏低、ROUGE 偏高。**同一对文本，换个取向就换个数。**

**model-based 的六个隐忧**（【slides】p41）：受**模型自身偏置**限制、**对事实错误/幻觉不敏感**（BERTScore 会给 "born in 1942" 和 "born in 1924" 很高分）、跨域无校准、算力和可复现性、**长度偏置**（越长越容易"蒙中"）、与人判断不一致的实证。

### 2.2 轴二：reference-based 还是 reference-free（【slides】p51–52）

| 类 | 有无金标准答案 | 代表 |
|----|--------------|------|
| **reference-based** | 有 | BLEU/ROUGE、BERTScore、COMET |
| **reference-free** | 无 | COMETKiwi/QE、**FActScore**（把长文拆成原子事实逐条核）、CLIPScore、**SelfCheckGPT**（多次采样看自洽）、**G-Eval**（用 judge + CoT） |

reference-based 的失效点（p51）：**金标准本身质量差、或覆盖不了多样的正确写法**时，分数没意义；更糟的是——**模型会过拟合参考的怪癖**，参考分数涨了、人评质量没涨。

### 2.3 信息论指标（【slides】p43–49）

- **熵度量"多样性"**：Shannon 熵 = "平均信息量/惊讶度"；Von Neumann 熵是它的量子推广（在**样本相似度矩阵**上算）。用它测"benchmark 的多样性"或"模型输出的多样性"（p44）。Vendi score 是现役做法；G-Vendi（2025）在**梯度向量**上算，据称最能预测 OOD 表现（p45）。
- **KL 散度度量"分布距离"**：想用它比"模型的语言 vs 人类的语言"——**理论可以，实践卡住**：高维连续分布不可积；且两分布**支撑不交**时除法除零（p47）。**MAUVE（2021）用"量化"绕过**：把文本嵌入 → K-means 聚类 → 在两个 k-类多项式分布上算 KL（p48），再在 KL 与 reverse-KL 之间平滑插值成一条"前沿"（p49）。

### 2.4 任务与指标的对应（把 §1.3 补齐）

| 任务 | 首选指标 | 为什么 |
|------|---------|--------|
| 选择题 | **accuracy** | 判分最干净 |
| 短答案 / 数学 | **EM**（精确匹配，数值题常用其变体） | 答案只有一个形式时最硬 |
| 抽取式问答 | **token-F1** | EM 太严，F1 给部分分 |
| 翻译 | **BLEU** | precision 向 |
| 摘要 | **ROUGE** | recall 向 |
| 代码 | **pass@k** | 有多个正确解，只看"能不能跑对" |
| 开放生成 / 对话 | **win-rate**（judge 或人评的成对胜率） | 没有唯一答案，只能两两比 |

**EM、token-F1、pass@k 的口头定义**（公式在 `04`）：

- **EM**：**归一化后整串相等**才记 1，否则 0。归一化通常含小写、去标点、去冠词。**"好答案换个写法就 0 分"**是它的代价。
- **token-F1**：把预测和参考切成 token，数**交集**，算 precision 与 recall，取**调和平均**。答对一半也能得分。
- **pass@k**：让模型对同一题生成 $n$ 个样本。**"至少有一个正确"的概率**就是 pass@$k$。**关键：它随 k 单调上升**——`03` §2 会实测 pass@1=0.30、pass@5≈0.87、pass@20=1.0。**报 pass@k 不带 k，等于没报。**
- **win-rate**：成对比较里某模型胜出的比例。判官可以是人（Chatbot Arena）也可以是 LLM。

## §3 好的 benchmark 长什么样，以及"假捷径"

### 3.1 四条 desiderata（【slides】p15、p18、p26）

| 要求 | 含义 |
|------|------|
| **Scale & diversity** | 要覆盖关心现象，复杂现象需要**又多又杂**的样本 |
| **Difficulty** | **人类（专家）够得着、SOTA 够不着**——太易没区分度、太难全 0 |
| **Quality** | 正确答案必须**明确正确**；"没有大量功夫很难保证"（slides 原话 "Surprisingly hard"） |
| **No spurious bias** | 不能有"标注 artifact"，否则模型**以错误理由做对** |

**SQuAD 是正面教材**（【slides】p16–17）：高质量、超大规模（10 万），两个创新——**span-based 评测** + **不可答问题**（SQuAD 2）。对比之下：MCTest 小（2.6k）、CNN/DM 大但**自动生成、噪声、靠模式匹配**、SQuAD 居中（规模大、人工写、中等推理）。

### 3.2 "假捷径"的两种典型（【slides】p19–23）

1. **词面重叠（copy-paste 捷径）**：问题含答案句的词 → 模型找重词最多的句子（`01` §2，干扰句一插，**75%→36%**）。
2. **标注 artifact**：不可答问题里的 **"not"**（否定偏置）、**人名替换**（Obama→Bush）成了信号。

反制武器是**诊断集**：【slides】p22–23 的 **HANS**（Heuristic Analysis for NLI Systems）——**专门构造"捷径管用"和"捷径失效"两组样本**。4 个强模型在原 MNLI 上分数高，但在"捷径失效"的那半 HANS 上**分数极低**。这直接证明：**原始高分里有很大一部分是捷径**。

> **【直觉】用你 408 里的东西打比方——白盒测试的"边界用例"**：一个函数在正常输入上全对，不代表对；得专挑**边界/异常输入**去戳。诊断集就是给模型准备的边界用例。

### 3.3 抗饱和的两种 benchmark（【slides】p24–25）

| 类型 | 做法 |
|------|------|
| **对抗 benchmark** | 把模型放进构造回路（**model-in-the-loop**），专挑它做错的题（**ANLI**） |
| **动态 benchmark** | 持续从模型失败中生成新样本、定期换题 |

两者共同点：**用"模型当前会错"来喂题**，所以**天然抗污染、抗饱和**——这正是对 Goodhart 的工程回应（`01` §5）。

## §4 LLM-as-judge：让另一个模型当裁判

开放生成（翻译/摘要/对话）没有唯一答案，BLEU/ROUGE 又太死（§2.1）。**judge** 就是出路：**用另一个（往往更强的）LLM 来打分或两两选优。**

### 4.1 为什么流行（【slides】p63）

- 比人类评测**便宜得多**；
- LLM **往往比人更会听指令**（格式、rubric 遵守更好）；
- 可以规模化、自动化。

### 4.2 它的偏置（【slides】p63，本课重点）

| 偏置 | 表现 | `03` §3 的模拟 |
|------|------|---------------|
| **位置/顺序偏置** | 换一下 A、B 的左右位置，结论可能翻转 | 假 judge 只看槽位：30 对同样内容，**槽位1 胜率 1.00，交换后 0.00** |
| **verbosity（啰嗦）偏置** | 更长的回答更容易被偏爱 | 加 15 个废话词、内容不变：**冗长版胜率 1.00** |
| **自我偏好 / 裙带偏置** | 偏爱自己或同门模型产出的风格 | 本课未实测（【待核验】） |
| **格式偏好** | 偏爱带 markdown/分点的排版 | 本课未实测（【待核验】） |

此外 slides 还点了一条**能力边界**：judge **擅长"氛围检查"、弱于细逻辑**；而且**强模型当 judge 也贵**（p63）。

### 4.3 做对 judge 的办法（【slides】p64）

- **清晰指令 + 示例 + rubric**（评分标准写明白）；
- **让多个 judge 讨论**（ChatEval 2023、CollabEval 2025）；
- **"LLM 陪审团"（jury）**：用**多样化评委面板**压偏置，聚合分更稳，还能用小模型省成本。

## §5 人类评测：终极理想，但不是免检

【slides】p54–55 的口径：**所有自动指标都不够**，**人类评测长期被视为终极理想**；每当提出一个新自动指标，**必须证明它和人类评测高度相关**。但人也有硬伤：

| 问题 | 含义 |
|------|------|
| 成本高、不可扩展 | 需要大量标注人力 |
| 主观性 / 评分者间一致性 | 不同人打分不一致 |
| 可复现性 | **不同方式做的研究之间分数不可比**（slides 特别强调） |
| 判断偏置 | **可信度陷阱 / 流畅陷阱 / 长度陷阱** |
| —— | slides 还有一句反直觉的话："**LLM 之间的一致性比人之间更高**" |

**做对人的评测**（p55）：**明确定义 rubric**（正确性、流畅度、原创性…）→ **多人过大量例子、讨论校准** → **算 inter-rater agreement（评分者一致度）**。

**Chatbot Arena**（p56–61）是真人偏好的大规模平台：优点是**比别的评测更"in the wild"**；缺点是会混进大量怪异/越狱查询（p60 有真实例子）、成本高、只测有名模型、**外部效度**存疑（随便的用户随机提问未必代表真实使用，p61）。

## §6 四个"后评测"问题：污染、饱和、红队、可复现

### 6.1 数据污染（【slides】p71–73）

**机制**：测试集样本躺在训练语料里（互联网数据、合成数据都会）。**为什么合成数据也会污染**？因为合成数据可能**由模型基于同一批资料生成**，把测试信息带了进去。
**检测**：训练语料 vs 测试样本的 **n-gram 重叠（8–13 gram）**，辅以嵌入/改写式近重复检测。
**`03` §4 会实测**：逐字泄露 → 8-gram 精确抓出（precision=recall=1.00）；但**只改 7 处措辞**，重合数就从 15 掉到 0（**漏报**）。

### 6.2 benchmark 饱和与出路（【slides】p12–13、p77）

当一个 benchmark 被"打满"（GPQA：一年从"太难"到 O1 78.3%），它**失去区分度**。出路：**造更难的**（HLE）、**造对抗/动态的**（§3.3）、**换维度**（行为、安全、诚实）。slides p77 的元判断很直白：**"评测的科学落后于工程的进展"**。

### 6.3 红队 red teaming（【slides】p28 + A4 handout）

**定义**（A4 handout 原文口径）：研究者**故意当攻击者**，去找漏洞、绕过安全措施、让系统产生非预期行为。LLM 场景里，典型目标是**让模型违反它的 system prompt**——A4 就是让 G/H/I 三个模型**吐出本该保密的密码**（H 比 G 难、I 比 H 难；还能在给"假密码"的情况下**骗你**）。

评测里，红队属于**安全评测**那一支：不问"答得准不准"，问"**能不能被弄坏**"。

### 6.4 可复现性与统计显著性

- **可复现性**（【slides】p76）：prompt、few-shot 数、CoT、甚至空格、答案抽取脚本都影响分数 → **必须把这些连同分数一起报**。
- **统计显著性**：30 道题上两个模型 15:15，**不能说 A 和 B 一样、更不能说谁更好**——这只是**抽样噪声**。差异要超出**置信区间**才算数（`04` §6 给量级直觉）。
- **自洽性**（【slides】p75）：**生成器-校验器间隙**——"7+8"答 15，但"7+8=15, True or False"答 False；**GPT-4 也只有 76% 自洽**。这提醒：**答对 ≠ 真懂**。

## §7 一张图收尾

```
评测要回答"模型到底好不好"
        │
        ├── 用什么题？  benchmark（§1）——选择题/短答/句子/长答，判分难度递增
        │        └─ 好 benchmark 四条：scale·difficulty·quality·no spurious bias（§3）
        │
        ├── 怎么打分？  指标家族（§2）
        │        ├─ model-free（BLEU/ROUGE）vs model-based（BERTScore）
        │        ├─ reference-based vs reference-free
        │        ├─ 信息论（熵=多样性 / KL=分布距离）
        │        └─ 任务对应：accuracy / EM / F1 / pass@k / win-rate
        │
        ├── 谁当裁判？  judge（§4）或人类（§5）
        │        └─ judge 有偏：位置·长度·自我偏好·格式
        │
        └── 分数能信吗？ 后评测四问（§6）
                 ├─ 污染（n-gram 检测，会漏）
                 ├─ 饱和（造更难/对抗/动态）
                 ├─ 红队（安全评测）
                 └─ 可复现 & 统计显著性
        ↑ 全部被 Goodhart 定律统摄（`01` §5）
```
