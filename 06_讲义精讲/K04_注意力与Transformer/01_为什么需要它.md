# K04 · 01 为什么需要它

> **进这一篇之前你能说出什么**：K03 的一整套——语言模型是"预测下一词"、RNN 用"同一组权重反复用"处理任意长度输入、隐藏状态逐时刻更新、BPTT 沿时间反传、梯度连乘导致消失/爆炸、梯度剪裁治爆炸不治消失、seq2seq 把整句压成一个编码。
> **这一篇回答什么**：seq2seq 那条"整句压成一个向量"的路到底死在哪？RNN 的"串行"和"记不住远处"为什么是同一个病根的两面？以及——**能不能让每一步直接回看源句的每个位置，而不是靠一个压缩后的向量**？
> **读完你应该能说出什么**：
> 1. bottleneck 死在"**定长向量装不下变长信息**"，且这个损失**发生在生成之前**、无法补救
> 2. 串行与长程衰减是**同一件事的两面**：都来自"信息必须沿着链子一步步传"
> 3. 出路是给"任意两个位置"修一条**直连**——这正是本课要展开的东西

**这一篇不引入本知识点的新术语**（"注意力""query/key/value""self-attention""位置编码""Transformer"都留到 `02`），也不写代码、不推公式。打比方只用你 408 和 K01–K03 里已经有的东西。

## §1 回顾：K03 结尾那台翻译机

K03 结束在 seq2seq。它的形状你现在应该能默画：

```
源句 x = [il, m', a, entarté]
        │
   ┌────▼─────┐
   │ Encoder  │  逐词读入，最后留下一个隐藏状态 h_n
   └────┬─────┘
        │  这一个向量（"编码"）
        ▼
   ┌──────────┐
   │ Decoder  │  以它为初始状态，逐词生成目标句
   └────┬─────┘
        │
目标句 y = [he, hit, me, with, a, pie]
```

【slides】p16 的原话：Encoder RNN **produces an encoding of the source sentence**，这个编码**provides initial hidden state for Decoder RNN**；Decoder 是一个**条件语言模型**（p18），一步步算 $P(y^{(t)}\mid y^{(1)},\dots,y^{(t-1)},x)$。

两个语言之间不是一一对应的：法语四个词 "il m'a entarté" 对应英语六七个词。**词数不一样、语序不一样、有些词必须拆、有些必须合。** 这台机器现在要做的，是把左边整句的**全部信息**先塞进一个向量，再靠它写出右边。

【slides】p20 在结构图上直接贴了一个标签：**"Conditioning = Bottleneck"**；p21 紧接着发问：**"Problems with this architecture?"** —— 这一篇就是回答这个问号。

## §2 死法①：一个定长向量，装不下变长句子

先把问题说清楚，不要停在"瓶颈"这个隐喻上。

RNN 的隐藏状态 $h\in\mathbb{R}^{d}$（比如 $d=512$）。**它的维度是固定的**，不随句子长度变。而源句长度可以从 3 个词到 100 个词。

于是：

| 源句长度 | 要装进那个向量的信息量 | 结果 |
|---------|----------------------|------|
| 3 个词 | 少 | 够用 |
| 50 个词 | 多 | 挤，细节被抹平 |
| 100 个词 | 更多 | **装不下** |

> **【直觉】用你 408 里的东西打比方**：这就像把一张大图**缩成一张固定尺寸的缩略图**，或者把一个长文件**算成一个定长哈希**。
> - 缩略图能保留"大概长什么样"，但**细小的字全糊了**；哈希只能**判等**，判不了"哪里像"。
> - 更致命的是：**压缩是有损的，而且损失发生在解码之前**。解码器拿到这个向量时，源句的细节**已经没了**——它再怎么努力也变不回来（这正对应 K02 §2 里"信息被压扁那一步就丢了，回头改不了"）。

【slides】p37 用一句话点破：attention 让 decoder **"look directly at source; bypass bottleneck"**——**直接看源头，绕过这个瓶颈**。

## §3 死法②和③：串行与"记不住远处"，其实是一个病根

K03 已经讲透了两件事，这里只把它们接到一起。

### 3.1 串行：每一步都必须等上一步

RNN 的 $h^{(t)}$ 依赖 $h^{(t-1)}$。这意味着**第 100 步必须先算完第 99 步**——一条**长长的依赖链**。

> **【直觉】你 408 里的流水线**：指令之间如果有**数据相关（data hazard）**，后一条必须等前一条写回，流水线就**卡住（stall）**。
> 这里的"数据相关"比流水线更糟——它**贯穿整个序列**：第 100 个位置要用的信息，可能是第 1 个位置生产的，中间必须**顺序走过 99 步**。**GPU 再宽也并行不了。**

对比一下 K02/K03 见过的：**同一层里的不同位置本来是可以并行算的**（矩阵乘法一次算一大片）。RNN 把这个并行性**用"每步依赖上一步"亲手毁掉了**。

### 3.2 长程衰减：信息必须一步步"传递"，传得越远越淡

【slides】p9–p10 讲梯度：远端梯度信号**被近端淹没**，权重**只按近端效应更新，学不到长期效应**；例子是要学 "tickets"（第 7 步）和句末目标词的依赖，梯度小就学不到。

但请注意：**这不只是梯度的问题，是"信息通道"的问题。** 就算不考虑梯度，第 1 个位置的信息要影响第 100 个位置，也只能**一路被重写 99 次**。

【slides】p13 说得很直接：

> **"In a vanilla RNN, the hidden state is constantly being rewritten"** —— 隐藏状态**不断被重写**。

### 3.3 两条死法是一个病根

把 §3.1 和 §3.2 摆在一起：

| 死法 | 表现 | 共同病根 |
|------|------|---------|
| 串行 | 不能并行、训练慢 | **信息必须沿链子一步一步传** |
| 长程衰减 | 远处信息淡、学不到长依赖 | 同上 |

**所以真正的出路不是"把 RNN 调好一点"，而是换一条信息通路：让任意两个位置之间有一条直连。**

如果能做到——第 100 个位置要看第 1 个位置，就**直接去看**，不经过中间 98 次重写——那么：
- **串行没了**：所有位置可以**同时**去"看"彼此（一次矩阵乘法）；
- **长程衰减没了**：远距离也是**一跳**，和近距离一样短。

【slides】p13 正是这么并列的：治消失的方向除了 LSTM（独立记忆），还有一条是造 **"more direct and linear pass-through connections"**，并点名 **"Attention, residual connections, etc."**。

> **术语预告**：那个"直连"就叫**注意力**。名字不重要，先记住它的实质：**每一步都能直接回看源句/前文的每个位置，而不是靠一个被反复重写的中间状态。** `02` 会把它写成三步可算的操作。

## §4 出路长什么样：从"查表"想起

先不引入术语，用你熟悉的东西逼近它。

### 4.1 精确查表：你已经会的

**哈希表 / 数组索引**：给一个 key，**精确命中**某个槽位，取回它的 value。

```
   query "user_42"  ──命中──▶  表[42]  ──▶  value
```

【slides】p24 把它当起点：lookup table 里，一个 query **matches one of the keys**，返回它的 value。

问题：语言里没有这么干净的"精确命中"。翻译 "entarté" 时，你要看的不是"某一个词"，而是**同时**看几个词、并且**按相关程度分配注意力**。

### 4.2 软查表：query 和**所有** key 都匹配一点

【slides】p24 的下一步：

> **"In attention, the query matches all keys softly, to a weight between 0 and 1. The keys' values are multiplied by the weights and summed."**

也就是说：

- **不再二选一**，而是给每个 key 一个 $0\sim1$ 的**相关度权重**；
- 所有 value 按这些权重**加权求和**，得到输出；
- 权重加起来是 1（p29：**"Take softmax to turn the scores into a probability distribution"**）。

> **【直觉】用你 408 里的东西打比方**：
> - **精确查表** = 哈希，**要么命中要么不命中**；
> - **软查表** = 带权重的**模糊检索/相关性排序**，每个候选都返回一点，按相关度加权。
>
> 还有一层关键差别，【slides】p24 特意加了句：**"this is very powerful if the weights are learned"**——这些权重**不是人定的规则**，是模型自己学出来的。所以模型能学到"翻这个词时该看哪几个源词"，**对齐是白送的**（p37：**"We get (soft) alignment for free!"**）。

### 4.3 那"每一步都回看一遍"要花多少

回到 §3 的出路：解码器每生成一个词，都**直连**回源头看一遍。

这里已经能嗅到代价了：如果源句有 $n$ 个词、目标句有 $m$ 个词，那么"每个目标位置都要和每个源位置配一次对"——**配对次数是 $n\times m$ 量级**。

【slides】p37 把它写成唯一的缺点：

> **"(One issue – attention has quadratic cost with respect to sequence length)"**

**这就是本课要付的新代价**：RNN 是"沿链子走 $n$ 步"（$O(n)$ 串行），而这条路是"所有 pair 都配一遍"（$O(n^2)$）。`04` §6 会把这个数算清楚，并说明**为什么工程上还是选它**。

## §5 没有它会怎样

把这一课要解决的问题摆齐：

| 如果没有…… | 后果 |
|---|---|
| **直连（注意力）** | seq2seq 只能靠一个定长编码向量（§2），长句细节丢失；解码器无法在需要时回看某个源词 |
| **并行化** | 训练速度被"每步等上一步"卡死（§3.1）；序列越长越慢，无法用 GPU 摊平 |
| **到远端的短路** | 长距离依赖只能靠一路重写传递（§3.2），学不到也记不住 |
| **位置信息（后面会看到）** | 一旦把"链子"拆成"任意两两直连"，**顺序就没了**——`02` §5 会看到这是个必须补的洞 |

**第三条和第四条是"交换"，不是"免费"**：拆掉 RNN 的链子，换来并行与长程，**同时丢掉链子天然携带的顺序**。所以本课的架构里必须**额外**把位置信息注入回去——这也是 `02` 要讲的第二个关键零件。
