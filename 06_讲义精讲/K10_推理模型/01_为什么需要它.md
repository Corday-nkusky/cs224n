# K10 · 01 为什么需要它

> **进这一篇之前你能说出什么**：K05 的预训练（模型会续写下一 token）、K06 的后训练（SFT/RLHF 让它"听话、像人偏好"）、以及最基础的"大模型就是一个逐 token 接话机"。
> **这一篇回答什么**：一个已经会续写、会听指令的模型，**为什么还是答不对一道难数学题**？以及"多试几次""多想一会儿"为什么可能有用、代价在哪。
> **读完你应该能说出什么**：
> 1. 直接生成死在**近视**：它每一步只看局部，没有"先算中间再得结论"的余地
> 2. 难题难在**要串很多步**；把长链**摊成一小步一小步**，每步都更简单
> 3. "多试几次再取多数"之所以有用，靠的是**错的答案各不相同、对的答案只有一种**
> 4. 这三件事都**不是免费**的——都是在推理期花钱买准确率，而且有边界

**这一篇不引入本知识点的新术语**（思维链、self-consistency、verifier、RLVR 都留到 `02`，这里只放"术语预告"），**也不写代码、不推公式**。打比方只用你 408 和 K01–K06 里已经有的东西。

## §1 一个具体例子：它到底错在哪

先别谈概念，看一道题。

> 一个数 $x$，先乘 31，再加 7，再乘 31，再加 4，再乘 31，再加 9……这样连着做 5 次，$x=100$ 时结果是多少？

一个"会接话"的模型，如果被要求**直接吐最终答案**，它要在一瞬间（一层网络的前向、少数几层计算）把"5 次乘加"全部算完、再吐出那个 9 位左右的数。

它经常错。而且**错得很像**：前面几步都像那么回事，最后一位或一半位数偏掉。

**为什么？** 回想 K05/K06 里你对这个模型的全部认识：它做的唯一一件事是"**给定上文，预测下一个 token**"。这个动作本身**没有草稿纸**——它不能"先写下 1553，再拿这个 1553 继续算"。中间结果**没有地方存**，只能在内部那几层网络里"憋"着。

> **【直觉】用 408 打比方：表达式求值。**
> 算 `((100*31+7)*31+4)*31+9` 时，你会**把中间结果压进栈/寄存器**，一步一步来。假设有人**不给你寄存器**、要求你"看一眼就报最终值"——你只能心算整条链，链越长越容易错。
> **直接答 = 没有寄存器的心算；分步答 = 把中间结果写出来。**

这不是"模型笨"，是**计算结构**的问题：它被要求用**固定的一小段计算**，去完成**一串任意长的计算**。链一长，错误概率就指数级地涨。

这就是这一整课要解决的东西。所以先看清楚**"直接生成"这套现成工具**为什么不够。

## §2 现成的三种"直接生成"，各死在哪

K05 讲过：模型输出的是一个**概率分布**，你要用一个**解码算法**从里面挑 token。挑法有三种，各自有毛病。

### 2.1 每次都挑最大的（贪心）

**每步都取当前概率最大的 token**，一路走到底。

毛病一句话：**近视**。它在第 1 步挑了"当下最顺"的词，但可能把后面一条**整体更对**的路给堵死了。

> **【直觉】408 里的贪心 vs 动态规划。**
> 贪心算法每一步取局部最优，**不保证全局最优**；要找全局最优得用 DP/搜索，把"多条路的代价"一起考虑。逐 token 贪心就是"没有任何回溯、没有任何全局视野"的贪心。
> 后果：它是**可复现**的（同样输入永远同样输出），所以适合有唯一答案的题；但它**永远到不了**那条"先走一步不那么顺、后面才豁然开朗"的路。

### 2.2 保留几条并行路（beam search）

不取一条，而是每步保留 **top-k 条部分序列**，最后挑整体概率最高的一条。k=1 时它就退化成贪心。

毛病两条：

- **它仍在追"整体概率最高"，而"概率最高"不等于"答案正确"**——笔记里最顺的那句话，往往就是最常见的、人云亦云的话。
- **它越来越贵，却越来越不常用**。slides 直接写：beam search 曾是经典 NLP 的默认解码，**现代 LLM 里已不常用了**。

> **【slides】part1 p7** 的原话汇总：k=1 退化为 greedy；"Beam search was the defacto standard decoding algorithm for the classical NLP models, but it is no longer used often in modern day language models."

### 2.3 按概率随机抽（采样）

不挑最大的，而是**按概率掷骰子**。这样能跳出"最常见的那句话"，输出更丰富。

毛病：**它会把乱七八糟的尾巴也抽出来**。分布的长尾里有大量"概率很小但总和很大"的烂选项——序列一长，抽到烂选项几乎是必然。

> **【slides】part1 p15** 给了个能记住的数字：连续生成 30 个 token，**"每一步都只从累计概率前 95% 的区域里抽"的概率，低到只有 21%**。
> 所以有了各种"砍尾巴"的采样法（下一课 `02` 讲），但**它们治的是"别乱说话"，治不了"算不对"**。

### 2.4 更麻烦的：最"顺"的答案是**重复**

slides 花了整整一节讲这件事（【slides】part1 p9–11）：**最可能的序列会惊人地重复**。原文例子是模型反复吐 `I don't know.` —— 而且"**越重复，它越可能继续重复**"（重复的内容本身推高了重复的概率）。

更关键的是：**这在今天的推理模型里没有消失**。slides 说，AIME 上把"某个 30-gram 重复超过 20 次"标为 **looping**；而它更容易发生在三个条件下：**温度越低、模型越小、题目越难**。

> 记住这三个条件——它是本课"代价"那一节（`02` §8、`03` §5）的伏笔：**难题 + 小模型 + 想稳（低温度）**，恰好是"想稳却陷入循环"的组合。

## §3 关键一转：不是所有 token 都一样难

到这里，"直接生成"的三条路都撞墙了。出路不是换个更好的挑法，而是**换一种"写答案的方式"**。

先看一个你已经会的事实：**一个长计算，拆成很多短计算之后，每一步都更容易做对。**

再说一个 408 里天天见的结构：

> **【直觉】编译器的中间表示 / 流水线的分级。**
> 一个复杂的复合运算，编译器会拆成**一长串只做一件事的指令**（IR）；CPU 流水线把它切成**每级只做一点点**的阶段。**每一小级的正确率，远高于"一次憋完整条链"的正确率。**
> 代价是多花了步骤（时间），换来的是每步的可靠性。

把这事搬到模型上，就是这一课的核心动作：**让模型不要直接吐答案，而是先把中间结果"写进上文"**——写下来的每一步都成了它下一步的输入，于是**它有了草稿纸（寄存器）**。

> **术语预告**：把"一步一步的中间推理"写出来，这套做法叫 **Chain-of-Thought（思维链，CoT）**。`02` §1 正式讲。

**这一转为什么关键**：它同时解决了 §2 的两个毛病——

| §2 的毛病 | CoT 怎么破 |
|-----------|-----------|
| 没地方存中间结果（憋不住长链） | 中间结果**写进上文**，下一步直接读 |
| 一步错就全错（无法回头） | 步骤变短、每步更易对；且能看到自己写了什么，**有机会自查、回头** |

## §4 第二转：既然会错，就**多试几次**

分步之后，单次仍会因为某一步走了岔路而错。**但换个角度**：

一次做不对，**做很多次**、然后把答案**投票**呢？

> **【直觉】冗余 + 多数表决。** 你 408 里见过"三模冗余"这类思路：三条独立通道同时算，**取多数**，单条出错就被投掉。前提是**各条的错法是独立的**。
> 换到模型上：同一道题**独立采样**很多条推理链，把**最终答案**拿出来投票。

它为什么可能有用？靠两个条件：

1. **对的答案只有一种**——所有"走对了"的链，最后都会落到同一个数上，票会**堆在一起**。
2. **错的答案各不相同**——走岔的链，会各自落到不同的错答案上，票**分散**，很难凑出多数。

于是"正确"这个选项天然是**得票最高的那个**，k 越大越明显。

> **术语预告**：多次采样 + 多数投票，叫 **self-consistency（自洽性）**。`02` §2 讲。

**这条也有边界**：如果错的链**错得很一致**（都掉进同一个坑），票会堆到那个错答案上，投票就救不了——这一点 `03` §4 会用实测数字说明。

## §5 第三转：与其"多试"，不如"多想"——以及"请一个裁判"

再往前一步：既然"推理链本身可以更长"，那能不能让模型**在难题上自动想得更久**（写更多中间步骤）？而"多试几次"里，能不能**不靠投票、而是请一个裁判直接挑出最好的那个**？

这两件事分别是 **test-time compute 缩放**（多花推理算力换准确率）和 **verifier / reward model**（学会判对错、用来挑解）。都在 `02` §3–§4。

本课真正的落点，是**最后一转**：与其在推理期"打补丁"（多采样、多搜索），不如**把这套"会想"直接训进模型**——用"答案对不对"当奖励做强化学习。这就是 slides 花 25 分钟讲的 **RLVR / GRPO / DAPO**（`02` §5、`04` §4）。

## §6 没有它 / 用错的代价

这一篇讲了"为什么要多想、多试、多挑"，但**必须把代价一起摆上来**，否则学到的是半截：

| 代价 | 具体是什么 |
|------|-----------|
| **慢** | 分步要生成更多 token；多采样 = 多跑好几遍。**这是推理期实打实的时间与电费。** |
| **贵** | 采样 N 条 = N 倍生成成本；训练时还要额外的裁判模型（verifier）成本。 |
| **会"假装推理"** | 输出的推理链**看起来对，其实错**；更糟的是**用了某个提示却不写出来**（slides 的 CoT 忠实度结论）。 |
| **长度不是准度** | "想得越久越好"是**有条件的**——错误往往**更长**（胡言乱语、反复、钻牛角尖）。用"挑最长"当规则会把准确率做**低**。`03` §5 有实测。 |
| **只对可验证的题有效** | 纯靠"答案对不对"的 RL，**只在答案能被程序判对错的题上（数学、代码）有效**；开放写作、闲聊它管不了，**也不会顺便发现安全护栏**。 |

> **【slides】part1 p28** 把后面两条说得很直：R1-Zero 涌现出的不良特征是"可读性差、语言乱切、**范围窄**——纯 RL 只在可验证任务上有效，解数学/代码不会发现安全护栏"。
