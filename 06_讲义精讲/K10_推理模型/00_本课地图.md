## §1 这一课要回答的问题

**主问题**：一个模型已经能"接话"（预训练，K05）也能"听话"（SFT/RLHF，K06）了，为什么**还是答不对难数学题**？——以及，"让它多想一会儿 / 多试几次"到底买到了什么，代价是什么，怎么把"会想"这件事**训进模型**？

**拆成十个必须回答的子问题**：

| # | 子问题 | 在哪答的 |
|---|-------|---------|
| 1 | 直接用 greedy / beam / 采样生成，为什么会答错？三种解码各死在什么地方？ | `01` §2、`02` §1 |
| 2 | **Chain-of-Thought（思维链）**是什么？它凭什么把准确率抬起来？ | `01` §3、`02` §2、`04` §2 |
| 3 | **self-consistency**（多次采样 + 多数投票）为什么有效？收益曲线长什么样？ | `02` §3、`04` §3、`03` §3 |
| 4 | **test-time compute 缩放**：采样预算 / 思考长度增加，准确率如何变？有没有上限？ | `02` §4、`03` §4、`04` §3 |
| 5 | **verifier**（ORM / PRM）与搜索，比"投票"强在哪、弱在哪？ | `02` §4、`04` §5 |
| 6 | 用 RL 训练推理：**RLVR**（可验证奖励）、**GRPO** / DAPO 的目标是什么？ | `02` §5、`04` §4 |
| 7 | **过程奖励模型 vs 结果奖励模型**怎么取舍？DeepSeek 为什么**不用 PRM**？ | `04` §5、`01` §4 |
| 8 | **长度 / 难度权衡**是怎么来的？模型什么时候"该多想"？ | `04` §6、`02` §6 |
| 9 | 代价：慢、贵、会"**假装推理**"（reward hacking / CoT 不忠实）具体怎么发生？ | `04` §6、`03` §5 |
| 10 | **蒸馏长 CoT 到小模型**为什么比直接给小模型上 RL 划算？隐式推理（latent reasoning）是什么？ | `04` §7、`02` §6 |

**第 6、7 个问题不是凑数** —— 它们是 L12 花掉整整 25 分钟（PPO → GRPO → DAPO）的部分，也是"推理模型"与 K06 后训练（RLHF/DPO）在**目标函数层面**的真正分岔：K06 优化的是"像不像人偏好"，K10 优化的是"答案对不对"。

## §3 知识清单

每条一句话结论 + 出处。**扫一遍，看有没有哪条你讲不出来。**

### A. 解码：从 greedy 到采样（7 条）

1. 【slides】part1 p5：**greedy decoding 近视**——每步取局部最大概率，可能错过全局最优序列；**beam search** 每步保留 top-k 个部分序列（k = beam width）。
2. 【slides】part1 p7：**k=1 时 beam search 退化成 greedy**；beam search 曾是经典 NLP 的默认解码，但现代 LLM 里**不再常用**（表：搜索空间 1 条路径 / 复杂度 / 局部最优 vs 更好近似全局最优 / 多样性）。
3. 【slides】part1 p9–10：**最可能的序列会（惊人地）重复**（Holtzman et al. 2019）——"I don't know." 反复；"the more repeat, the more likely it becomes"。
4. 【slides】part1 p11：**looping 在推理 LLM 里不是边角情况**——AIME 上把"30-gram 重复 > 20 次"标为 looping；更易发生的条件：**低温度 → 更 loopy、小模型 → 更 loopy、更难的题 → 更 loopy**。
5. 【slides】part1 p15–17：**top-k 采样**（Fan et al. 2018，只从概率最高的 k 个里采）与 **top-p / nucleus 采样**（Holtzman et al. 2019，从累计概率达 p 的集合里采）；top-k 对"平分布"砍太快、对"尖分布"砍太慢。
6. 【slides】part1 p18–19：**temperature 是解码超参，不是一种算法**——beam search 和采样都能用（调 logits 的锐度）。
7. 【slides】part1 p20：**何时 greedy、何时采样**（有唯一正确答案/要可复现/受限输出 → greedy；开放创作/长 CoT/求多样 → sampling）；**Best-of-N sampling** 是新兴趋势：采 N 个、用 reward model 选最好的，是一类 rejection sampling，能让小模型媲美大模型，**对推理任务尤其有效**。

### B. DeepSeek R1：从 R1-Zero 到 R1 到蒸馏（9 条）

8. 【slides】part1 p26：**R1-Zero 的奖励只两样**——**准确率奖励**（数学比末答案、代码跑测试，基本是二值的对/错）+ **格式奖励**（把推理放进 ` thinking…`、答案放后面给个小奖励）；**明确不用 PRM**（DeepSeek 认为 PRM 贵、易被 reward hacking、会限制模型发现新推理策略，结果奖励给最大自由）。后续 R1 才加了语言一致性、安全等复合奖励。
9. 【slides】part1 p27：**涌现出的推理行为**——**self-verification**（导出答案后自查）、**reflection and backtracking**（"Wait, let me reconsider"）、**extended deliberation**（响应长度从数百涨到数千 token，模型"学到想得久→答得好"，是**学到的 test-time compute scaling**）。
10. 【slides】part1 p28：**R1-Zero 涌现的不良特征**——可读性差、**code switching**（同一响应里在语言间乱跳）、**范围窄**（纯 RL 只在可验证任务上有效；靠解数学/代码**不会**发现安全护栏）。
11. 【slides】part1 p30：**Finding 1：RL 本身就能诱导推理**（此前以为 CoT 需要监督样本）；R1-Zero 证明纯结果奖励、无过程监督也能诱导复杂推理。**保留意见**：最终 R1 仍走 SFT→RL 流水线；**不适用小模型**。
12. 【slides】part1 p31：**Finding 2：结果奖励能催生"发现"**——PRM 可能因惩罚"非常规但有效"的路径而**抑制探索**；教训："sometimes less supervision yields more capability"。**保留**：RLVR 不适用所有推理问题。
13. 【slides】part1 p32：**Finding 3：RL 与 SFT 协同**——纯 RL 与纯 SFT 都不是最好；**RL 发现能力、SFT 提供可靠性**；cold-start 数据防 RL 早期不稳，rejection sampling 把 RL 的发现转成可复用训练数据。
14. 【slides】part1 p33：**Finding 4：蒸馏 > 对小模型直接 RL**（算力有限时，从大推理模型蒸馏比给小模型上 RL 好）；能力可下传到 **1.5B**。**Finding 5：开源推理模型可行**——R1 系列 MIT 许可，蒸馏的 7B/14B 在推理基准上超过许多更大的闭源模型。
15. 【slides】part1 p34：**Finding 6：推理可以纯自回归**——此前以为需要 MCTS 之类推理期搜索，实际**不需要特殊搜索算法**；但后面对硬数学的模型会引入结构（非传统 MCTS 意义）。
16. 【slides】part1 p35：**Finding 7：test-time compute 是可学习资源**——R1 学会给**更难的题分配更多思考 token**；这不是 beam search / 多数投票那种"推理期 trick"，而是**被训练内化**进模型。**保留**：只在一定程度上成立。

### C. RL 算法：PPO → GRPO → DAPO（8 条）

17. 【slides】part1 p38：**PPO 回顾**——含 entropy loss、value network loss（为优化 CLIP surrogate，value network 停梯度）；**式中的 `r` 是重要性采样的 ratio，不是 reward**。
18. 【slides】part1 p39：**PPO 复杂度之一：内存里要装 4 个模型**（policy、略旧的 policy、参考 policy、value network、reward model）——实践中常是 **5 个**，因为 evolving policy 有两份（RL 基础设施/GPU 优化带来 off-policy drift）。
19. 【slides】part1 p40–41：**GAE** 要在**每个 token 位置**调一次 value function；一批 512 prompts × 16 responses × 平均 2000 token ⇒ **每步约 1600 万次 value forward**。
20. 【slides】part1 p42：**value network 与 policy 联合训练**，其 loss 是"预测 value 与实际 return"的平方误差；有独立学习率与调参；**理论上**帮 credit assignment（把最终标量奖励沿时间回传），**实践上**不确定它学到的是不是有用信号。
21. 【slides】part1 p43：**PPO 完整一步 = 7 小步**（生成 rollout → 算奖励 → 用 KL 惩罚构造 per-token 奖励 → per-token value 估计 → 算 advantage → 更新 policy → 更新 value）。
22. 【slides】part1 p44–46：**GRPO 目标**——给定 prompt 采**一组 G 个响应**，用 token 级重要性采样比，**advantage 直接是"组内奖励的 z-score"**（减去组均值、除以组标准差）；PPO 把 KL 藏在奖励里、再藏进 advantage，GRPO 把 KL **直接放进学习目标**。对比表：**内存模型数**（5 → 3）、**advantage**（GAE 每 token → 组奖励 z-score）、**token credit**（per-token TD → 全 token 均匀）、**训练对象**（policy+value → 只有 policy）、**KL 位置**。（Shao et al. 2024, DeepSeekMath）
23. 【slides】part1 p47：**DAPO 技巧 1 · clip-higher**——标准 PPO/GRPO 对称裁剪，上界限制探索、导致 entropy collapse；DAPO 解耦上下界，例如把 ratio 裁到 **[0.8, 1.28]** 而非 [0.8, 1.2]。
24. 【slides】part1 p48：**DAPO 技巧 2 · dynamic sampling**——一组响应**全对或全错时组标准差为 0，形成梯度死区**、并缩小有效 batch；DAPO 只保留**至少有一个对、一个错**的组参与训练。
25. 【slides】part1 p49：**DAPO 技巧 3 · token-level loss**——GRPO 是**样本级**平均（先在一段响应内平均 token、再在 G 个响应间平均）；后果：**对长 CoT 不公平**，100-token 响应里单个 token 的梯度贡献是 1000-token 响应的 **10 倍**；DAPO 改成 **token 级**平均（每个 token 权重相同）。

### D. 推理的本质：什么有效（6 条）

26. 【slides】part1 p51：**CoT prompting 大幅提升推理**（Wei et al. 2022）；但它是**规模的涌现性质**——好处只在**足够大的模型（100B+）**上出现；**小模型常产出不合逻辑的思维链，并不提升准确率**。
27. 【slides】part1 p52：**self-consistency（= N 个样本多数投票）进一步提升**——GSM8K **+17.9%**、SVAMP **+11.0%**、AQuA **+12.2%**、StrategyQA **+6.4%**（Wang et al. 2022）；有效原因是**贪心解码到不了的、位于高概率区的多样推理路径**；**N 越大提升越大** → test-time scaling 的味道。
28. 【slides】part1 p53/p56：**CoT-decoding**（Wang & Zhou 2024）——第一个 token 用 top-k 全分支、之后 greedy；这些"另类路径"**常包含 CoT，哪怕完全没做 CoT 提示**；含义：**推理路径本就存在于预训练 LLM 中，只是被标准 greedy 遮蔽**。
29. 【slides】part1 p57：**整条解码路径的对数概率并不比 greedy 更可靠**；若做**长度归一化**，有时才有帮助。
30. 【slides】part1 p58–59：**"Let's think step by step"**（Kojima et al. 2023）——zero-shot CoT：只加一句触发语，不给人写好的示例。
31. 【slides】part1 p60–61：**"Why think step by step? Reasoning emerges from the locality of experience"**（Prystawski et al. 2023）——核心假设：**训练数据是"重叠的局部相关变量簇"**，逐步推理把这些局部关系串起来，才能到达"训练中从未一起出现过的变量"；**数学上证明"reasoning gap"存在**（局部样本训练的自回归模型，走中间变量比直接估计偏差更小）；中间步骤**只在数据局部结构化时**才有用；局部结构化数据 + 推理**远比"直接在全部变量上训练"省数据**。

### E. 为什么/何时失败（3 条）

32. 【slides】part1 p62–63：**"Four Habits of Highly Effective STaRs"**（Gandhi et al. 2025）——同款 RL 训练下 **Qwen-2.5-3B 远胜 Llama-3.2-3B**，差别在四种行为：**Verification（核对中间结果）、Backtracking（识别错误并回头换路）、Subgoal Setting（拆子问题）、Backward Chaining（从目标倒推）**；**行为比正确性更重要**——用"含正确推理模式但答案错误"的样例预热，也能达到与"正确解"训练相当的效果。
33. 【slides】part1 p64/p67：**"Reasoning Models Don't Always Say What They Think"**（Chen et al., Anthropic 2025）——**CoT 忠实度**：跨 6 种提示、多个 SOTA 模型，模型实际用了某个提示却**在 CoT 里说出来的比例 < 20%**；**RL 起初显著提升忠实度（63%、41%）但随后平台化（28% MMLU / 20% GPQA）**；**reward hacking 时**模型更多用提示、却不更多"说出来"——**靠监控 CoT 无法可靠检测模型的抄捷径**。
34. 【slides】part1 p68：**"Mind Your Step (by Step)"**（Liu et al. 2025）——在那些"**人越想反而越差**"的任务上，CoT 也会**降低**模型性能。

### F. test-time compute 缩放的机制（4 条）

35. 【slides】part2 p54–55：**test-time compute scaling** 由 OpenAI **O1（2024-09）**引爆；更早有 GDM 论文（2024-08）与 **"Let's verify step by step"（2023-05）**；核心提问："与其训更多，何不让模型**多想**？"
36. 【slides】part2 p56：**智能地扩展 test-time compute 可比单纯扩参数带来更大提升**；**固定推理预算下，小模型 + 聪明的 test-time 策略可胜过更大模型 + 标准解码**；compute-optimal 要在**模型大小（预训练 FLOPs）**与**样本数 / 修订步数（推理 FLOPs）**之间找平衡。
37. 【slides】part2 p57：**test-time 策略**——Best-of-N（采 N 个、用 verifier 选最好）、Weighted Best-of-N（从 compute-optimal 温度分布采样）、Sequential revisions（用自评反复改进单个解）、Beam search with PRMs（按 step-level 奖励剪枝）、Diverse beam search（鼓励不同解法）；**验证方法**——**ORM**（预测整解对错）、**PRM**（逐步评对错）、领域专用 verifier（如跑代码）。
38. 【slides】part2 p59：**关键结果**——MATH-500 上 **14B + 优化 test-time 追平/超过 4× 大的模型**；compute-optimal 大致把**等量 FLOPs 分给预训练与推理**；**Sequential revision 在需要精修/纠错的题上缩放特别好**；**PRM 比 ORM + beam search 省 4–8× 算力**。**takeaways**：别默认用最大模型、**投资验证**、高质量 PRM 能显著改善 test-time 缩放。

### G. 配套系统：投机解码、RL 基建、蒸馏、长上下文（4 条）

39. 【slides】part2 p4–p11：**speculative decoding**——用小 LM 起草、大 LM 验证；本质是 **rejection sampling**，采样过程**与直接从目标（大）LM 采同分布**（证明见 Chen et al. 2023 附录 I）；**60M T5-small 起草 + 11B T5-XXL 目标 ⇒ 2–3× 加速且输出一致**。
40. 【slides】part2 p21–p26：**online/offline RL**（能否与环境交互）与 **on-policy/off-policy RL**（rollout 是否来自最新策略）；**off-policy drift** 在实践中来自：故意的异步 RL、每批多步梯度、大 replay buffer、生成与训练分集群；危害：**梯度有偏、重要性权重爆炸、reward hacking 被放大**；缓解：PPO 裁剪、KL 惩罚、GRPO/REINFORCE 这类无 critic 算法、少 epoch、连续批处理 + 权重流式、Pipeline RL 的 in-flight 权重更新。
41. 【slides】part2 p28–p34：**on-policy distillation（GKD）**——此前蒸馏是 teacher-centric（对学习者是 off-policy），GKD 是 **student-centric**，用 **reverse KL**、**上下文来自学生自己的生成**，从而**消除 exposure bias**（学会从自己的错误里恢复）、并**mode-seeking**（在自己最好行为上更"尖"）；定位为 **SFT 与 RL 的最佳结合**（采样 on-policy、奖励 dense、GPU 需求轻）；域适配用例：先 70% mid-training 学新领域知识、再 30% on-policy 蒸馏恢复指令跟随。
42. 【slides】part2 p36–p52：**长上下文扩展**——挑战来自**数据（互联网文档不够长）、算力/内存（注意力 O(n²)）、位置编码泛化**；典型文档长度（Common Crawl 600–1200、维基 500–1500、arXiv 5k–10k+、书 50k–100k+、GitHub 100–5k）；**RoPE**（旋转 Q、K，不改 V；**相对距离**干净可得；可外推）；扩展实践：位置编码改动（**Position Interpolation、NTK-aware、YaRN**）、**渐进/分阶段训练**（8K→32K→64K→128K，只需原预训练 **0.1–1%** 的 token 预算）、数据工程、注意力结构改动（**GQA/MQA、FlashAttention、滑动窗口 + 全局 token**）。

## §5 术语索引

按首次出现的篇排。`01` 篇零前置，`02` 篇是本知识点核心概念，`04` 篇才需要推导背景。

| 术语 | 一句话解释 | 出处 |
|------|-----------|------|
| **greedy decoding** | 每步取概率最大的 token，近视 | `01` §2 |
| **beam search** | 每步保留 top-k 个部分序列，k=1 时退化成 greedy | `01` §2 |
| **top-k / top-p（nucleus）采样** | 只在概率最高的 k 个 / 累计概率达 p 的集合里采 | `02` §1 |
| **temperature** | 调分布锐度的解码超参（不是算法） | `02` §1 |
| **looping（循环退化）** | 生成陷入重复；低温度/小模型/难题更易发生 | `01` §2 |
| **Chain-of-Thought（CoT，思维链）** | 让模型先写中间步骤再给答案 | `02` §1 |
| **few-shot CoT / zero-shot CoT** | 给人写的示例 / 只加"let's think step by step" | `02` §1 |
| **self-consistency（自洽性）** | 采样多条 CoT，对最终答案多数投票 | `02` §2 |
| **test-time compute scaling** | 推理期多花算力（采样/思考长度）换准确率 | `02` §3 |
| **Best-of-N** | 采 N 个解，用 verifier/reward 选最好 | `02` §3 |
| **verifier（验证器）** | 挑答案对错的外部裁判 | `02` §4 |
| **ORM（结果奖励模型）** | 只预测整解对错 | `02` §4、`04` §5 |
| **PRM（过程奖励模型）** | 逐步评对错，给 step-level 奖励 | `02` §4、`04` §5 |
| **RLVR（可验证奖励的 RL）** | 用"答案可自动验证"的奖励做 RL | `02` §5、`04` §4 |
| **GRPO** | 组内相对 advantage 的 RL，不要 value network | `02` §5、`04` §4 |
| **GAE** | 广义优势估计，逐 token 调 value function | `04` §4 |
| **DAPO** | GRPO 的三处修补：clip-higher / dynamic sampling / token-level loss | `04` §4 |
| **过程奖励 vs 结果奖励** | 逐步给分 vs 只看末答案 | `04` §5 |
| **reward hacking（奖励攻击）** | 钻奖励的漏洞，分数高但没真做对 | `04` §6 |
| **CoT 忠实度（faithfulness）** | CoT 是否如实反映模型真正用的信息 | `03` §5、`04` §6 |
| **latent reasoning（隐式推理）** | 不在文本里显式写推理，在隐状态里算 | `02` §6 |
| **distillation（蒸馏）** | 用大模型的输出/分布训练小模型 | `02` §6、`04` §7 |
| **exposure bias** | 训练见"标准上文"、推理见"自己的上文"的错配 | `04` §7 |
| **on-policy distillation / GKD** | 用学生自己生成的上下文做蒸馏（reverse KL） | `04` §7 |
| **speculative decoding** | 小模型起草、大模型验证，加速且不改分布 | `02` §7 |
| **RoPE** | 用旋转编码位置，天然带相对距离 | `02` §7 |
| **Position Interpolation / NTK / YaRN** | 三类长上下文外推的位置编码改法 | `02` §7 |
| **RLVR 的可验证性** | 奖励能否被程序自动判定对错 | `02` §5 |
