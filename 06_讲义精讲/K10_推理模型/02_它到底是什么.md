# K10 · 02 它到底是什么

> **进这一篇之前你能说出什么**：① 直接生成死在"近视 + 没地方存中间结果"；② 难题难在要串很多步，摊成小步每步更简单；③ 多试几次取多数，靠"错的各不同、对的只有一种"；④ 这些都是花钱买准确率、有边界。
> **这一篇回答什么**：CoT、self-consistency、test-time scaling、verifier、RLVR/GRPO、蒸馏、隐式推理**各是什么**？它们之间怎么串起来？
> **读完你应该能说出什么**：
> 1. **CoT** = 把中间步骤写进上文；few-shot 是给人写示例，zero-shot 是只加"let's think step by step"
> 2. **self-consistency** = 采样多条 + 对答案多数投票；**test-time scaling** = 预算越大越准（但有上限）
> 3. **verifier** 分 **ORM**（整解对错）与 **PRM**（逐步对错）；挑解比投票强，但靠的是裁判质量
> 4. **RLVR** 用"答案可验证"的奖励做 RL，**GRPO** 用组内相对 advantage、省掉 value network

**这一篇几乎不推公式、不跑代码。** 会出现几条定义式（多数投票、$1-(1-p)^k$、GRPO 目标），但只是把话说成符号，**不往下推**——真正的推导都在 `04`。所有例子都小到能手算。
**这一篇的目的是让你在 `03` 里看见那些准确率曲线时，知道每条曲线是什么、该不该长那样。**

## §1 换一种写法：把中间步骤写出来（CoT）

### 1.1 直接答 vs 分步答

用 `01` §1 那道题，缩到能手算的规模：

> $x=3$，做 $x=x\times 2+1$ 两次，结果是？

| 方式 | 模型输出的样子 |
|------|---------------|
| **直接答** | `11` |
| **分步答** | `3×2+1=7`；`7×2+1=15`；所以答案是 `15` |

（上面两个数故意写成一个对一个错，就是为了让你盯着"直接答"那一步有多脆。）

**同一个模型，同一样的知识**，只是被要求把中间结果**写下来**。写下来的 $7$ 立刻变成了下一步的输入——**这就是 `01` §3 说的"草稿纸"**。

> **术语**：让模型在给出最终答案前**先生成一段中间推理**，这段推理叫 **Chain-of-Thought（思维链，CoT）**。注意 CoT **不要求中间步骤真的正确**——它只是"写出来"这个动作。

### 1.2 两种触发方式

| 方式 | 做法 | 出处 |
|------|------|------|
| **few-shot CoT** | 在提示里**给几个"带推理过程"的示例**，模型照着学 | Wei et al. 2022（【slides】part1 p51） |
| **zero-shot CoT** | 不给示例，**只在问题后加一句"Let's think step by step"** | Kojima et al. 2023（【slides】part1 p58–59） |

【slides】part1 p51 对 few-shot CoT 有个**必须打八折**的结论：**CoT 是"规模的涌现性质"**——好处**只在足够大的模型（100B+）上才出现**；**小模型常产出不合逻辑的思维链，还不提升准确率**。所以"加一句 think step by step"不是万能药。

### 1.3 一个反直觉的发现：想不想，其实"本来就会"

【slides】part1 p53/p56（Wang & Zhou 2024，**CoT-decoding**）说了一件挺震撼的事：**不做任何 CoT 提示**，只在**第一个 token** 处用 top-k 分叉、之后照常贪心——这些"另类路径"里**经常自己长出 CoT**。含义是：**推理路径本来就存在于预训练模型里，只是被标准贪心解码遮住了**。

不过也有反例（part1 p53 的小字）：**光靠 top-k / 温度采样**、完全不做提示，CoT 反而**不容易浮出来**——分叉的"姿势"很重要。且（part1 p57）**整条路径的对数概率并不比贪心可靠**，只有做**长度归一化**后才偶尔有帮助。

## §2 多试几次：self-consistency（自洽性）

分步之后仍会走岔。**多采几条，对最终答案投票**：

1. 同一题**独立采样** $k$ 条 CoT（互相不共享上下文）；
2. 从每条里**抽出最终答案**；
3. **多数投票**，得票最高的就是输出。

> **术语**：这套叫 **self-consistency**（Wang et al. 2022，【slides】part1 p52）。它**不改模型、不训练**，只在推理期多花钱。

【slides】part1 p52 给的增益数字（**直接抄 slides，本课未复核**）：GSM8K **+17.9%**、SVAMP **+11.0%**、AQuA **+12.2%**、StrategyQA **+6.4%**。slides 还点出两件事：

- 有用的原因是**那些贪心到不了的、位于高概率区的多样推理路径**；
- **N 越大提升越大** —— "test-time scaling 的味道"。

**它有边界**（`01` §4 埋的）：如果错的链**错得很一致**（都掉进同一个错答案），投票会把那个错答案选出来。`03` §3 的实测里，投票曲线是"快速上升然后**贴上一条上限**"——上限就是"k 条里至少有一条对"。

## §3 多花算力：test-time compute 缩放

把"多采样"这件事**当成一个可以调的旋钮**：

> **术语**：**test-time compute scaling（测试时算力缩放）**——在**推理期**多花算力（更多采样、更多思考 token、更多修订步），换更高准确率。它不是新算法，是一种"投资方向"的选择。

【slides】part2 p54–55：这个概念由 OpenAI **O1（2024-09）**引爆；更早有 GDM（2024-08）与 **"Let's verify step by step"（2023-05）**。

**它的核心主张**（part2 p56）：**智能地花推理算力，收益可能大于单纯把模型训得更大**；**固定推理预算下，小模型 + 聪明的 test-time 策略，可能胜过大模型 + 标准解码**；但要在**模型大小**与**采样数/修订步数**之间找 **compute-optimal 平衡点**。

### 3.1 三种花法，三条不同的曲线

同样是把预算 $k$ 增大，**怎么花**决定曲线长什么样（`03` §4 会分别实测）：

| 花法 | 一句话 | 需要什么 |
|------|--------|---------|
| **多数投票**（self-consistency） | 采 $k$ 条，投票 | **什么都不需要**，但天花板有限 |
| **Best-of-N + 完美 verifier** | 采 $k$ 条，**请裁判挑最好的那条** | 一个**永不犯错的裁判**（理想上限） |
| **Best-of-N + ORM** | 采 $k$ 条，**用结果奖励模型挑** | 一个**会犯错的裁判** |

> **【直觉】投票是"群众意见"，verifier 是"专家"。** 群众里只要对的比错的分散，多数就靠谱；专家如果判得准，直接从 $k$ 个里挑出那个对的，效果更好。**但专家会误判——`03` 会看到 ORM 曲线的天花板被自己的识别率卡住。**

## §4 请裁判：verifier / ORM / PRM

**verifier（验证器）** 就是那个"判对错、用来挑解"的东西。两类：

| 类型 | 评什么 | 一句话 | 出处 |
|------|--------|--------|------|
| **ORM（Outcome-supervised Reward Model，结果奖励模型）** | **整个解**的对错 | 看最终答案，猜这对不对 | part2 p57 |
| **PRM（Process-supervised Reward Model，过程奖励模型）** | **每一步**的对错 | 逐步给分 | part2 p57 |

【slides】part2 p57 列的 test-time 策略里，"**Beam search with PRMs**"就是：保留多条候选解，**按 step-level 奖励剪枝**。有 PRM 之后还能做**定向搜索**（在坏步骤处回头），而不只是"采完再挑"。

【slides】part2 p59 的关键结论里有一条**很实在**：**PRM 比 ORM + beam search 省 4–8× 算力**。另一条 takeaway 直接是口号：**"Invest in verification!"**——**高质量的裁判，尤其是 PRM，能显著改善 test-time 缩放**。

**但 PRM 不是免费的好东西**。DeepSeek 在 R1 里**明确不用 PRM**（【slides】part1 p26），理由是：**贵、容易被 reward hacking、还可能限制模型发现新推理策略**——结果奖励给的是"最大自由"。这个取舍是本课 `04` §5 的重点。

## §5 真正的落点：用 RL 把"会想"训进模型

前面都在**推理期打补丁**（多采样、多搜索）。slides 花最大篇幅讲的，是**训练期**：**用"答案对不对"当奖励，做强化学习**。

### 5.1 RLVR：奖励只问"答案对不对"

> **术语**：**RLVR（RL with Verifiable Rewards，可验证奖励的强化学习）**——奖励来自**能被程序自动判对错的检查**。数学：比末答案；代码：跑测试用例。**奖励基本是二值的**（对/错）。

【slides】part1 p26 给的 R1-Zero 配方就是极简两样：

| 奖励 | 内容 |
|------|------|
| **准确率奖励** | 答案对错（二值） |
| **格式奖励** | 把推理放进 ` thinking…`、答案放后面给**一点点**奖励 |

**没有什么"逐步打分"，没有忠实度奖励，没有"回答要多像人"**。DeepSeek 的赌注是：**只要奖励"最终对不对"，模型会自己长出会想的能力**。结果（part1 p27）它确实长出了三样：**self-verification（自查）、reflection/backtracking（回头换路）、extended deliberation（越难想越久）**。

> **一个关键区分**（part1 p35, Finding 7）：这些是**被训练内化**的能力，**不是** beam search / 多数投票那种"临时 trick"。模型**学会了给更难的题分配更多思考 token**。

### 5.2 为什么需要 GRPO：PPO 太贵

要在 RL 里更新策略，得知道"这个动作比平均水平好多少"——即 **advantage**。K06 讲的 **PPO** 用 **GAE** 逐 token 估 advantage，而 GAE 需要**一个额外的 value network**，还要**在每个 token 位置调一次**它。

【slides】part1 p41 给了个夸张的量级：一批 **512 prompts × 16 responses × 平均 2000 token ⇒ 每步约 1600 万次 value forward**。加上 policy、略旧 policy、参考 policy、value、reward，**内存里要装 4–5 个模型**（part1 p39）。

> **术语**：**GRPO（Group Relative Policy Optimization，群体相对策略优化）**（Shao et al. 2024，DeepSeekMath）——**不要 value network**。做法：对同一 prompt 采**一组 G 个响应**，算每个响应的奖励，然后 **advantage = 这个奖励在组内的 z-score**（减组均值、除组标准差）。**"你比同组平均好多少"就是 advantage**，不需要单独学一个价值函数。

【slides】part1 p44 的原话点出它和 PPO 的关系：PPO 把 KL 项**藏在奖励里、再藏进 advantage**；GRPO 把 **KL 直接写在学习目标里**。对比表（part1 p46）：

| 维度 | PPO | GRPO |
|------|-----|------|
| 内存模型数 | 5 | 3 |
| advantage | GAE（每 token） | 组奖励的 z-score |
| token 级 credit | 逐 token（TD 残差） | **全 token 均匀** |
| 训练谁 | policy + value | **只有 policy** |
| KL 位置 | 藏在 token 奖励里 | 直接放目标里 |

### 5.3 DAPO：给 GRPO 补三个洞

【slides】part1 p47–p49，DAPO 修三处：

| 技巧 | 修什么毛病 |
|------|-----------|
| **clip-higher**（如 [0.8, 1.28]） | 对称裁剪的上界**限制探索**、导致 entropy collapse |
| **dynamic sampling** | 一组**全对或全错**时组标准差为 0 → **梯度死区**；只留"有好有坏"的组 |
| **token-level loss** | GRPO 样本级平均对**长 CoT 不公**（100-token 响应的单 token 梯度权重是 1000-token 的 **10 倍**）；改成 token 级平均 |

## §6 蒸馏与隐式推理

### 6.1 把小模型"教会"更划算

【slides】part1 p33, **Finding 4**：**如果算力有限，从一个大推理模型蒸馏，比给小模型直接上 RL 更划算**。能力能被蒸到小到 **1.5B** 的模型里。

> **术语**：**distillation（蒸馏）**——用大模型（teacher）的输出/分布来训练小模型（student）。

这背后还有一层（part2 p28–p34）：**on-policy distillation（GKD）**——传统蒸馏是"老师生成、学生模仿"（对学生是 **off-policy**），GKD 让学生**用自己生成的上文**去对齐老师（**reverse KL**），从而**消除 exposure bias**（训练见标准上文、推理见自己上文这个错配），并更"尖"地专注在自己最好的行为上。

### 6.2 隐式推理（latent reasoning）

> **术语**：**latent reasoning（隐式推理）**——推理**不写在文本里**，在模型的隐状态里"算"。它对应 slides 的一个观察（part1 p34, Finding 6）：**推理可以纯自回归完成，不需要 MCTS 那种外部搜索**——"想"这件事未必要全部可见。

**本课只给概念**：隐式推理是"推理一定要写成文字吗"这个问题的另一种答法，**没有可跑的对照**（见 `00` §6）。

## §7 顺带的两块系统知识（slides 里占了篇幅，但与推理本身是"配套"）

### 7.1 投机解码（让"想"变快）

**问题**：大模型生成慢。**观察**：**不是所有 token 都一样难生成**。

> **术语**：**speculative decoding（投机解码）**——用一个**小模型起草**若干 token，再让**大模型一次性验证**；验证通过就接收，不通过就退回重来。本质是 **rejection sampling**，能**保证输出分布与直接从大模型采一致**（证明见 Chen et al. 2023 附录 I）。

【slides】part2 p11：**60M 的 T5-small 起草 + 11B 的 T5-XXL 目标 ⇒ 2–3× 加速且输出完全一致**。这是纯工程红利：**不加准确率，只提速度**。

### 7.2 长上下文（让"想"能想很久）

【slides】part2 p36–p52：**要扩展推理，就得扩展长上下文**（读整个仓库、审几百页文档、超难数学的大量试错）。三个限制：**数据不够长、注意力 O(n²)、位置编码不泛化**。

- 典型文档长度（part2 p38）：Common Crawl 600–1200、维基 500–1500、arXiv 5k–10k+、书 50k–100k+。
- **RoPE**（part2 p43–48）：只旋转 **Q、K**（不动 V），**相对距离**能被干净地编码——"Taylor/Swift 在位置 10、11"与"在 100、101"得到**完全相同**的结果。
- **扩展实践**（part2 p49–52）：位置编码改法（**Position Interpolation、NTK-aware、YaRN**）；**渐进训练**（8K→32K→64K→128K，只需原预训练 **0.1–1%** 的 token）；数据工程；注意力结构（**GQA/MQA、FlashAttention、滑动窗口+全局 token**）。

## §8 串起来：一张心智地图

```
【直接生成】  greedy(近视) / beam(退化) / 采样(乱)
      │  没有草稿纸
      ▼
【CoT】  把中间步骤写进上文           ← 推理期，不改模型
      │  单条仍会走岔
      ▼
【self-consistency】 采样 k 条 + 多数投票      ← 推理期，更贵
      │        ⇕ 泛化
【test-time scaling】 预算 k ↑ → 准确率 ↑（有上限）
      │  投票是"群众"，还有"专家"
      ▼
【verifier】 ORM(整解) / PRM(逐步) + 搜索/Best-of-N
      │  但裁判会错、要钱、会给错奖励
      ▼
【RLVR】 用"答案对不对"训进去          ← 训练期，改模型
      │  需要一个便宜的 advantage
      ▼
【GRPO】 组内相对 advantage，省掉 value network；DAPO 再补三洞
      │  小模型上算力不够？
      ▼
【蒸馏】 从大推理模型蒸到 1.5B，比直接 RL 小模型划算
```

**代价**（整张图都悬在上面）：慢、贵、**会假装推理**、**长度不是准度**、**只对可验证的题有效**。

## §9 手算一个（这一篇唯一的算例）

题目：$x=3$，$x \leftarrow x\times 2+1$ 做 **2** 次，答案？

**假设**：这个"模型"每处理**一个步骤**，正确率 $p_{\text{step}}=0.9$；每处理**一整条链**（不写中间结果），正确率只有 $q_{\text{int}}=0.6$。（数字是假设，不是实测；实测见 `03`。）

| 方式 | 要几个"步骤"都对 | 正确率 |
|------|-----------------|--------|
| **直接答** | 内部一次算完 2 步，两步要同时对 | $0.6^2=0.36$ |
| **分步答** | 写两步，两步都要对 | $0.9^2=0.81$ |

**就这一格手算，是整个 `03` §2 的缩小版**：**分步把"一次憋两步"变成"两次各一小步"**，同样的"每步出错率"，整题正确率从 0.36 抬到 0.81。

**再看投票**（`02` §2）：单条分步正确率 $0.81$，采 $k=3$ 条多数投票。

- 三条**至少一条对**的概率 = $1-(1-0.81)^3 = 1-0.19^3 \approx 0.993$（这是上限）。
- 三条**多数（≥2 条）对**的概率 = $C_3^2\,0.81^2\cdot0.19 + 0.81^3 = 0.374+0.531=0.905$。

所以手算预期：$k=1$ 是 $0.81$，$k=3$ 投票大约 $0.90$，上限约 $0.99$。**`03` §3 会看到形状完全一样、只是数值来自真实仿真**。

## §10 术语小结（这一篇立的概念）

| 术语 | 一句话 |
|------|--------|
| **CoT（思维链）** | 先写中间推理再给答案 |
| **few-shot / zero-shot CoT** | 给示例 / 只加"think step by step" |
| **self-consistency** | 采样多条 + 对答案多数投票 |
| **test-time compute scaling** | 推理期多花算力换准确率 |
| **Best-of-N** | 采 N 个解，用 verifier 挑最好 |
| **verifier / ORM / PRM** | 裁判 / 判整解 / 判逐步 |
| **RLVR** | 用可验证奖励做 RL |
| **GRPO / DAPO** | 组内相对 advantage 的 RL / 它的三处修补 |
| **exposure bias** | 训练上文 ≠ 推理上文的错配 |
| **on-policy distillation（GKD）** | 用学生自己生成的上文做蒸馏 |
| **latent reasoning** | 推理不写出来，在隐状态里算 |
| **speculative decoding** | 小模型起草、大模型验证加速 |
| **RoPE / PI / NTK / YaRN** | 旋转位置编码 / 三类长上下文外推 |
