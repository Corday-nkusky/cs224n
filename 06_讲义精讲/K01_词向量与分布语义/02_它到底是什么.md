# K01 · 02 它到底是什么

> **进这一篇之前你能说出什么**：① WordNet 致命在算不出相似度；② one-hot 两两正交，内积恒为 0；③ 分布语义假说——观其伴而知其言。
> **这一篇回答什么**：这个"能算相似度的表示"具体长什么样？有哪两条路能得到它？各自的关键动作叫什么名字？
> **读完你应该能说出什么**：
> 1. 词向量是**稠密**向量，相似度用点积或余弦算——余弦是为了消掉向量长度的影响
> 2. **共现矩阵**是什么：给 3 句话，你能手算出来（它本质是一张带权无向图的邻接矩阵）
> 3. 共现矩阵为什么不能直接用，**降维**在干什么，SVD 在干什么
> 4. word2vec 的"代理任务"是什么：用中心词预测上下文

**这一篇不写代码、不做推导。** 会给出几个定义式（余弦、Frobenius 范数），但只是把话说成符号，**不往下推任何结论** —— 真正需要推导的都在 `04`。所有例子都小到能手算。
**这一篇的目的是让你在 `03` 里看见那些数字时，知道每个数字是什么、该不该长那样。**

## §1 一句话回答

> **给每个词一个稠密的实数向量，使得出现在相似上下文里的词，它们的向量在几何上也挨得近。**

【slides】Lec2 p10 给了两个 8 维真实例子（`banking` 和 `monetary`，取自训好的模型）：

```
banking  = [0.286, 0.792, −0.177, −0.107, 0.109, −0.542, 0.349, 0.271]
monetary = [0.413, 0.582, −0.007,  0.247, 0.216, −0.718, 0.147, 0.051]
```

对比一下 one-hot：

| | one-hot | 词向量 |
|---|---|---|
| 每一位 | 几乎全是 0，只有一个 1 | 每位都是小数，都参与表达 |
| 维度 | = 词表大小（50 万） | **25–1000**（【slides】p32），常用 100–300 |
| 两个不同词的关系 | 内积恒为 0（正交） | 内积是一个**连续值**，可大可小 |

> **术语**：
> - **稠密向量 / 分布式表示（distributed representation）** —— 意思分散在多个维度上，每个维度参与表达很多个词。
> - **局部表示（localist representation）** —— one-hot 那种，一个词一位。两者是相对的概念。

上面那两个向量每一位上的符号和大小都很接近，所以它们的内积会比较大——**这就是"稠密向量能算相似度"的全部秘密**。

## §2 相似度怎么算：点积，以及为什么要改用余弦

### 2.1 最直接的算法：点积

【slides】p10 说明，相似度用**点积**衡量：

$$\text{score}(u, v) = u^{\mathsf T} v = \sum_i u_i v_i$$

**它在干什么**：逐位相乘再求和。两位上符号相同（同为正或同为负）就贡献正值，符号相反就贡献负值。**所以"两个向量长得像" ⟺ "点积大"。**

### 2.2 点积有个毛病：向量长度会混进来

点积同时受两件事影响：**方向** 和 **长度**。而我们要的是"方向一致不一致"，不要长度。

> **术语**：向量的**模长（norm）** $\lVert v\rVert=\sqrt{\sum_i v_i^2}$，就是它到原点的距离。

打个比方：两个人都指向"东北"，一个走了 1 公里，一个走了 100 公里。方向完全一样，但点积差 100 倍。**你只想知道他们指的方向是不是一致，不想知道谁走得远。**

### 2.3 解决办法：余弦相似度

把点积除以两个模长，**把长度因素除掉**：

$$\cos(u,v)=\frac{u^{\mathsf T}v}{\lVert u\rVert\,\lVert v\rVert}$$

**它是两个向量夹角的余弦**，取值范围 $[-1, 1]$：

| 值 | 含义 |
|---|---|
| `1` | 方向完全相同 |
| `0` | 互相垂直（无关） |
| `-1` | 方向相反 |

【slides】p39 里做词向量类比检索时用的就是余弦距离。

> ⚠️ **余弦只回答"方向上像不像"，它不保证这个答案有意义**（`03` §4 会亲手撞上这一屏）。
> 拿到一堆 `1.0000` 时先别高兴，去数两件事：① 每个词实际用到了几个坐标；② 这两个词是被语料区分开了，还是压根没被区分。
> 【实测】两种成因都能造出来，见 `code/k01_verify_dim.py`：一种加维度能救，**另一种 300 维也救不了**——两个词在语料里共现行完全相同时，无论降到几维余弦都是 `1.000000000000`。**看到 1.0000 先别高兴。**

### 2.4 顺带一个后面要用的记号

`03` 里要量"矩阵被压缩后差了多少"，用到的 **Frobenius 范数**就是把模长推广到矩阵：

$$\lVert A\rVert_F=\sqrt{\sum_{i,j} A_{ij}^2}$$

**它就是"把矩阵抻成一个长向量再算长度"**。$\lVert X-X_k\rVert_F$ 就是原矩阵和压缩后矩阵的**逐元素总差距**。这里先认个脸，`03` §5 会看到它的实际数字。

## §3 怎么让向量自动长成这样：代理任务

分布语义假说只给了**目标**（相似上下文 → 相似向量），没给**方法**。总不能人手填 50 万个向量。

word2vec（Mikolov et al. 2013）的答案是设计一个**代理任务**：

> **给一个中心词，预测它周围会出现哪些词。**

【slides】p11 的机制：

- 有一个大语料（一长串词）
- 词表里每个词对应一个向量
- 走到语料的每个位置，取出**中心词** `c` 和它周围的**上下文词** `o`
- 用两者的向量算出一个"o 是 c 的邻居"的得分
- 不断调整向量，让真实邻居的得分变高

> **术语**：
> - **中心词（center word）** —— 窗口中间那个词
> - **上下文词（outside/context word）** —— 窗口里除中心外的词
> - **窗口大小 m** —— 中心词左右各看 m 个词（真实总宽度是 2m，常用 5–10）

### 【直觉】关键在这一步的"不关心"

**我们根本不关心这个预测准不准。** 我们关心的是：为了让预测变准，模型**被迫**把"出现在相似上下文里的词"放得越来越近。

> **比方**：让一群人玩"猜邻居"的游戏。游戏得分本身没意义，但玩着玩着，**住得近的人自然坐到了一起**。我们要的不是得分，是那个座位排布。

这个"用简单任务逼出好的表示"的思路，后代是**对比学习**和 **BERT 的掩码语言模型**——后面每一课都在用，这里是第一次出现。

### 一个反直觉的点

【slides】p23 指出：word2vec 在每个位置做**同样的预测**，不管词在句子里的位置，所以它本质是个 **bag-of-words 模型**——**丢弃了词序信息**。这是它快的代价。

## §4 每个词有两套身份

【slides】p15：每个词 `w` 有**两个**向量：

| 记号 | 什么时候用 | 角色 |
|------|-----------|------|
| `v_w` | w 作**中心词**时 | 中心向量 |
| `u_w` | w 作**上下文词**时 | 上下文向量 |

打分用的是一个中心向量和一个上下文向量做内积（`$u_o^{\mathsf T}v_c$`）——**不是两个同类向量相乘**。

**为什么？** 【slides】p25 给的理由只有一句：**Easier optimization**（优化更容易）。

**展开说**：如果共用一套向量，那么"a 出现在 b 附近"和"b 出现在 a 附近"会强制走同一个参数，梯度更新时互相牵扯。拆成两套后，每个位置的更新只影响"当前这个词作为中心 / 作为上下文"的那一个角色，梯度更干净。

**代价**：参数翻倍（`2dV`），且两套向量处在**不同坐标系**里。slides 说训练完可以把两套平均。

> ⚠️ **slides 还补了一句"只用一套也能实现，而且稍微好一点（it helps a bit）"** —— 这是原话，**我没有实验数据验证**。工程现实：`gensim` 默认只输出一套。
> **实用结论**：算相似度时**别把 `u` 和 `v` 混着用**。

## §5 另一条路：不"学"，直接"数"

【slides】p30 替你问了这个问题：

> **干嘛要一遍遍扫整个语料？直接把"谁和谁一起出现"的统计全攒下来不行吗？**

可以。这就是**共现矩阵**路线——也是 **A1 作业 Part 1 的全部内容**。

### 5.1 手算一遍（这是 `03` 里要跑的同一个例子）

语料三句话，**window = 1**（中心词左右各看 1 个词）：

```
I like deep learning
I like NLP
I enjoy flying
```

**数法**：从左到右走每个词，把它左右各 1 个词的计数 +1。

| 中心词 | 邻居 | 记什么 |
|--------|------|--------|
| I | like | `X[I][like] += 1` |
| like | I, deep | `X[like][I] += 1`、`X[like][deep] += 1` |
| deep | like, learning | `X[deep][like] += 1`、`X[deep][learning] += 1` |
| learning | deep | `X[learning][deep] += 1` |
| I | like | `X[I][like] += 1`（**第 2 句又来一次**） |
| like | I, NLP | `X[like][I] += 1`、`X[like][NLP] += 1` |
| NLP | like | `X[NLP][like] += 1` |
| I | enjoy | `X[I][enjoy] += 1` |
| enjoy | I, flying | `X[enjoy][I] += 1`、`X[enjoy][flying] += 1` |
| flying | enjoy | `X[flying][enjoy] += 1` |

结果（行 = 中心词，列 = 上下文词）：

|     | I | NLP | deep | enjoy | flying | learning | like |
|-----|---|-----|------|-------|--------|----------|------|
| **I** | 0 | 0 | 0 | 1 | 0 | 0 | **2** |
| **NLP** | 0 | 0 | 0 | 0 | 0 | 0 | 1 |
| **deep** | 0 | 0 | 0 | 0 | 0 | 1 | 1 |
| **enjoy** | 1 | 0 | 0 | 0 | 1 | 0 | 0 |
| **flying** | 0 | 0 | 0 | 1 | 0 | 0 | 0 |
| **learning** | 0 | 0 | 1 | 0 | 0 | 0 | 0 |
| **like** | 2 | 1 | 1 | 0 | 0 | 0 | 0 |

**两个可以自己验的性质**：

1. **矩阵是对称的** —— 因为窗口口径下不分左右，"a 在 b 旁边" 和 "b 在 a 旁边" 记的是同一件事（`X = Xᵀ`）
2. **非常稀疏** —— 非零元素只有 12/49 ≈ 24.5%，而这还只是 7 个词的词表

### 【直觉】共现矩阵就是一张图的邻接矩阵

这条类比能让你一次记住它的全部性质：

| 图论里的东西 | 共现矩阵里的对应 |
|---|---|
| 顶点 | 词 |
| 边 | 两个词在同一个窗口里出现过 |
| 边权 | 共现次数 |
| **无向图** | **窗口口径下矩阵对称** |
| 邻接矩阵 | 共现矩阵 X |

**"对称"和"稀疏"不是需要背的性质，是图结构的直接后果。**

### 5.2 两种统计算法

【slides】p30 给了两种口径：

| 口径 | 统计什么 | 抓到什么 | 别名 |
|------|---------|---------|------|
| **窗口** | 词与词在同一窗口共现 | 句法 + 语义信息 | word space |
| **全文档** | 词与词在同一文档共现 | 主题（所有体育词会有相似条目） | document space → **LSA** |

## §6 为什么不能直接拿它当词向量用

【slides】p32 列了三个问题：

1. **维度随词表增长** —— 词表 50 万，每个词的向量就是 50 万维
2. **极其稀疏** —— 上面 7 个词就只有 24.5% 非零，真实规模下稀疏得多，存储吃不消
3. **下游分类模型对稀疏敏感**（slides 原话 "Models are less robust"）

**所以必须降维**：从「词表大小」维压到 **25–1000 维**（【slides】p32），和 word2vec 一个量级。

**降维在干什么**：把 50 万个"谁和谁共现过"的计数，压缩成几百个**能代表主要变化方向的坐标**。压完每个词就有了一个几百维的稠密向量，正好是 §1 要的那个东西。

## §7 SVD 在干什么（直觉版，不推公式）

【slides】p33 给的降维工具是 **SVD（奇异值分解）**：

$$X = U\Sigma V^{\mathsf T}$$

**这一篇只需要它的直觉，公式留给 `04`。** 三句话：

### ① 它给数据换了一组坐标轴

原来每个词用"跟 50 万个词各自的共现次数"来描述，这 50 万个数高度冗余（出现 debt 的词往往也出现 crisis）。

SVD 找出一组**新的坐标轴**：

- 第 1 个轴 = 数据散得**最开**的那个方向
- 第 2 个轴 = 与第 1 个垂直的前提下，散得次开的方向
- 以此类推

> **术语**：**奇异值** $\sigma_i$ —— 数据在第 i 个轴上散开的程度，也就是**这个轴有多重要**。

### ② 只留前 k 个轴 = 有损压缩

丢掉后面那些轴，就丢掉了散得最少的方向（信息量最小的部分）。

> **【直觉】类比**：给一栋建筑拍照。你只能拍一张二维照片，那就选一个能看清最多结构的角度拍——这就是"第 1 个轴"。拍完丢掉的那些角度，就是被压掉的部分。**SVD 帮你把"最值得拍的角度"按重要程度排好序，你只要决定拍几张。**

（顺带一提：这就是 PCA 背后那台机器。PCA 是对协方差矩阵做特征值分解，SVD 直接对数据矩阵做——**同一件事的两种走法**。）

### ③ 而且SVD 给的是"最优"的有损压缩

【定义】保留前 k 个奇异值得到的 $X_k$，是 X 在**最小二乘意义下的最优秩 k 近似**——意思是：在"只允许用 k 个方向"的所有方案里，$X_k$ 与 X 的逐元素总差距 $\lVert X-X_k\rVert_F$ 最小。

**这是经典线性代数结论，不是经验规律。** `03` §5 会用 7×7 的矩阵实测验证误差随 k 单调下降。

### 一个必须先说的警告

【slides】p34 用三个感叹号强调了这件事：

> **Running an SVD on raw counts doesn't work well!!!**
> （对原始计数直接跑 SVD，效果不好。）

**原因**：the / he / has 这类**功能词**太频繁，**句法信号压倒了语义信号**——降维抓到的第一个主轴往往是"这个词常不常和功能词一起出现"，而不是它的意思。

slides 给的修正手段（"hacks to X"）：

| hack | 做法 | 解决什么 |
|------|------|---------|
| 取对数 | `log` 频次 | 压缩高频词的统治地位 |
| 截断 | `min(X, t)`，t ≈ 100 | 同上，硬上限 |
| 忽略功能词 | 直接不统计 the / he / has | 去掉纯句法信号 |
| **斜坡窗口** | 近的词权重更高 | 距离信息 |
| 用相关性替代计数 | 算相关系数，**负值置 0** | 去掉"共同不出现"的干扰 |

## §8 两条路的对照，以及 GloVe 的位置

| | **计数法**（共现 + SVD） | **预测法**（word2vec） |
|---|---|---|
| 怎么做 | 数一遍 → SVD 降维 | 训练一个预测模型 |
| 优点 | 统计充分、可解释、一次成型 | 可增量、复杂度可控 |
| 缺点 | 大矩阵 SVD 很贵；**原始计数效果差，需要各种 hack** | 要调参、要训练 |
| slides 的评价 | "classic method"（p33），但原始计数 "doesn't work well"（p34） | "standard word2vec"（p26） |

**GloVe（Pennington, Socher, Manning, EMNLP 2014）是这两条路的合流**（【slides】p36–37）。它问的是：

> **怎么把"共现概率的比值"编码成向量空间里的线性语义成分？**

**这句话什么意思**：光看 P(ice|solid) 高不高没用，因为 P(water|solid) 也高。真正区分 ice 和 steam 的是**比值**——P(ice|solid)/P(ice|gas) 很大，而 P(steam|solid)/P(steam|gas) 很小。GloVe 直接去拟合这个比值。

它的模型是 **log-bilinear**，卖点是**训练快、能扩展到超大语料**。

## §9 它在第几代，以及这一代的边界

slides 没有明列这条链，但它贯穿 Lec1–2：

| 代 | 做法 | 解决了什么 | 还差什么 |
|----|------|-----------|---------|
| 1 | BoW（词袋） | 文本变成向量 | 丢词序、稀疏 |
| 2 | LSA / SVD | 降维、抓住主题 | 原始计数效果差 |
| 3 | NNLM（神经语言模型） | 第一次"学"出词向量 | 慢 |
| 4 | **Word2Vec** | 快到能用在工业规模 | 一词一义 |
| 5 | GloVe | 用全局统计补上只看局部窗口的短板 | 一词一义 |
| 6 | fastText | 加入子词信息，罕见词有救 | 一词一义 |
| 7 | ELMo / BERT | **上下文相关**表示 | 贵，需要大模型 |
| 8 | 句向量 | 整句一个向量 | 长度与组合性 |

**word2vec 的历史定位**：第 4 代，核心贡献是**把代价从 O(V) 降到 O(K)**——**这是一次效率革命，不是效果革命**。

### ⚠️ 这一代技术的死穴：一词一义（静态表示）

**不管上下文是什么，"bank" 只有一个向量。**

- "I deposited money in the **bank**" —— 金融机构
- "We sat on the river **bank**" —— 河岸

**两个意思被压进同一个向量**，压出来的结果偏向哪边，取决于语料里哪个意思出现得更多。

这个问题要到 **ELMo / BERT（上下文相关表示）** 才解决，在 CS224N 里是 K03 之后的主线。**记住它——它是整条缺陷链上的下一个扣。**
