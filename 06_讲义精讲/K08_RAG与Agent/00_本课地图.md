## §3 知识清单

每条一句话结论 + 出处页码。**扫一遍，看有没有哪条你讲不出来。**

### A. 为什么需要 RAG（5 条）

1. 【slides】p14：与其让 LM **把一切背进参数**，不如**在需要时（just-in-time）**把相关内容喂给它——检索就是识别这种相关内容的手段。
2. 【slides】p14：检索有两条参数记忆给不了的好处：**动态**（往库里加/改文档很容易）与**可解释**（LM 能给出指向来源的指针供人核对，即引用）。
3. 【slides】p12：**开放域问答**不给现成段落，只给一个大规模文档集（如维基百科），要自己定位答案；比"给段落的阅读理解"难得多、也实用得多。
4. 【slides】p11：**阅读理解**的形式化——输入 $C=c_1..c_N$、$Q=q_1..q_M$，输出一个区间 $1\le\text{start}\le\text{end}\le N$；典型量级 $N\sim100$、$M\sim15$。
5. 【slides】p15-16：**RAG = 检索器 + 生成器**：检索器 $f(\mathcal D,Q)\to P_1,\dots,P_K$（$K$ 预先定，如 100），生成器 $g(Q,\{P_i\})\to A$；早期检索器就是 **TF-IDF 稀疏模型**（固定模块），生成器是神经阅读理解模型或零样本 LLM。

### B. 检索（6 条）

6. 【slides】p17：三类检索器：**词重叠（BM25）**、**向量检索（DPR / sentence vectors）**、**其它神经检索（ColBERT）**。
7. 【slides】p18：**快慢谱**——最快是在**预计算向量**上算相似度；最慢是用一个 LM 现算相似度；中间是**混合**（预建"文档索引"），如 ColBERT。
8. 【slides】p19-20：检索器**可以训练**——用 BERT 把问题和段落各编码成向量，打分取点积；DPR 用问答对训练，**可训练检索器显著优于传统 IR 模型**。
9. 【slides】p22-24：**"能用几篇文档"是真问题**——检索器召回率慢慢爬到 90%，但 **RAG 的效果在 10–20 篇后就饱和**：LM 用不上那么多文档。
10. 【slides】p23：LM **无法把注意力公平分给整个长上下文**——实验设置"1 篇相关 + 其余全不相关"：纯闭卷最好 ~56%，**只喂相关文档（oracle）~88.5%**（GPT-3.5-Turbo）。
11. 【slides】p21：**深度检索 + 生成**——最近工作显示"生成答案"优于"抽取答案"（Fusion-in-Decoder = DPR + T5）。

### C. 引用与幻觉（2 条）

12. 【slides】p27-28：RAG 的独有卖点是**引用来源**；但**引用本身也是 LLM 生成的，所以引用也可能被幻觉**——实测里输出"看起来有用"（评分还行），**但精确率与召回率都低**。
13. 【slides】p26：**RARR**（Guo+2023）用 QA 检查"来源与回答是否一致"、返回引用、检测分歧并让编辑模型改写。

### D. Agent（6 条）

14. 【slides】p29：LLM 对给定输入预测文本；**Agent 则基于对环境的观察去执行动作**（act / observe）。"什么算 Agent"有很多争论。
15. 【slides】p30：**语言 Agent 的关键组件**——**LLM 核心** + **规划与推理**（ReAct / CoT / Reflexion）+ **记忆**（episodic / semantic / procedural）+ **工具**（检索、计算器、代码、搜索、读写记忆）+ **环境**（桌面 OS、浏览器、App、游戏、机器人、数据库）。
16. 【slides】p33-34：**推理**对 LLM 是"模仿人思维过程的中间生成"，对 Agent 是**内部动作**；它有用的原因是"观察→行动"的映射很难，推理提供**泛化**与**对齐**。
17. 【slides】p35-37：**ReAct = Reason + Act**——交替"思考→行动→观察"，在找答案的例子中 4 步走完；ReAct 稳定优于纯行动，且**能缓解 CoT 的幻觉**。
18. 【slides】p38-43：推理增强家族——**Self-Consistency**（多条推理路径取最一致答案）、**Reflexion**（用自然语言反馈自我反思、把失败轨迹蒸馏成"自我提示"）、**多 Agent 辩论**、**Orchestrator 协调**。
19. 【slides】p45-51：**记忆按内容分三类**——episodic（存经历）、semantic（存知识）、procedural（存技能）；**MemGPT** 借鉴 OS 做"虚拟上下文管理"，用函数调用读写外部数据、自己改上下文。

### E. 工具与 Agent 应用/数据（4 条）

20. 【slides】p54-58：**工具调用**——ToolkenGPT 把每个工具表示成一个 token；**Toolformer** 让 LM 自学"调哪个 API、何时调、传什么参数、怎么用结果"（工具：计算器/QA/搜索/翻译/日历）；Gorilla 用 self-instruct 生成 {instruction, API} 对做微调。
21. 【slides】p60-63：**Agent 应用按环境分**——数字世界（编码、游戏、移动、Web/App、电脑操作 Agent）与物理世界（机器人）；每类都给了观察空间/动作空间（如编码 Agent：环境=代码库/文件系统/IDE，观察=代码/输出/报错/提交历史，动作=改代码/搜文件/跑测试）。
22. 【slides】p64-67：**Agent 数据难造**——人类示范贵、专家贵、任务覆盖难；替代是**合成/模拟**（把在线教程转成示范）、互联网规模数据、以及 **SWE-smith** 这类自动造 100s–1000s 任务实例的工具。
23. 【slides】p70-72：**从一个最小编码 Agent 看本质**——"一个 AI 编码 Agent 就是**一个大循环**"：LM 提动作 → 在代码环境执行 → 把输出告诉 LM → 重复；只需实现 `query_lm`、`parse_action`、`execute_action` 三个函数。

### F. 评测（1 条）

24. 【slides】p68：**Agent 评测的难点**——真实环境搭建复杂、任务覆盖、成功标准开放、解法不唯一、**无法脚本化指标（需要人工判断）**、要评"任务成功之外"的东西；手段有 benchmark、LLM/VLM 打分、众包。**详见"Benchmarking and Evaluation"那一讲（= K09）。**

## §5 术语索引

按首次出现的篇排。`01` 篇零前置，`02` 篇是本知识点核心概念，`04` 篇才需要推导背景。

| 术语 | 一句话解释 | 出处 |
|------|-----------|------|
| **知识截止 / 参数记忆** | 模型知识全压在训练时的参数里，之后发生/私有的知识它没有 | `01` §2 |
| **幻觉（hallucination）** | 模型生成看似合理但与事实不符的内容 | `01` §2 |
| **检索增强生成（RAG）** | 先检索相关内容，再把它连同问题喂给生成器 | `02` §1 |
| **开放域问答（open-domain QA）** | 不预设段落，从大规模文档集里找答案 | `01` §3 |
| **检索器（retriever）** | RAG 前半段：从文档集里挑出 $K$ 篇最相关的 | `02` §2 |
| **生成器 / 读者（generator / reader）** | RAG 后半段：读检索结果并产出答案 | `02` §2 |
| **稀疏检索** | 靠词的**字面重叠**打分（BM25/TF-IDF），向量高维稀疏 | `02` §3 |
| **BM25** | 词重叠检索的标准打分函数（IDF×饱和TF×长度归一） | `02` §3、`04` §2 |
| **TF-IDF** | 词频×逆文档频率，稀疏检索的另一基础打分 | `02` §3、`04` §2 |
| **稠密检索 / 向量检索** | 把查询与文档编码成稠密向量，按相似度检索（DPR） | `02` §3、`04` §4 |
| **余弦相似度** | $\cos(u,v)=u^\mathsf{T}v/(\lVert u\rVert\lVert v\rVert)$，只比方向 | `02` §3、`04` §4 |
| **混合检索** | 稀疏 + 稠密一起用（如 ColBERT 的预建索引） | `02` §3 |
| **分块（chunking）** | 把长文档切成小块再建索引，块太小/太大各有代价 | `02` §4 |
| **重叠（overlap）** | 相邻块共享一部分句子，防止答案被切在边界 | `02` §4 |
| **reranking（重排）** | 检索出候选后，用更贵的模型重新精排前几名 | `02` §5、`04` §5 |
| **条件生成（conditioning）** | 把检索结果放进上下文，让生成"以它为条件" | `02` §5 |
| **Lost-in-the-middle** | 长上下文里中间位置的信息容易被忽略 | `02` §5、`04` §9 |
| **Agent** | 基于对环境的观察执行动作的 LLM 系统 | `02` §7 |
| **工具调用（tool use）** | Agent 生成一个"调用某工具+参数"的请求并拿回结果 | `02` §8 |
| **ReAct** | Reason+Act：交替"思考→行动→观察"的循环 | `02` §8、`04` §6 |
| **CoT（思维链）** | 让模型先输出推理步骤再给答案（只推理、不行动） | `02` §8、`04` §6 |
| **规划（planning）** | 把目标拆成有序子任务 | `04` §7 |
| **记忆（memory）** | episodic/semantic/procedural：存经历/知识/技能 | `02` §8、`04` §8 |
| **Reflexion** | 用自然语言反馈自我反思、把失败轨迹变成"自我提示" | `04` §6 |
| **误差归因（检索 vs 生成）** | 答错时先定位是"没检索到"还是"检索到了没用对" | `03` §5、`04` §9 |
| **LLM-as-judge / red team** | 用 LLM 打分 / 主动攻击找漏洞 —— **K09 内容** | `05` §5（引 K09） |

## §7 下一课预告：K09 评测

会复用本课的东西：**RAG/Agent 都是"系统"，需要一个判据说它好不好**——本课 `04` §9 只提出了"误差归因"（是检索错还是生成错）与"为什么无法脚本化"，**没有给判据**。

下一课（K09）会回答：

1. **内在指标 vs 外在指标**：检索的 recall@k 是内在，端到端正确率是外在
