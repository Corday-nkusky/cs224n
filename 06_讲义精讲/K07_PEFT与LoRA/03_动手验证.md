## §2 验证一：参数到底省了多少

**断言**（`02` §4.3、【slides】p46–48）：LoRA 只训 $A,B$ 两个小矩阵，可训练量远小于全参。

**你的预期**：一个 $4096\times4096$ 的矩阵，用 $r=8$ 的 LoRA，可训练参数是**几万**还是**几百万**？占总参数百分之几？

**【实测】** 先按公式列一张表：

```
一个 4096×4096 的权重矩阵 W0：
  全参微调可训练参数 = d·k = 16,777,216

   秩 r      LoRA 可训练 2·d·r         占全参比例
     1               8,192    0.048828%
     2              16,384    0.097656%
     4              32,768    0.195312%
     8              65,536    0.390625%
    16             131,072    0.781250%
    64             524,288    3.125000%
```

再用 torch **真建**一个 `nn.Linear(4096, 4096)`，用 LoRA($r=8$) 包一层，用 `requires_grad` 数一遍：

```
实测：LoRA(r=8) 包装 4096×4096 Linear
  总参数 = 16,846,848，可训练 = 65,536（占 0.389010%）
  即把可训练量从 16,777,216 降到 65,536，少 256 倍。
```

**对账**：
- $r=8$：$2\times4096\times8=65,536$ ✅；占 $65536/16777216=0.390625\%$ ✅。
- "实测"里比例是 **0.389010%**，与公式的 0.390625% **略有差别**：因为实测把**冻结的底座 $W_0$（16,777,216）也算进了"总参数"的分母**（$16,846,848=16,777,216+65,536$）。**两个比例口径不同，都对**——`02` §4.3 说的是"占 $W_0$ 的比例"，实测说的是"占整个模块的比例"。
- **符号约定**：表格里的 $r=64$ 是故意给个"太大"的值看趋势——**越大省得越少**（占 3.125%）。

**这一屏把 `01` §3.2 的"每任务一份"变成可算的重量**：

```
每任务存一份的成本（算术）：
  全参副本：GPT-3 175B 参数 × 2 字节(fp16) ≈ 350 GB
  一个 4096 矩阵的 LoRA(r=8)：65,536 参数 × 2 字节 ≈ 128.0 KB
```

> **350 GB vs 128 KB**——**每任务一份全量权重**这件事的重量，和**每个矩阵只带一个 LoRA**这件事的重量，差了六个数量级。这就是 PEFT 让"多任务并存"从不可能变可做的直接原因。

> ⚠️ **诚实边界**：这里的 350 GB 是**算术**（$175\times10^9\times2$ 字节），**不是实测下载/存储**；128 KB 也是算术。真正"LoRA 化整个 GPT-3 要多少参数"取决于加在多少层、$r$ 多少，**本课没有算全模型的总量**。

## §3 验证二：低秩的 $\Delta W$ 能被 LoRA 拟合，秩不足则不能

**断言**（`02` §4.1–§4.2、【slides】p48）：任务带来的改变是低秩的，所以"两个小矩阵之积"能表示它。

**你的预期**：如果我构造一个**真实秩为 4** 的目标改变量 $\Delta W$，那么 LoRA 用 $r=8$（≥4）能不能拟合到接近零？用 $r=2$（<4）会怎样？

**【实测】** 构造 $64\times64$ 的 $W_0$，目标 $\Delta W=B_{\text{true}}A_{\text{true}}$（$B_{\text{true}}$ 为 $64\times4$、$A_{\text{true}}$ 为 $4\times64$，故**真实秩 = 4**）；用随机 $X$ 生成 $Y=XW_{\text{target}}^\top$，冻结 $W_0$、只训 $A,B$（这里取 $\alpha=r$，使缩放 $=1$）：

```
方法                                       可训练参数        相对误差 ‖W_eff−W_target‖/‖ΔW‖
LoRA r=8（≥ r_true）                     1,024                        0.000834
LoRA r=2（< r_true）                       256                        0.507081
全参微调（训整个 W）                            4,096                        0.000244
```

**对账**：
- **LoRA $r=8$ 误差 8.3e-4**（≈0）✅ —— 秩够，两个小矩阵足以拼出真实秩 4 的改变量。
- **LoRA $r=2$ 误差 0.507** —— **卡住了，拟合不下去** ✅。这个数不是随便的：一个秩 4 矩阵用秩 2 去近似，**理论最优的相对误差**（Eckart–Young）在四个奇异值相当时约为 $\sqrt{(σ_3^2+σ_4^2)/(σ_1^2+\cdots+σ_4^2)}\approx\sqrt{2/4}=0.707$；实测 **0.507** 在同一量级（奇异值不相等，所以略低）。`04` §3 会补这条。
- **全参微调误差 2.4e-4** ✅ —— 训整个 $W$ 当然也能拟合，**但可训练参数是 4096，是 LoRA $r=8$ 的 4 倍**。

**这一屏意味着什么**：

> **"低秩"不是修辞，是能被拟合出来的性质。** 只要任务的改变确实低秩，LoRA 就能用极少的参数把它学到；**而秩给不够时，它会诚实地"学不动"**（r=2 卡在 0.5）。
> **反过来**：如果真实任务的 $\Delta W$ **不是低秩的**，那 LoRA 就会受限——这正是 `01` §5"容量天花板"的机制来源。

## §4 验证三：秩 $r$ 扫描 —— 参数线性涨、误差跨过真秩就塌

**断言**（`02` §5.1、【slides】p49）：$r$ 越大表达力越强、参数线性增长；$r$ 大到足够后，LoRA 收敛到全参微调。

**你的预期**：目标真实秩还是 4。误差应该在 $r$ 等于几的时候"断崖式"下降？$r$ 从 8 继续加到 32，误差还会明显下降吗？

**【实测】** 同一目标（真实秩 4），扫 $r$：

```
目标 ΔW 的真实秩 r_true = 4

   秩 r        可训练参数 2·r·64          相对误差
     1                 128      0.733148
     2                 256      0.507081
     4                 512      0.000064
     8               1,024      0.000834
    16               2,048      0.000006
    32               4,096      0.000373
```

**对账**：
- **参数**：$2\times r\times64$，严格线性 ✅（128→256→512→1024…）。
- **误差**：$r=1$（0.733）、$r=2$（0.507）都**卡在 0.5–0.73**；**$r=4$ 一跨过真秩，误差立刻塌到 6.4e-5** ✅。**断崖点在 $r=r_{\text{true}}=4$**——这正是"**表达能力由 $r$ 决定，且上限就是 $r$**"的实测。
- **$r\ge4$ 之后**：6.4e-5 / 8.3e-4 / 6e-6 / 3.7e-4 —— **在同一量级上下抖**，**没有再系统性地下降**。这**不是 bug**，是**已经触及训练下限**（Adam 在 2500 步内能到达的精度）；$r=8$ 比 $r=4$ 略高，纯属**优化过程的抖动**，不代表"更大的秩更差"。

> **这一屏把"秩是旋钮"说死了**：$r$ 决定**能表示多少**（跨过真秩前后是"学不动"和"够用"的质变），**增加 $r$ 的收益在跨过真秩后迅速消失**（只剩抖动）。
> **工程含义**：p54 说"LoRA 秩低到 1 也能匹配全参微调（RL 场景）"——**因为那些任务真实需要的秩可能就很低**；而盲目把 $r$ 开到 64、128，多半是**白涨参数量 + 更难训**。

> ⚠️ **必须的诚实声明**：这里的"真秩 = 4"是**我人为构造的**（$\Delta W=B_{\text{true}}A_{\text{true}}$）。真实任务里"内在秩是多少"**没人预先知道**，只能靠试。**本课没有在真实任务上测内在秩**——`0.000064` 这样的数字演示的是**机制**（秩够就能表示），**不是真实任务的精度**。

## §5 验证四：$B$ 零初始化 ⇒ 起点就是原模型

**断言**（`02` §5.3、【slides】p48）：$A$ 高斯初始化、$B$ 初始化为零，于是 $\Delta W=BA=0$，训练起点等于预训练模型。

**你的预期**：$B=0$ 时，LoRA 模块的前向输出和"纯预训练前向"差多少？如果 $B$ 也随机非零呢？

**【实测】** 同一个 $W_0$、同一批输入，两种 $B$：

```
B=0 时，LoRA 前向 = 预训练前向，max|差| = 0.000e+00
对照：B 随机非零时，与预训练前向 max|差| = 1.672e-02
```

再补一屏**梯度视角**（训练前、$B=0$）：

```
梯度视角（训练前 B=0）：‖∂L/∂A‖_F = 0.000000e+00，‖∂L/∂B‖_F = 4.150881e-01
```

**对账**：
- **$B=0$：差恰好 0.000e+00** ✅ —— 因为 $\Delta W=BA=0$，**前向是逐位相同的同一串浮点运算**。**训练从"原模型"出发，一步都不偏。**
- **$B$ 随机非零：差 1.7e-2** —— 起点就给 $W_0$ 叠了一个**随机扰动**，等于**一开始就破坏了一部分预训练能力**，得靠训练再补救。
- **梯度**：$B=0$ 时 **$\|\partial L/\partial A\|=0$**、$\|\partial L/\partial B\|=0.415\neq0$ ✅ —— **第一步只有 $B$ 会被更新**，$B$ 一旦非零，$A$ 才开始收到梯度。`04` §4 给推导。

**这一屏意味着什么**：

> **初始化的选择不是小事**：$B=0$ 让"加 LoRA"这个动作在训练开始时**对模型行为零影响**——**这是"从预训练出发做小改动"这句话能成立的机制保证。** `04` §4 会给出它的一条附带好处（梯度更干净）。

## §6 验证五：merge 是恒等变形，且可精确回退

**断言**（`02` §5.5、【slides】p49）：推理时把 $\frac{\alpha}{r}BA$ 合进 $W_0$，前向结果不变、且无额外延迟；换任务时减掉即可回退。

**你的预期**：合并前（分开算两路再相加）与合并后（一个矩阵一次乘法），输出差异应该是多少？

**【实测】** 用 float64、$512\times512$ 的 $W_0$、$r=8$、$\alpha=16$、256 条输入：

```
LoRA 前向 vs 合并后前向：max|差| = 1.421e-14
→ 合并只是把 (α/r)·BA 加进 W0，是恒等变形，差异只有浮点舍入。
回退：W_merged − (α/r)·BA = W0 ?  max|差| = 5.551e-17
```

**对账**：
- **合并前后差 1.4e-14** —— **不是零，但那是双精度浮点的舍入量级**（$\sim10^{-16}$ 的机器精度，$512$ 项累加后放大到 $\sim10^{-14}$）。**代数上恒等**：$W_0x+BAx=(W_0+BA)x$，就是矩阵乘法的**分配律**。
- **回退误差 5.6e-17** —— 减掉同一份 $\frac{\alpha}{r}BA$，**精确拿回 $W_0$** ✅。

> **一个必须指出的差异**：任务书原本预期 merge 差"~1e-16"，**实测是 1.4e-14**。原因是这里在 $512$ 维上做矩阵连乘，**舍入误差随累加项数增长**（$\sim\sqrt{n}\cdot\varepsilon$）。**这不是"没对上"，而是预期里低估了累加规模**——`04` §7 会说明为什么这是恒等而不是近似。

**这一屏意味着什么**：

> **"推理无额外延迟"是可验证的**：合并后就是**一个普通 $W$**，前向与任何普通 Linear 一模一样。
> **"换任务无痛"也可验证**：回退只差 5.6e-17，**换一份 $B'A'$ 就是换一个矩阵**——多个任务的适配器可以**在内存/磁盘上并存、按需换**（`01` §3.2 的镜像分层，在这里落地）。

## §7 验证六：$\alpha$ 是强度旋钮

**断言**（`02` §5.2、【slides】p48）：$\alpha$ 是"预训练知识与任务知识的权衡"，即改动强度的旋钮。

**你的预期**：固定 $r=8$、固定同一份 $A,B$，把 $\alpha$ 从 8 调到 32，$\Delta W$ 的**大小**会怎么变？

**【实测】** 取 $A,B$ 随机（不训练），看 $\|\frac{\alpha}{r}BA\|_F$：

```
固定 r=8，BA 的 Frobenius 范数 = 1.944751

    α     α/r    ‖(α/r)·BA‖_F
    8    1.00        1.944751
   16    2.00        3.889502
   32    4.00        7.779003
```

**对账**：$\alpha=8,16,32$ 对应 $s=\alpha/r=1,2,4$，范数 **1.945 / 3.890 / 7.779** —— **严格线性** ✅（7.779 = 4 × 1.945）。

**这一屏意味着什么**：

> $\alpha$ **不改 $A,B$ 本身，只改它们对 $W_0$ 的作用强度**。**同一份更新，$\alpha$ 越大，模型被"推"得越远**——推得太远会覆盖预训练能力，推得太近又改不动任务。这就是"权衡"的字面意思。

> ⚠️ **口径提醒**：本 demo 用的是**论文口径**的缩放 $s=\alpha/r$（Hu et al. 2021）。**slides p48 写的是 $\Delta W=\alpha BA$（没有除 $r$）**——两种写法都只是"强度旋钮"的不同刻度。**本课以 slides 的概念为准，公式上用论文的 $\alpha/r$ 并已标注**（见 `04` §5）。
