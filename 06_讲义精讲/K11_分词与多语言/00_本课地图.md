## §3 知识清单

每条一句话结论 + 出处。**扫一遍，看有没有哪条你讲不出来。**

### A. 分词是什么、为什么要它（4 条）

1. 【slides】p8：对语言模型而言，**语言的基本单位是 token**；**分词（tokenization）**是把文本切成 token 的过程；**tokenizer** 在"文本 ↔ token 序列"之间翻译；**词表（vocabulary）**是所有已知 token 的集合。例子 `We looked at the Milky Way.` → `[2167, 10802, 540, 290, 10282, 5781, 0]`。
2. 【slides】p9：**根本原因**：模型不能读原始文本（"Models can't just read raw text"），需要一个"**字符串 → 一串 embedding**"的映射。
3. 【slides】p11–14：token ID 通过**查 embedding 矩阵**变成向量（`(We) 2167 → 向量`）；分词在模型训练**之前**就决定了它看到什么。
4. 【slides】p15–17：分词是**预处理步骤，不是 LM 核心的一部分**；但它同时影响**序列长度**和**参数量**（vocab 越大，embedding 矩阵越大）。

### B. 词级分词：优点与两条死因（3 条）

5. 【slides】p18：词级分词 = 按空格切词 + 标点；词表取语料里最高频的 V 个词。**优点**：语义上有意义的单位；**一个 embedding ≈ 一个可解释的意思**。
6. 【slides】p19：**死因①词太多、长尾太长**——词频与频次排名成反比（**Zipf 定律**）；而且语言一直在变（Merriam-Webster 第 12 版新增 5k 词，包括 "rizz"）。
7. 【slides】p20：**死因②OOV（未登录词）**——两个补丁：① 用正则/规则预处理（改拼写）；② 用一个 `UNK` 代表所有未知词（后果是**大量词被映射成 UNK**）。

### C. 字符/字节级分词（3 条）

8. 【slides】p21：token = 文本里的单个字符/字节。**注意字节 ≠ 字符**：`😀` = 1 字符 4 字节，`地` = 1 字符 3 字节。
9. 【slides】p21：**优点**：词表小、**完全覆盖输入（无 OOV）**、能直接看到拼写。代表模型：CharBERT、CANINE、Charformer、ByT5。
10. 【slides】p21：**缺点**：**序列非常长**；"更难构建高层表示"（slides 自己标了 debatable）。

### D. 子词与三种算法（4 条）

11. 【slides】p22：子词的出发点——**用数据和算法来定义词表**（用"相邻文本片段的语料频次统计"），而不是人工定；大多数切分**和语言学不对齐**（如 `Milky`、`looked`）。
12. 【slides】p23：**BPE**（Sennrich et al., 2016）：从单个字节开始，**迭代合并相邻 token**。**WordPiece**（Wu et al., 2016）：类似 BPE，但每次合并**使数据似然最大**的那对。**Unigram LM**（Kudo, 2018）：**从一个大词表开始，逐步丢弃 token** 直到目标大小。
13. 【slides】p24：**BPE 是所有前沿 LM 用的算法**；由 **GPT-2 普及**，OpenAI 立了标准；理由是"简单、易实现、高效、**确定性**"。词表大小表：Gemini 2.x/Gemma3 262k、Gemini1.x/Gemma2 256k、Llama4 201k、GPT-4o/GPT-5/o1/o3 200k、Kimi K2 163k、Qwen2.5/Qwen3/GLM-4 151k、Grok2/Longcat 131k、Llama3/DeepSeek v3·R1 128k、DeepSeek v2.5 100k。
14. 【slides】p56：**SentencePiece**（Kudo & Richardson, 2018）是一个**库（不是算法）**，实现了 BPE 和 Unigram LM；**把空格当成词表里的基本符号**；被 T5、Llama 2、XLM-R、Gemma 等用。**SuperBPE**（Liu et al., 2025）：先学子词、再放开空格约束学"superword" token。

### E. BPE 训练与推理（5 条）

15. 【slides】p25：**训练算法**：① 按空格预分词；② 词表初始化为 D 中的字节；③ 把 D 转成 token 序列；④ 当 |V|<N：数所有相邻对的频次 → 合并最高频的那对为新 token $v_{n}=v_iv_j$（$n=|V|+1$）→ 把 D 里所有该对替换成 $v_n$。
16. 【slides】p30–53：**完整 walkthrough**（语料 "Peter Piper picked a peck of pickled peppers"）：初始对频次 `_+p 4, p+e 4, c+k 3, e+r 3, …`；合并顺序 `_+p→_p`、`c+k→ck`、`e+r→er`、`_p+e→_pe`、`_p+i→_pi`、`_pi+ck→_pick`。
17. 【slides】p54：**推理（编码新文本）**：把词切成字节，**按顺序套用合并规则**。例 `_pier` → 字节 `_ p i e r` → 套 merge1 `_p i e r` → 套 merge3 `_p i er` → 套 merge5 `_pi er`。
18. 【slides】p57：子词分词**没有解决所有问题**。它做到了：是简单有效的**压缩算法**、**无 OOV**、有共享表示（picked / picking 共享）。
19. 【slides】p55：官方给了 tiktokenizer 在线 demo（`https://tiktokenizer.vercel.app/`）——**本课不跑它**（本机不下载词表、不用 tiktoken）。

### F. 分词的翻车案例（4 条）

20. 【slides】p58–59：**拼写**：模型看到的是子词块，不是字符——GPT-2 里 `strawberry → ["str","aw","berry"]`，GPT-4o 里整词一个 token；**两者都数不出 r 的个数**。子词模型的系统弱点还包括：拼读、**反转字符串**、**对拼写错误的鲁棒性**（改一个字符会移动所有合并边界）。
21. 【slides】p60–61：**glitch token**：tokenizer 和 LM 的训练语料可以不一致，某些 token 进了词表却几乎没在 LM 训练里出现 → embedding 随机初始化/训练不足 → 未定义行为。名例 `SolidGoldMagikarp`（一个在 tokenizer 语料里过采样的 Reddit 用户名）。
22. 【slides】p61：glitch token 不只是奇观：**浪费词表槽位 + 提供对抗攻击面**；结论："**别用和 tokenizer 不同的数据训模型**"。
23. 【slides】p59：分区结论——**模型的语言原子是子词、不是字符**；任何字符级任务都在逼模型"反推"token 里没有显式包含的信息。

### G. 多语言与不均衡（6 条）

24. 【slides】p62/70：**同一个 ChatGPT tokenizer，不同语言 token 数不同**：English 21 tokens / 75 chars、French 27/95、Somali 30/88、**Thai 36/79**。
25. 【slides】p63–64：世界有 **7000+ 语言**；约 20% 人口说英语，但只有约 **5% 是母语者**；**Common Crawl 里 40–45% 是英文**；许多低资源语言（Tagalog、Amharic、Yoruba）**占比 <0.01%**。
26. 【slides】p66：**多语言 LM 架构上和普通 LM 完全一样**（同样的 Transformer、同样的训练目标），**唯一区别是用多语言数据训 tokenizer 和 LM**。代表：mBERT 2018/104 语、XLM-R 2020/100、mT5 2021/101、BLOOM 2022/46。
27. 【slides】p67：**跨语言迁移**（cross-lingual transfer）：在一种语言（如英语）有标注数据上微调，能在**没微调过**的语言上做任务。XLM-R 三段：多语言 MLM 预训练（2.5TB CommonCrawl/100 语）→ 英语微调 → 任意语言零样本推理。
28. 【slides】p68–69：**词表重叠促进迁移**（重叠 > 不重叠，越多越好；连"假朋友"都有帮助）——但**多语言诅咒（curse of multilinguality）**：加入更多语言在**固定模型容量**下会让每种语言分到的份额变小；XNLI 上 XLM-R 从 **71.8%（7 语）掉到 67.7%（100 语）**。XLM-V 把词表扩到 1M（4× XLM-R）覆盖更好但**效率代价显著**。
29. 【slides】p71：**分词在语言之间引入不公平**：① 分词**可能和预训练数据量同等重要**（Rust et al., 2021）；② 等义文本的 token 长度差异**最高 15 倍**（Petrov et al., 2023）；③ 商业 API **对非英语用户多收费**——22 种类型学多样语言的分析（Ahia et al., 2023）：花更多钱、拿更差结果，且用户常来自 API 更贵的地区。**subword fertility = 每词平均子词 token 数**，它与下游性能**强负相关**。

### H. 回到字符/字节级（3 条）

30. 【slides】p72：多语言可能是**重访字符/字节级**的理由——CANINE（Google 的字符级 mBERT）覆盖**整个 Unicode 字母表**，因此能处理它**从没见过的语言**。
31. 【slides】p73：字符/字节模型也能更高效地处理长序列——**MrT5**（Kallini et al., 2025b）用**可学习的删除门**动态缩短序列，并**学到语言特定的压缩**。
32. 【slides】p74–75：一大批字节级新架构（H-Nets、Byte Latent Transformer、Hierarchical AR Transformers、Bolmo、EvaByte）；字符/字节级还能解决子词的其他问题：**无 glitch token、对字符级扰动鲁棒、能直接观察词的字符组成**。**潜在分词（latent tokenization）**：让模型自己在架构里学"有意义的单位"。

## §5 术语索引

按首次出现的篇排。`01` 篇零前置，`02` 篇是本知识点核心概念，`04` 篇才需要推导背景。

| 术语 | 一句话解释 | 出处 |
|------|-----------|------|
| **token** | 语言模型处理的基本单位（不是"词"） | `01` §2 |
| **tokenizer** | 在文本与 token 序列之间双向翻译的程序 | `01` §2 |
| **词表（vocabulary）** | 所有已知 token 的集合 | `01` §2 |
| **OOV（未登录词）** | 不在词表里的词，词级分词绕不开 | `01` §3 |
| **Zipf 定律** | 词频与其频次排名成反比（长尾的来源） | `01` §3 |
| **词素（morpheme）** | 有意义/语法功能的最小单位（look + ed） | `01` §3 |
| **子词（subword）** | 词或词的一部分，落在词与字符之间 | `01` §4 |
| **BPE（字节对编码）** | 从字节起、迭代合并最高频相邻对 | `02` §4 |
| **合并列表（merge list）** | 训练得到的"合并规则 + 顺序"，推理时按序套用 | `02` §4 |
| **WordPiece** | 合并使数据似然最大的那对（BERT 用） | `02` §5 |
| **Unigram LM** | 从大词表逐步丢弃 token 到目标大小 | `02` §5 |
| **SentencePiece** | 实现 BPE/Unigram 的**库**，空格是基本符号 | `02` §5 |
| **字节级 BPE** | 在 UTF-8 字节上做 BPE，天然无 OOV（GPT-2） | `02` §6 |
| **预分词（pre-tokenization）** | 正式合并前先按空格/规则切块 | `02` §4 |
| **glitch token** | 进了词表却几乎没被 LM 训练的 token | `02` §7 |
| **subword fertility** | 每词平均被切成几个子词 token | `02` §8 |
| **高/低资源语言** | 数字文本与标注数据多 / 稀缺 | `02` §8 |
| **跨语言迁移** | 一种语言微调、另一种语言零样本可用 | `02` §8 |
| **多语言诅咒** | 固定容量下语言越多，每种分到的越少 | `02` §8 |
| **合并频次口径** | 相邻对在语料里出现的（加权）次数，决定合并顺序 | `04` §1 |
| **合并顺序的确定性** | 频次并列时的打破规则（本课：token 字典序） | `04` §1 |
| **压缩率** | 原生字节数 / token 数，衡量 tokenizer 省不省 | `04` §3 |
| **embedding 规模** | $|V|\times d$，词表越大越大 | `04` §3 |
| **字节级回退** | 未知字符退回按 UTF-8 字节表示 | `04` §5 |
| **潜在分词** | 让模型在架构里自学单位（字节级模型的延伸） | `04` §5 |
