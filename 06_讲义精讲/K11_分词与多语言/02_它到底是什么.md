# K11 · 02 它到底是什么

> **进这一篇之前你能说出什么**：① 分词是训练前定死的一步，决定序列长度和参数量；② 按词切死在词表爆炸/OOV；③ 按字符切死在序列长度，所以要一个折中。
> **这一篇回答什么**：token / tokenizer / 词表到底是什么？"什么是词"为什么难？BPE 具体在做什么（手算一遍）？BPE、WordPiece、Unigram 差在哪？字节级、glitch token、fertility 各是什么？

> 1. token / tokenizer / 词表 的确切含义，以及"词"这个粒度为什么不可靠

**这一篇不推公式、不跑代码。** 所有算例都小到能手算。给的定义式（fertility、压缩率）只是把话写成符号，**不往下推**——推导都在 `04`。

## §1 三个词：token / tokenizer / 词表

【slides】p8 把这三个词定死了：

| 词 | 定义 | slides 原话 |
|----|------|------------|
| **token** | 语言模型处理的**基本单位** | "The fundamental units of language are tokens" |
| **tokenization** | 把文本切成 token 的**过程** | "the process of breaking text into tokens" |
| **tokenizer** | 在"文本 ↔ token 序列"之间**翻译**的东西 | "translates between text and a sequence of tokens" |
| **词表（vocabulary）** | **所有已知 token 的集合** | "the set of known tokens" |

**两个方向**（p15）：
- **encode**（编码）：文本 → token 序列（如 `[2167, 10802, 540, 290, 10282, 5781, 0]`）；
- **decode**（解码）：token 序列 → 文本。

**token 长什么样？** 完整链条是（p8–p14）：

```
文本  --tokenizer.encode-->  token ID 序列  --查 embedding 矩阵-->  向量序列  -->  模型
模型  --输出向量-->  token ID  --tokenizer.decode-->  文本
```

**关键的三个"注意"**（后面 `03` 会实测到）：

1. **token ≠ 词。** 一个词可能是一个 token，也可能是几个 token 拼起来（`looked → look + ed`），甚至几个词是一个 token。
2. **token ID 是整数**，来自词表里的位置；**embedding 矩阵的行数 = 词表大小**（p17）。
3. **分词是预处理**（p15），模型不学它——**先定切法，再训模型**。

> **术语**：最初的 token 序列（切分之前）通常先经过一步 **预分词（pre-tokenization）**——先按空格/标点把文本切成块，再在块内部做后面的合并（`02` §4）。slides p27 的例子就是"先按空格切"。

## §2 "什么是词"：这个粒度本身就不稳

【slides】p5 让全班数一句话有几个词：

```
We'd sat back on the grass, and time flew by as we looked at the Milky Way.
```

答案不是唯一：
- **按空格**：17 个词 + 2 个标点；
- 但 `We'd` = `we + had`，算 1 个还是 2 个？
- `looked` = `look + -ed`，`-ed` 看着挺重要；
- `Milky` = `milk + -y`。

【slides】p6 引入 **词素（morpheme）**：**有意义或语法功能的最小单位**。同一句话按词素数：

| 词 | 词素拆解 | 个数 |
|----|---------|------|
| `We'd` | we + had | 2 |
| `looked` | look + -ed | 2 |
| `Milky` | milk + -y | 2 |
| `sat` | sit + -ed（不规则） | 还是 1 个？ |
| `flew` | fly + -ed（不规则） | 还是 1 个？ |
| `Milky Way` | 是一个实体 | 但三个词素？ |

**这一段要你记住的**（【slides】p7）：切分文本的方式有很多种——**字符、词素、词、短语**——**没有哪一种天然"对"**。对语言模型而言，"最好"的切法**不由语言学决定，而由统计和成本决定**。

> **【直觉】`Milky Way`（银河）是一个概念，但字面是 milk + -y + way 三个词素。** 你按哪种粒度切，模型就按哪种粒度理解——**粒度选错，模型连"这是一个实体"都难学出来。**

## §3 三种粒度的取舍（把 `01` 的话收拢）

| 粒度 | token = | 词表 | OOV | 序列长度 | slides |
|------|---------|------|-----|---------|--------|
| **词级** | 一个词（+标点） | 巨大（长尾） | 有 | 短 | p18–20 |
| **字符/字节级** | 一个字符/字节 | 极小 | **无** | **很长** | p21 |
| **子词** | 词或词的一部分 | 可控 | 基本无 | 中等 | p22–24 |

slides p21 提醒的字节/字符区别要记住：**`😀` = 1 字符 4 字节；`地` = 1 字符 3 字节。** 后面 `04` §5 讲"字节级回退"时会用到这个数字。

【slides】p22–23 的结论：**子词分词 = 用数据 + 算法来定义词表**。算法看的是"相邻文本片段的语料频次统计"，所以**切分通常和语言学不对齐**。

## §4 BPE 在做什么（手算，用 slides 的语料）

**这是这一篇的核心。** 【slides】p25 的训练算法，四步：

```
需要：训练语料 D、目标词表大小 N
1. 按空格预分词
2. 词表 V 初始化为 D 中出现的单个字节
3. 把 D 转换成 token 序列（即字节序列）
4. 当 |V| < N：
   a. 数 D 里所有相邻对的频次
   b. 合并最高频的那一对 (v_i, v_j) 成新 token v_n = v_i v_j
   c. 把 D 里所有 v_i v_j 替换成 v_n
```

**一句话记住**：**从字节开始，每次把"最常挨在一起的两个符号"粘成一个新符号。**

### 4.1 语料与初始状态（p26–p30）

语料（slides 原文）：

```
Peter Piper picked a peck of pickled peppers
```

预分词后（`_` 表示词前的空格，p27）：

```
Peter | _Piper | _picked | _a | _peck | _of | _pickled | _peppers
```

**词表初始化为出现的单字符**（p28）：

```
{ _, a, c, d, e, f, i, k, l, o, p, P, r, s, t }   （15 个）
```

数所有**相邻对**的频次，降序（p30）：

| 对 | 频次 |
|----|------|
| `_` + `p` | 4 |
| `p` + `e` | 4 |
| `c` + `k` | 3 |
| `e` + `r` | 3 |
| `e` + `d` | 2 |
| `i` + `c` | 2 |
| `p` + `i` | 2 |
| …（一堆 1） | 1 |

### 4.2 迭代合并（p31–p53）

最高频是 `_+p` 和 `p+e`，都是 4（**并列**）。slides 选了 `_+p`。合并后：

```
merge 1: _ + p -> _p
```

**每次合并后都要重数频次**，因为 token 变了。接下来（slides 的顺序）：

```
merge 2: c + k  -> ck
merge 3: e + r  -> er
merge 4: _p + e -> _pe
merge 5: _p + i -> _pi
merge 6: _pi + ck -> _pick
```

merge 6 之后语料变成（p52）：

```
P e t er | _ P i p er | _pick e d | _ a | _pe ck | _ o f | _pick l e d | _pe p p er s
```

**这就是 BPE 的全部**：`_pick` 之所以能诞生，是因为 `_picked` / `_pickled` 里 `_pi` 和 `ck` 老是挨着——**统计出来的，不是语言学规则。**

> **术语**：训练得到的这一串规则 + **顺序**，叫 **合并列表（merge list）**。顺序不能乱——第 6 条依赖第 5 条的产物。

### 4.3 推理：编码一个新词（p54）

**关键区别**：推理时**不重新统计**，只把训练好的合并列表**按顺序套一遍**。

slides 的例子（p54），编码 `_pier`：

```
输入词:  _pier
字节:    _ p i e r
套 merge1 (_+p):   _p i e r
套 merge3 (e+r):   _p i er
套 merge5 (_p+i):  _pi er
结果:    _pi | er   （2 个 token）
```

> **【直觉】训练是"编字典"，推理是"查字典"。** 字典（合并列表）一旦编好就固定了；新词进来，只是一条条对照规则往上套。`03` §1 会实测到这个过程，结果和 slides **逐位一致**。

### 4.4 一个 8 词英文句子怎么切（本课的手算练习）

假设已有合并列表 `[_+p, c+k, e+r, _p+e, _p+i, _pi+ck]`（就是上面那 6 条），要编码：

```
We looked at the Milky Way and time flew.
```

预分词 → 8 个块（`We / _looked / _at / _the / _Milky / _Way / _and / _time / _flew.`，实际是 8 词 + 句点）。逐块套规则：

| 块 | 字节 | 有规则命中吗 | 结果 token 数 |
|----|------|-------------|--------------|
| `We` | W e | 无 | 2 |
| `_looked` | _ l o o k e d | 无（没有 `_l`/`oo`/`ke` 等规则） | 7 |
| `_at` | _ a t | 无 | 3 |
| `_the` | _ t h e | 无 | 4 |
| `_Milky` | _ M i l k y | 无 | 6 |
| `_Way` | _ W a y | 无 | 4 |
| `_and` | _ a n d | 无 | 4 |
| `_time` | _ t i m e | 无 | 5 |
| `_flew.` | _ f l e w . | 无 | 6 |

**结果：39 个 token（还没算句点）**——比"9 个词"碎得多。

**这屏要说明什么**：**BPE 只认"合并列表里有的对"**。上面这份合并列表是在 "Peter Piper" 那种语料上学出来的，放进另一段英文就几乎**全部不命中**——**分词结果高度依赖训练语料**。这正是 §8 多语言不均衡的机制源头：

> **语料里没统计到的组合，就永远合并不了，只能碎成字节。**

（`03` §2/§4 会用真的分词器把这件事量化：中文和未登录词被切碎。）

## §5 三种子词算法差在哪（【slides】p23）

| 算法 | 一句话 | 方向 | 代表 |
|------|--------|------|------|
| **BPE** | 从单个字节起，**迭代合并相邻 token**（最高频） | 由小到大 | GPT-2/3/4、Llama、DeepSeek…（p24 一整个表） |
| **WordPiece** | 类似 BPE，但合并**使数据似然最大**的那一对 | 由小到大 | BERT |
| **Unigram LM** | **从一个大词表开始**，逐步**丢弃** token 到目标大小 | 由大到小 | 部分多语言模型 |

**共同点**：都是"用统计决定词表"，不是人工定。
**差别**：
- BPE / WordPiece 都是**从小到大**合并，区别只在"选哪一对"的判据（**频次** vs **似然增益**）；
- Unigram **从大到小**删——先假设所有可能的子串都在词表里，再删掉贡献小的。

【slides】p24 强调 **BPE 是事实标准**，理由是"**简单、易实现、高效、确定性**"（simple / easy to implement / efficient / deterministic）。p24 还给了主流模型的词表大小（Gemini3 262k、GPT-4o 200k、Llama3/DeepSeek 128k……），**越大越能装长 token**，但 embedding 矩阵也越大。

【slides】p56 补一个常被搞混的点：

> **SentencePiece 不是算法，是库。**

它**实现了** BPE 和 Unigram LM 两种算法，另外做了一件事：**把空格也当成词表里的基本符号**（这样"词前空格"不再靠 `_` 手工标记）。T5、Llama 2、XLM-R、Gemma 都用它。

> **术语预告**：`04` §2 会讲清楚"WordPiece 的似然"和"Unigram 的丢谁"具体怎么算——那需要公式，属于深潜篇。

## §6 字节级 BPE：为什么它"没有 OOV"

BPE 有两条路线：

| 路线 | 起点 | OOV |
|------|------|-----|
| **字符级 BPE** | 字符做起始 token | 词表外的字符编不了 |
| **字节级 BPE** | **UTF-8 字节**做起始 token（256 个） | **无**——任何字符都能写成字节 |

【slides】p24 说 BPE 由 **GPT-2 普及**，GPT-2 用的就是**字节级**。

**为什么字节级没有 OOV**：任何 Unicode 字符都能编码成 UTF-8 字节（`地` = 3 字节，`😀` = 4 字节）。初始词表就是 256 个字节值，**覆盖所有可能输入**。遇到从没见过的字符，它最坏也就是**退回成它的几个字节**。

> **【直觉】这就像"任何字符都能用 ASCII 转义写出来"。** 你不用认识那个字符，只要能写出它的字节，就能表示它。

代价（`03` §4 实测）：**没见过的字符会被切成好几个 byte-token**——中文一个字 3 个，emoji 一个 4 个，序列就是这么被拉长的。

## §7 glitch token：tokenizer 和 LM 的语料错位

【slides】p60–61：**tokenizer 和 LM 可以用不同的语料训练**。于是可能出现：

- 某个 token **进了词表**，却几乎没在 **LM 训练数据**里出现过；
- 它的 embedding 要么随机初始化、要么训练不足 → **未定义行为**。

名例（p61）：`SolidGoldMagikarp`——一个在 **tokenizer 语料**里过采样的 Reddit 用户名。GPT-3 被要求复述/解释这个 token 时，会**幻觉成 "distribute"**、回避问题或复述失败。

【slides】p61 的结论是：glitch token 不只是趣闻——它**浪费词表槽位 + 提供对抗攻击面**。一句话纪律：**别用和 tokenizer 不一样的数据训模型。**

> **【直觉】这就像"字典里有个词条，但词义是空的"。** 你按主键能查到这一行，可这一行从没被填过值——模型拿到它，只能瞎猜。

## §8 多语言不均衡与 fertility

【slides】p62 用**同一个 ChatGPT tokenizer**切不同语言，结果是：

| 语言 | tokens | chars |
|------|--------|-------|
| English | 21 | 75 |
| French | 27 | 95 |
| Somali | 30 | 88 |
| **Thai** | **36** | **79** |

**同样的意思，泰国语用了最多的 token，字符却不多。** 这就是不均衡的直观样子。

**为什么**：训练语料极度偏斜——**Common Crawl 里 40–45% 是英文**，而许多低资源语言占比 **<0.01%**（p64）。BPE 只合并"统计上常见"的组合；低资源语言的组合统计不到 → 合并不了 → 被切成更多碎片。

两个关键概念：

| 术语 | 定义 |
|------|------|
| **高/低资源语言** | 数字文本 + 标注数据/工具多 / 稀缺（p64） |
| **subword fertility** | **每词平均被切成几个子词 token**（p71） |

【slides】p71 记了三条硬结论：
- 分词**可能和预训练数据量同等重要**（Rust et al., 2021）；
- 等义文本的 token 长度差异**最高 15 倍**（Petrov et al., 2023）；
- **fertility 与下游性能强负相关**——切得越碎，效果越差。商业 API 因此**对非英语用户多收费**（Ahia et al., 2023：22 种语言分析）。

> **这条直接砸到你的方向**：方言 / 低资源语言在 **tokenizer 这一步**就先吃亏——还没开始训练，输入就已经比英语长、比英语碎。`04` §4 会把这个链条讲透，`05` §3 给对策。

## §9 到这里，整条链是这样的

```
文本  --预分词（按空格等）-->  块
块    --BPE 合并规则（按顺序套）-->  token 序列
token --查词表-->  ID 序列  --查 embedding-->  向量序列  -->  模型
```

**这条链上每一步的代价**：

| 环节 | 定死的量 | 代价落到谁头上 |
|------|---------|---------------|
| 预分词 | 什么叫"一个块" | 无空格语言（中/日/泰）吃亏（p56） |
| 合并规则 | 词表内容 | 语料占比低 = 被切碎（p71） |
| 词表大小 | embedding 规模 | 词表大 → 序列短但显存涨（p16–17、`04` §3） |
| 训练语料 | glitch token | tokenizer 与 LM 不一致就出怪 token（p61） |
