## §1 参数与形状卡

| 符号 | 含义 | 典型取值 / 本课实测 |
|------|------|---------------------|
| $V$（词表） | 所有已知 token 的集合；$\|V\|$ = 词表大小 | 主流 LM **100k–262k**（p24）；本课玩具 **15–243** |
| $D$ | 训练语料，表示成 $\{(w^{(i)}, f_i)\}$（块 + 频次） | 本课 §1 是 8 个块、$f_i=1$ |
| $N$ | 目标词表大小（**上界**，`while |V|<N`） | 本课扫 0–800 merges |
| $M$ | **合并列表**（有序！）：$[(a_1,b_1),\dots]$ | 本课 §1 共 6 条 |
| $d$ | 嵌入维度 | 主流 4k 量级；本课无关 |
| $C$ | 一段文本的**字符数** | 本课 §3 测试句 **55** |
| $T$ | 它的 **token 数** | 本课 §3：**55 → 17** |
| $T/C$ | **tokens/char**（切得多碎） | 英文 0.286 / 中文 0.500 / 未见过中文 3.000 |
| $\mathrm{comp}$ | **压缩率** $=C/T$（跟 $T/C$ 互为倒数） | 本课 §3：1.0 → **3.24** |
| $F$ | **fertility**（每词平均子词数） | slides p71；本课未按"词"口径实测 |
| 初始词表 | 字节级 = **256 个字节值**；字符级 = 字符集 | 本课 §2 语料实际出现 **50** 个字节 |
| 参数量（嵌入） | $\|V\|\cdot d$（+ 输出层若共享则不加） | 见 §2 |
| 算力（注意力） | $\sim T^2 d$（K04 的 $O(n^2)$） | 见 §2 |

**一次性对齐形状**：

| 对象 | 规则 |
|------|------|
| token ID | 整数，取值范围 $[0,\ \|V\|-1]$ |
| embedding 矩阵 | 行数 = $\|V\|$（p17）；`ID → 该行` |
| 编码（train 后推理） | 输入词 → **按 $M$ 顺序套** → token 序列（**不重统计**） |
| 训练（BPE） | 每轮：**数相邻对 → 合并最高频 → 替换 → 重数**，直到 $\|V\|=N$ |

## §2 公式速查

**相邻对频次**（【slides】p25 第 4a 步的形式化）：

$$\mathrm{cnt}(a,b)=\sum_{i} f_i\cdot \#_{ab}\big(w^{(i)}\big)$$

**BPE 合并准则**（【slides】p25 第 4b 步）：

$$(a^{*},b^{*})=\arg\max_{(a,b)}\ \mathrm{cnt}(a,b),\qquad v_{n}=a^{*}b^{*}\quad(n=|V|+1)$$

**并列打破**（【slides】没写，【工程】本课采用）：频次并列时取 **token 字典序**最小者（`'_' < 'p'` → 选 `_+p`）。

**BPE 编码**（【slides】p54）：按合并列表 $M$ **严格按顺序**、从左到右贪心替换，**不重新统计频次**。

**WordPiece 打分**（【非 slides】，Wu et al. 2016）：

$$\mathrm{score}(a,b)=\frac{\mathrm{cnt}(ab)}{\mathrm{cnt}(a)\cdot \mathrm{cnt}(b)}$$

**Unigram LM 目标**（【非 slides】，Kudo 2018）：$P(X)=\prod_{x\in \mathrm{seg}(X)}p(x)$，$\mathcal{L}=\sum_{X\in D}-\log P(X)$；**删掉 $\mathcal{L}$ 涨幅最小的 token**，重复到 $\|V\|$ 达标。

**压缩率**（【定义】）：

$$\mathrm{compression}=\frac{C}{T}=\frac{1}{\text{tokens/char}}$$

**fertility**（【slides】p71）：

$$F=\frac{1}{N_{\text{words}}}\sum_{i=1}^{N_{\text{words}}}\#\text{tokens}(w_i)$$

**成本两组**（【非 slides】标准分析）：

$$\text{嵌入参数}=|V|\cdot d,\qquad \text{注意力}\sim T^2 d,\qquad \text{总代价}\propto |V|d+\frac{C^2 d}{\mathrm{comp}^2}$$

**UTF-8 字节数**（【定义】）：ASCII **1** 字节、常用汉字 **3** 字节、emoji **4** 字节。

## §3 踩坑点

| # | 坑 | 怎么认出来 | 怎么修 |
|---|----|-----------|--------|
| 1 | **把 token 当"词"** | 以为"一句话 8 个词 = 8 个 token" | token 是**模型的基本单位**，可粗可细（p8）。本课实测：8 词英文句在"只学过 Peter Piper"的分词器下要 **39 个 token**（`02` §4.4） |
| 2 | **以为推理也重新统计频次** | 疑惑"推理为什么这么快" | 推理 = **按合并列表查表套规则**，不碰语料（p54、`04` §1.5）。这也是 BPE "deterministic" 的来源（p24） |
| 3 | **以为 BPE 有全局最优** | 期望"再调调词表就能最短" | BPE 是**贪心**：每步只选当前最高频对、不回头（`04` §1.6）。它便宜、确定、够好，但没有最优性保证 |
| 4 | **忽略"并列打破"规则** | 换了实现，合并列表/ID 全对不上 | 频次并列必须显式定义（本课=字典序，`03` §2 与 slides 一致）。**规则不同 = tokenizer 不同 = 下游全失效**（`04` §1.4） |
| 5 | **把字符数当字节数** | 算 emoji/中文的 token 数算少 | `😀`=**4** 字节、`地`=**3** 字节（p21）。本课实测 `😀 → 4 tokens`、`地球 → 5 tokens`（`03` §5） |
| 6 | **以为"无 OOV"就等于没问题** | 字节级很美好 | 无 OOV 的代价是**被切碎**（3 字节/字）。同一句中文，分词器没见过 → **3.000 tokens/char**（`03` §3） |
| 7 | **以为词表越大越好** | 只看序列变短 | 词表大 → **embedding 矩阵 $\|V\|\cdot d$ 变大**、softmax 变大（p16–17、`04` §3）。这是权衡，不是单调最优 |
| 8 | **以为 200k 词表能救低资源语言** | "槽位够多啊" | 合并预算被**高频语言**吃掉；token 数在 200 merges 后**饱和**（本课 `03` §4）。低资源语言要的是**语料配比 + 覆盖**，不只是上限 |
| 9 | **用和 tokenizer 不同的语料训 LM** | 出现怪 token / 复述失败 | 这就是 **glitch token**（p60–61，`SolidGoldMagikarp`）。纪律：**tokenizer 和 LM 用同一份数据** |
| 10 | **以为微调时能顺手改 tokenizer** | 想"加几个方言 token" | 改 tokenizer = **换主键**，embedding 行全对不上；要改就得**重训 tokenizer + 重新对齐 embedding**（`03` §6） |
| 11 | **把高 fertility 归罪于语言本身** | "泰语就是 token 多" | 是**语料占比**决定的（p64：Common Crawl 40–45% 英文、低资源 <0.01%）。改配比/覆盖才有用（`04` §4） |

### 答案要点

<details>
<summary>展开</summary>

1. 模型只吃数字，需要"字符串 → 一串 embedding"的映射（p9）。**token**=模型处理的基本单位（不一定是词）；**tokenizer**=在文本与 token 序列间双向翻译；**词表**=所有已知 token 的集合（p8）。完整链见 `02` §1。
2. 切分粒度有**字符 / 词素 / 词 / 短语**（p7），"最好"由统计和成本定、不由语言学定。例：`We'd`=we+had（1 或 2 个词？）、`looked`=look+-ed、`Milky`=milk+-y、`sat/flew` 不规则（算不算 2 个词素？）、`Milky Way` 是一个实体却是三个词素（p5–p6）。见 `02` §2。
3. ① **词表爆炸 + 长尾**：Zipf 定律让不同词无限增长，且语言一直在变（Merriam-Webster 第 12 版 +5k 词，含 "rizz"）→ 词表关不住（p19）。② **OOV**：测试时一定有没见过的词；补丁只有"规则预处理"或"全映射成 UNK"，后者把信息压光（p20）。
4. 解决：词表小、**完全覆盖无 OOV**、能直接看到拼写（p21）。引入：**序列非常长**（注意力 $O(n^2)$ 被拉爆），且"更难建高层表示"（slides 自标 debatable）。`😀`=1 字符 **4 字节**；`地`=1 字符 **3 字节**（p21）。
5. 【slides】p25：① 按空格预分词；② 词表初始化为 D 中的单字符/字节；③ 把 D 转成 token 序列；④ 当 $\|V\|<N$：数所有相邻对频次 → 合并最高频对为新 token → 把 D 里该对替换掉。**重数**是因为合并改写了语料，旧频次表失效；`_pi+ck→_pick` 只在 `_p+i→_pi` 之后才可能存在（`04` §1.5）。
6. **训练**：数语料、选对、改写语料、重数（要看数据）。**推理**：只把合并列表**按顺序套一遍**，不重新统计（p54、`03` §2）。所以推理极快、确定。
7. **WordPiece**：方向同 BPE（由小到大合并），但选 **score=$\mathrm{cnt}(ab)/(\mathrm{cnt}(a)\mathrm{cnt}(b))$ 最大**的对（似然比，归一化掉单词频率），BERT 用。**Unigram**：**由大到小**，从过完备词表用 EM 估计概率、**删掉使损失涨幅最小的 token**（p23、`04` §2）。**SentencePiece 是库不是算法**，实现了 BPE 和 Unigram，且把**空格当基本符号**（p56）。
8. tokenizer 和 LM 可以用**不同语料**训练：某 token 进了词表却几乎没在 LM 数据里出现 → embedding 随机/欠训练 → 未定义行为（p60–61）。名例 `SolidGoldMagikarp`（tokenizer 语料里过采样的 Reddit 用户名）。它**浪费词表槽位 + 提供对抗攻击面**——纪律是"别用和 tokenizer 不同的数据训模型"。
9. **fertility = 每词平均被切成的子词 token 数**（p71）。它与**下游性能强负相关**：切得碎，模型更难从碎片拼出语义（p71）。
10. 根因是**语料占比**：BPE 选 $\arg\max\mathrm{cnt}$，而 cnt 是语料加权频次；占比低 → 相邻对频次低 → **永远排不上合并** → 只能保留字节（`04` §4.2）。本课最小实验：中文占比 0.60% → 0.500 tokens/char；0% → **3.000**（`03` §3）。
11. $\mathrm{cnt}(a,b)=\sum_i f_i\cdot\#_{ab}(w^{(i)})$。$f_i$ 是块 $w^{(i)}$ 在语料里的出现次数；$\#_{ab}$ 是这对在**该块内部**出现的次数。乘起来再对所有块求和（`04` §1.2）。
12. $(a^*,b^*)=\arg\max\mathrm{cnt}(a,b)$，$v_n=a^*b^*$。**必须定义并列打破**：多个对频次相同时选谁没有唯一答案，slides 只是**选了** `_+p`（p30–32）却没给规则；不定义规则 → 不同实现产出不同合并列表/ID → 下游全对不上（`04` §1.4）。
13. (a) **15** 个字符（`P _ a c d e f i k l o p r s t`）。
    (b) `_+p` = **4**（`_picked`/`_peck`/`_pickled`/`_peppers` 各 1）；`p+e` = **4**（`Peter`/`_peck`/`_peppers`/`_Piper`… 数每个块内相邻）；`c+k` = **3**；`e+r` = **3**。
    (c) merge1 `_+p→_p`（4，并列取字典序）；merge2 `c+k→ck`（3）；merge3 `e+r→er`（3）。**实测与 slides 逐位一致，`一致: True`**（`03` §2）。
14. `_pier` → 字节 `_ p i e r` → 套 `_+p`：`_p i e r` → 套 `e+r`：`_p i er` → 套 `_p+i`：`_pi er` → 结果 **`_pi | er`（2 tokens）**。其余规则不命中。与 slides p54 一致（`03` §2）。
15. $F=\frac{1}{N_{\text{words}}}\sum_i\#\text{tokens}(w_i)$；$\mathrm{compression}=C/T=1/(\text{tokens/char})$。本课 §3：tokens/char 1.000 → 0.309，即压缩率 1.0 → **3.24**。
16. 序列长度 $T$ **减小**（同样字符 $C$ 用更少 token），嵌入参数 $\|V\|\cdot d$ **线性增大**。权衡：$\text{总代价}\propto |V|d + \dfrac{C^2 d}{\mathrm{comp}^2}$——词表涨使第一项涨、第二项降，**存在折中点且取决于你更缺显存还是更缺上下文**（`04` §3.2）。
17. **正常**。根因在 **tokenizer 的训练语料**这一层：分词器没见过中文 → 每个汉字退回 3 个 UTF-8 字节 → 6 字 = 18 token（3.000 tokens/char）。不是模型、不是推理 bug（`03` §3）。
18. 因为词表变大 → **embedding 矩阵 $\|V\|\cdot d$ 变大**（输出层若不共享再加一份），这部分参数涨得比序列省下的算力多。**这是 §3 那组权衡的直接表现**（p16–17、`04` §3.1）。
19. 先怀疑 **tokenizer**：模型看到的是**子词块**不是字符（p59），GPT-2 里 `strawberry → ["str","aw","berry"]`，数不出 r 的个数；GPT-4o 整词一个 token 也数不出——**分词粒度决定了模型有没有字符级信息**。见 `02` §7 / `00` §3.F。
20. **不能"顺手加"**。tokenizer 是训练前定死的预处理（p15），改它 = 换主键 → 所有 embedding 行对不上、旧 token ID 全失效。要加就得**重训 tokenizer（或扩表）+ 重新对齐/重训 embedding**，成本很高（`03` §6）。
21. 重复/失忆/复述失败是 **glitch token** 的典型症状：该 token 的 embedding 从没被正常训练过（tokenizer 与 LM 语料错位），模型拿到它只能瞎猜（p60–61）。
22. **不是"设计得差"，是语料分布的结果**。Common Crawl 里 40–45% 是英文、低资源语言 <0.01%（p64），BPE 的合并预算被高频语言占据；泰语的相邻对排不上号 → fertility 高（`04` §4）。这是**结构性偏差 + 公平性问题**（p71：等义文本 token 长度差最高 15×，API 对非英语多收费）。
