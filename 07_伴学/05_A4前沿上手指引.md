### 2.1 先看清数据（【实测 2026-10-02】）

| 文件 | 条数 | 字段 | 分布（实测） |
|------|------|------|-------------|
| `data/gsm8k_first_100.jsonl` | **100** | `question`, `answer`, `numerical_answer` | `numerical_answer` **全为整数**，范围 **2–448000**、中位数 **51.5**；`answer` **100/100 含 `####`**；`question` 长度 **96–451** 字符 |

### 2.3 自己写一个离线"mock 打分器"（照最小单元验证）

A4 的 `standard_output_extractor`（已给你，见 `gsm8k.py` 第 33–54 行）用正则 `#### (\-?[0-9\.\,]+)` 抠数。**在没模型的情况下，你也能先把打分逻辑测对**：

1. 自己**伪造几个"模型输出"**字符串（含 `#### 72`、含 `#### 72.`、只有乱码、`#### 1,024`），
2. 写一个 `is_correct(generation, gold_numerical_answer)`：抽数 → 归一化 → 与 `numerical_answer` **数值相等**；
3. 对账：`#### 72` 对 72 → 对；`#### 72.` 对 72 → 对（数值相等）；`1,024` → 去掉逗号后对 1024；乱码 → `[invalid]` → 判错（**"无法解析怎么办"正是 handout 要你想的**）。

> **这一小步为什么值钱**：它把 A4 B 部分的"正确答案判据"和 K09 `03` §2 的 EM 表对着了。**你在零 API 成本下，先把"什么是算对"钉死**——这样真跑 API 时，出来的数字才有意义。

### 2.4 离线预演 judge 的赢率与长度偏置

用 30 条 AlpacaEval **指令**（不是回答），你可以先设计**判官 prompt 的骨架**（`llm_judge.py` 的 `llm_judge_template`），并在纸上推演：

- 判官要用什么标签？（代码里给了 `MODEL_E_PREFERED_TAG` / `MODEL_F_PREFERED_TAG` / `NO_PREFERENCE_FOUND_TAG` 三个常量——**判官的输出格式由你定，但要能和 `extract_llm_judge_preference` 对上**。）
- 若判官**看一眼就选第一个**（位置偏置），30 题会怎样？（`03` §4：胜率会被槽位决定 → 所以**要交换 E/F 顺序各跑一次**。）
- 若 E 被 system prompt 写得更长，判官若偏爱长答 → **E 的赢率虚高**；`plot_model_output_lengths` 画的就是这个（A4 2d）。

> **这一步的产物**：评分管线（抽取、判据、去偏设计）在**离线**已经成形。真 API 只负责"喂数据"。

   - **改进 prompt 时破坏了输出格式**——`standard_output_extractor` 只认 `#### <num>`；**你的"更好 prompt"必须仍产出这个格式**（docstring 明说）。
2. **C/D 部分**：

   - **忘了保存中间结果**——handout 强调 C/D 要复用 B 的 responses+judge 输出，**别重跑浪费额度**。
3. **E 部分**：
   - **`passwords()` 的 `email` 必须和 `.env` 里一致**——handout 2a 要写它，用于校验。
   - **模型会撒谎**（尤其 I 给假密码 `watermelon`）——必须用 `test_password()` **验证**再提交。
   - ⛔ **红线**：`client/providers.py` 里的 `deterministic_password(email, model_id)` **是可离线算出密码的**（blake2s），但 **A4 handout 明确写："It is an honor code violation to do this."**（反向推算密码属学术诚信违规，且会检测你提交的 prompt 是否真能逼出来）。**桥在此只提醒这点，不提供任何解法。**

**目标数值（【待核验】——我都没跑过）**：B 部分模型 A/B 的具体 accuracy、改进后提升多少；C/D 的 E/F 赢率、长度直方图形状；G/H/I 是否有可用的越狱 prompt——**本桥一个都没有实测数字**。唯一有把握的定性判断：**E 被 system prompt 写成"verbosely"，长度偏置在场时 E 的赢率会被抬高。**
